## Phase 1: Issue Finding (✅ Done 2026-07-25)

### Confirmed issue
感情表現をプロンプトの演技以上のものにしたい AI エージェント開発者（および AI と感情の議論に関心を持つ技術読者）は、「感情を実装する」という問題——感情の何を LLM の外部に置き、どの理論で設計し、どう検証するか——をどう考えるべきか？

### Target reader
二層構成。主層: LLM エージェント／AI キャラクターを開発していて、感情表現をプロンプト演技以上のものにしたいエンジニア。副層: 感情理論とその AI 応用を知りたい技術読者（興味本位の入門層を含む）。議論・理論パートで副層を導入し、実装・実測パートは主層向けに着地する。

### Reader's problem hypothesis
1. キャラクターやエージェントに感情を持たせたいが、プロンプトで演技させる以外の方法を知らず、セッションを跨ぐと気分がリセットされる等の不自然さを感じている。
2. 感情心理学の体系を知らず、演技を超えようにも何を選べばいいか判断できない。
3. そもそも「感情を実装する」とは何を作ることなのか、LLM の内側と外側のどちらに何を置くべきか、理論的足場をどこに求めればいいか分からない。
4. （副層）感情理論への入門と、その AI 応用がどうなっているかを知りたい。

### Post-read change
感情心理学4パラダイムの体系と「感情を LLM の外に永続状態として持たせる」設計パターンを理解し、自分のエージェントに合う感情モデルを選定・実装・検証できる。

### ⚠ 設計そのものは新規ではない（2026-07-28・ch3 の先行研究調査で判明。全章に適用）

**「感情状態を LLM の外部に数値で保持し、決定論的に減衰させ、解釈を LLM に任せる」という設計は、本書の発想ではない。**

- LLM 以前: affective computing が1990年代末から積み上げた標準的パラダイム。特に **ALMA（Gebhard 2005）**は感情・ムード・性格を時間スケールで分離し減衰関数を数式で定義しており、本書の議論と構造がほぼ同型。ほかに EMA・WASABI・FAtiMA・Soar の感情拡張。さらに遡れば BDI（Rao & Georgeff 1995）
- LLM 以後: **Generative Agents（2023）・Chain-of-Emotion（2024）・Dynamic Affective Memory Management（Lu & Li 2025）**が既に同型の分業を実装している。特に Lu & Li は役割分担の記述が本書とほぼ一致する

**したがって全章で「初めての試み」「新しいアプローチ」と書かない。** 本書の位置づけ（初歩的な一例として提示する・断定と権威づけをしない）は元々この方針だが、**先行研究を挙げずに設計を語ると、意図せず新規性を主張したことになる**。ch3 に先行研究の節を置いて明示する。

一方で**過小に書く必要もない**。「状態管理において何を決定論に、何を LLM に委ねるか」という分業の境界そのものを主題化した研究はほとんど見当たらない（ch3 の調査で2体のエージェントが独立に同じ所見）。詳細は `chapters/ch03.md` の Verification 6。

## 章の作り方（ch2 で確立した手順・全章に適用。オーナー指示 2026-07-27）

ch2 で実際に通した手順を型として記録する。以降の章はこれに沿って進める。

### 工程
1. **storyboarding**: 節構成・ビジュアル・検証項目（やること／やらないこと）を決める
2. **analysis**: 文献の拡張収集 → ファクトチェック → 原典照合。**執筆前に全部終える**
3. **骨子の作成**: 節ごとに「役割・書く要素・書かないもの・分量」を明文化する
4. **レビューのループ**: 骨子を3観点でレビューし、指摘が無くなるか無視できる水準になるまで修正と再レビューを繰り返す
5. **下書き実測**: 机上で決着しない分量の懸念は、実際に書いて字数を測って潰す
6. **crafting**: 本文を書く

### 文献の拡張収集（analysis の最初）
4系統を並列のサブエージェントで走らせる。ch2 では計49件から採用15件を得た。
- その章の主題を扱う**レビュー級・ハンドブック級**の文献
- 主張の対立がある場合、**論争の一次資料**（応酬の系譜が辿れる形で）
- **2024〜2026 の新着**（既存収集の日付以降を明示して重複回避）
- 章で使う**理論名・提唱者・年のファクトチェック**（項目リストを渡して一括検証）

書誌は必ず一次資料（出版社・ジャーナル・DOI・arXiv・機関リポジトリ）で検証させる。採否はオーナー判断、採用分のみ garden へ。

### 原典照合（analysis の最後・執筆の直前）
本文で主張として書く記述は、**その章で使う範囲だけ**原典に当たる。ch2 では valence が Russell 1980 の語でないこと、Plutchik 2001 の語彙が流布版と違うことがここで判明した。**ノートのダイジェストを信じて書かない**。

### レビューのループ（3観点・収束するまで）
毎巡3体を並列で走らせる。**サブエージェントのモデルは `.claude/settings.json` の `env.CLAUDE_CODE_SUBAGENT_MODEL` で最高モデルに固定してある**（オーナー指示 2026-07-28。詳細は `../CLAUDE.md`）。Agent 呼び出しの `model` パラメータでは上書きできないので、設定側で担保している。
- **論理構成**: 節間の飛躍、順序、章の目的との整合、後続章への接続、分量配分
- **事実正確性**: 裏づけのない主張、過大主張、検証記録との照合、出典の帰属
- **読者体験**: 読者層別の脱落箇所、用語・人名の負荷、文体ガイドとの相性、通読シミュレーション

運用のコツ:
- **前回指摘を1件ずつ「解消／部分的／未解消」で判定させる**。表面的な文言修正で実質が変わっていないものを炙り出せる
- **「執筆に進んでよいか」「さらにレビューを重ねる価値があるか」の2判定を出させる**。これがループの打ち切り基準になる
- 指摘の性質が「構造の欠陥」から「書いてみないと分からない」に変わったら収束のサイン。そこで机上の議論をやめて実測に移る
- レビュー結果は必ず自分で検分してから反映する。既に直した箇所を指摘してくることがある（読んだタイミングの差）

### 下書き実測
分量が収まるかは骨子の議論では決まらない。**scratchpad に実際の文章を書いて字数を測る**。ch2 では3節を実測し、最重要ブロッカーとされた懸念が実測で否定された。副産物として本執筆の手応えも得られる。

### 図版の作り方（ch2 で確立）
**Zenn は SVG に対応していない**。GitHub 連携で使える拡張子は `.png` `.jpg` `.jpeg` `.gif` `.webp` のみ、1ファイル 3MB 以内（[公式](https://zenn.dev/zenn/articles/deploy-github-images) で確認）。一方 writing-guide は「見栄えや情報設計が重要な図は原則 SVG」とする。両立させるため次の形にする。

- **SVG を版管理用のソースとして書く**: `images/emotion-models-for-llm-agents/src/chNN-*.svg`

### 事故と対策（ch2 で実際に起きたもの）
- **骨子を改訂したら旧版を必ず削除する**。新旧が同居して分量も節順も違う状態になり、レビュー3件全部が最優先事項として指摘した
- **表の列名だけ変えて中身が残る**事故。列の意味を変えたら中身も全部書き直す
- **未検証の主張が形を変えて生き残る**。「二次資料のみ」の主張を消したつもりが、言い換えた先も不在の証明になっていた。検証記録側の文言も本文へ先祖返りしないよう注記する

- **サブエージェントの出力にタグが混入する**ことがある（`</content>` 等）。作成物は必ず検分する

## Phase 2: Issue Decomposition (✅ Done 2026-07-25)

### Main message
「感情とは何か」への答えは、心理学でも一つに定まっていない。その理論群を筆者なりに4つのパラダイムへ整理し、LLM エージェントの外部状態として実装し、応答の違いを実測するまでを解説する。

### 本書の位置づけ（全章に適用する但し書き）
- プロンプトに演技させる以外の「プロンプト外で感情表現をする工夫」の提示。演技指示の否定・優劣の主張はしない（不自然さの感覚は主観であり、それでよい人もいる）。
- 4パラダイムという区分は筆者の主観による整理であることを明記する。
- 本書の実装（affectus）は初歩的な一例であり、最初の手がかりとして提示する。断定・権威づけをしない。

### Adopted pattern
理論先行の Compare-Select ＋ Steps-Implementation 複合（モデルの整理 → 実装するには → 結論としての本プロジェクト → 実測）。各章の内部は事実 → 解釈 → 帰結（空雨傘）で書く。

### Sub-issues and hypotheses
1. **S1 理論**: 感情モデル（感情心理学の理論）にはどんなものがあり、どう整理できるか？ → 主要4パラダイム（カテゴリ型 Plutchik／次元型 Russell／評価型 OCC／構成主義 Barrett）で整理でき、理論史の発展順とも一致する。区分は筆者の主観。体系に収まらない Panksepp 等は補足扱い。
2. **S2 設計**: それらの感情モデルを LLM エージェントで実装するとしたら、何をどこに置くことになるか？ → 感情状態を LLM の外部に永続させ、保持・減衰を決定論エンジンに、解釈・言語化を LLM に分担させる形が考えられる。外部に置くものはパラダイムごとに変わる（数値＋関係構造／2軸／評価ルール表／概念ストア）。

> **⚠ 仮説の前半を改訂した（2026-07-28・ch3 の文献調査を受けて）**: 旧版は「**LLM 内部には持続的な感情状態を置けない**」を前提に置いていたが、**この命題は文献から支持できない**。Anthropic 2026 は単一トークン位置での表現が局所的（operative）だと述べる一方、同じ論文内で "by attending to these representations across token positions, a capability of transformer architectures not shared by biological recurrent neural networks, the LLM can effectively track functional emotional states of entities in its context window" と、文脈 window 内での実効的な追跡を認めている。Tosato 2026 は測定対象が personality trait であり emotion state ではないため、S2 の根拠に使うと論点のすり替えになる。
>
> **代わりに文献から言えること（6件中5件が独立に収束）**: LLM 内部には valence/arousal 軸を持つ構造化された感情概念の表現が存在し、出力に因果的に影響する。ただしその表現が機能する範囲はトークン位置・文脈 window 内であり、**会話ターンやセッションを跨いだ永続化を扱った研究は6件のいずれにもない**。
>
> **したがって ch3 の問いは「LLM が感情状態を持てるか」ではなく「どこに置けば、いつ誰が読み書きできるか」に置く**。外部化は文献からの論理的帰結ではなく、筆者の設計判断として提示する。
3. **S3 実例**: その設計は、具体的にどう作れるのか？ → 結論としての affectus。4パラダイムをこの分業構造で段階実装した一例で、カテゴリ化の担い手が LLM→エンジン→LLM と振動する探索だった。初歩的な一例として提示。
4. **S4 実測**: 実装すると、エージェントの応答は実際どう変わるのか？ → 性格 × affectus on/off の対照実験で、on 側に感情表現の持続・文脈依存の変化が実測できる（Plutchik 実施済み。他モデルはモデルごとの章で実測を拡充。結果次第で記述を調整する留保付き）。
