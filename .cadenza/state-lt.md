# cadenza state — affectus 10分LT

## Phase 1: Issue Finding (✅ Done 2026-07-02)

### Confirmed issue
プロンプトで感情を演技させることに不自然さを感じている AI エージェント開発者にとって、感情コンポーネントを LLM の外部に切り出すことは、より自然な感情表現をもたらすのか？

### Target reader
AI エージェント開発者（LLM アプリ／エージェントを作っている・作りたいエンジニアのコミュニティ勉強会の聴衆）。10分 LT。

### Reader's problem hypothesis
二段構え。入口の痛み：キャラクターやエージェントに感情を持たせたいが「感情豊かに振る舞え」とプロンプトで演技させる以外の方法を知らず、会話が変われば気分がリセットされる等の不自然さを感じている。その先：感情の心理学モデル（4パラダイム）の地図がなく、演技を超えようにも何を選べばいいか判断できない。

### Post-read change
「感情を LLM の外に永続状態として持たせる」設計パターンを理解し、自分のエージェントで試せる（affectus を使う／真似る）。

### Primary-source basis
- affectus 自作：Plutchik → Russell → OCC → Barrett の4パラダイムを段階的に設計・実装した OSS（github.com/n-yokomachi/affectus）
- eval 対照実験の実測：strands-eval による性格 × affectus on/off の対照実験データ（Plutchik フェーズで実施済み）
- 文献読み込み：感情心理学の主要文献・計算論的実装の先行研究を deep-research 含め自分で調査・検証（garden ノート群、書誌は一次資料で確認済み）

### Differentiator
日本語圏の既存コンテンツはプロンプト・会話履歴設計レベルの感情持続の話が最接近（note 記事等）。「心理学の4パラダイムを1つの OSS で段階実装し、対照実験の実測まで回した」内容は見当たらない。TCE（構成主義的情動理論）のフル実装 OSS は deep-research 調査でも皆無。

### LT 上の位置づけ（構成方針メモ）
LT 全体は confirmed issue 一問の検証報告として構成する。開発経緯（4パラダイム段階実装）と情動理論の体系概要は主題ではなく「検証の道筋で得たもの」として従属配置する。感情の連続性・設計選択（どこに/どの理論で）も主題ではなく、自然な感情表現の構成要素・検証手段として扱う。

## Phase 2: Issue Decomposition (✅ Done 2026-07-02)

### Main message
自然な感情表現は、プロンプトの演技からではなく、LLM の外に置いた「状態の力学」（永続・減衰・理論構造）から生まれる。
（圧縮版スローガンは廃止 — 命令形はトークの正直路線と不整合とのオーナー判断。最終スライドはこの正式版一文のみ）

> [!note] 暫定確定
> オーナー確認済みの留保: **結論は affectus での検証結果により変わりうる**。分析フェーズで実測データを棚卸しした結果、メインメッセージが実測に支持されない場合は、メッセージとストーリーラインを上流に戻って見直す。

### Adopted pattern
Before-After（問題→解決→効果）を骨格に検証報告へ拡張。提示は LT 向けに結論先出し＋並列補強の色を混ぜた空雨傘。

### Sub-issues and hypotheses
1. なぜプロンプト演技では不自然になるのか？ → LLM は内部に持続的な感情状態を持たない（Anthropic の解釈可能性研究とも整合）。演技指示は毎ターンの局所処理にしかならず、気分の持続・減衰・引きずりという感情の力学が構造的に欠ける。
2. 「外部化」とは具体的に何をすることか？ → 感情を数値ベクトルとして LLM の外に永続させ、保持・時間減衰は決定論エンジンが担い、数値の解釈・言語化は LLM に委ねる分業にする（= affectus）。
3. 外部に持たせる感情状態は、どの理論で設計するのか？ → 心理学の主要4パラダイム（カテゴリ型/次元型/評価型/構成主義）を Plutchik→Russell→OCC→Barrett と段階実装した。理論の発展史がそのまま「外部に何を持たせるか」の探索だった。
4. で、実際に自然になったのか？ → 性格 × affectus on/off の対照実験で、on の側に感情表現の持続・文脈依存の変化が実測できた。

### Presentation order (storyline) — Phase 3 で改訂（理論を affectus の前へ）
1. つかみ: マルチセッションで"気分"が工場出荷に戻る不自然さ（軽く）＋「作ってみたかったが先、理由は後付け」の自白
2. 問題の構造: LLM 内部に持続する感情状態は存在しない（サブイシュー1）
3. 情動理論の地図: 「外に置く感情」をどう表すか＝4パラダイムの俯瞰（サブイシュー3前半・理論のみ）
4. affectus: 地図をモデルごとに実装（サブイシュー2＋3後半。共通基盤＋理論/再現の対×4）
5. 実測: on/off 対照実験の結果（サブイシュー4、money chart 1枚）
6. 結論: メインメッセージ（正式版のみ）＋持ち帰り（試し方）

変更理由: §2 の終わりで聴衆に生まれる「外に置く状態って何をどう数値にする？」への回答として理論地図を先に出す方が自然。affectus を先に出すと8軸が天下りに見える。

### Unverified territory
- 対照実験の実測は Plutchik フェーズ分のみ。Russell/OCC/Barrett の eval は未実施または未整理。LT では「実測は Plutchik、以降は実装済み・検証中」と正直に線を引く。
- 実測データ（money chart）の再掘り起こしと LT 向け1枚への再構成。
- メインメッセージ自体が実測の再確認待ち（上記「暫定確定」参照）。

## Phase 3: Storyboarding (✅ Done 2026-07-02)

### Dominant output style
short-form（10分 LT・スライド前提。時間配分: §1:1 + §2:1.5 + §3:1 + §4:3.5 + §5:1.5 + §6:1 ≒ 9.5分、スライド12〜14枚想定）

### Storyboard list

#### §1 つかみ: セッションを跨ぐと"気分"が工場出荷に戻る（1分・1〜2枚）
- **メッセージ**: キャラクターの感情は本来一つの核のはずが、いまの AI はセッションごと・相手ごとに別の感情が生えては消える
- **Form**: Before 対話例（セッション境界を跨ぐ2場面: 昨夜落ち込んで終了 → 翌朝ケロッと定型挨拶）
- **Spec**: 補助3行整理（コンテキストは同一セッション内の感情なら運べる／メモリー機能が運ぶのは事実であって気分ではない／気分を運ぶ仕組みだけが無い）。**トーン指定: Before は軽く1枚。直後に「理由は後付けで、本当は感情コンポーネントを作ってみたかった」と自白して橋渡し**
- **Required verification**: マルチセッション再現例を最小構成で1本実生成（同一エージェント設定でセッション2本）。「メモリー機能は事実を運ぶが気分は運ばない」の実挙動を軽く確認
- **Skipped verification**: off transcript 発掘（単一セッションログなので不適・取り下げ）、同一セッション内リセット例（短期記憶で引き継げるため誤り）、複数モデル網羅

#### §2 問題の構造: LLM 内部に持続する感情状態は存在しない（1.5分・1〜2枚）
- **メッセージ**: だから外に置くしかない
- **Form**: 概念図1枚（セッション毎に感情らしきものが生えては消える vs キャラクターの下に一つだけある核）＋出典1行
- **Spec**: Anthropic 2026（解釈可能性研究）の「LLM 内部の感情表現は operative なものを局所的に追うだけで持続状態を保持しない」を1行引用。§1 の3行整理を図で回収
- **Required verification**: **一次ソース（transformer-circuits.pub / arXiv:2604.07729）に直接当たって引用を確定する（garden ノート照合ではなく）**
- **Skipped verification**: プロービング/ステアリング手法の解説、論文の他の知見（アライメント等）

#### §3 情動理論の地図: 「感情」はどう表せるか（1分・1〜2枚）
- **メッセージ**: 心理学に100年分の蓄積があり4パラダイムに整理できる。外に置く状態の設計図はここから借りる
- **Form**: 地図1枚（4パラダイム: 離散カテゴリ=Plutchik／次元=Russell／認知的評価=OCC／心理構成主義=Barrett。捉え方の一言＋代表理論＋アイコン）
- **Spec**: 「理論史の発展順でもある」を添える。理論の紹介に徹し affectus はまだ出さない。§2 の疑問「何を数値にする？」への回答という位置づけ
- **Required verification**: garden 全体地図ノートからの圧縮転記（理論名・提唱年の正確性のみ確認）
- **Skipped verification**: 各理論の詳細・数式・OCC 22感情列挙・パラダイム間論争の深掘り

#### §4 affectus: 地図をモデルごとに実装する（3.5分・5枚前後）
- **メッセージ**: 4パラダイムそれぞれを「外部の決定論エンジン＋LLM の分業」に翻訳した。パラダイムごとに外に持つものが変わる
- **Form**: 共通アーキ図1枚 → モデル対スライド4枚（左=理論の一言／右=affectus での再現）
- **Spec**:
  - 共通基盤: 2ループ（show→応答→feel／cron tick が半減期減衰）。状態はエージェントに一つ（§2 の核と対応）。framework-agnostic
  - Plutchik 対: 8軸ベクトル実出力、関係構造の読解は LLM。**viz ホイール画面をここに**（状態の実在と減衰の視覚証拠を兼ねる）
  - Russell 対: config の軸差し替えだけで成立（軸は設定、力学は共通）
  - OCC 対: LLM は appraise で評価だけ申告、感情への変換は決定論ルール表。「カテゴリ化を初めてエンジン側に置いた逆転の実験」
  - Barrett 対: core affect＋過去経験の概念ストア（recall→構成→remember、忘却あり）。**実装したて・検証中と正直マーク**
  - 締め: 外部に持つもの（数値→2軸→ルール表→経験ストア）が段階的に変わる＝開発経緯の圧縮
- **Required verification**: show/feel 実出力採取（Plutchik）、appraise / recall・remember の実入出力各1本、viz スクショ（減衰途中の絵）
- **Skipped verification**: MCP・config 詳細・fragment、OCC 22感情全列挙、Barrett 検索スコア式の内訳

#### §5 実測: on/off 対照実験（1.5分・1〜2枚）
- **メッセージ**: 外部化の効果は実測で確認した
- **Form**: money chart 1枚＋測定条件の脚注
- **Spec**: 性格 × affectus on/off（Plutchik フェーズ、strands-eval）。N 反復・使用モデル・Comprehend 極性を脚注明記。「実測は Plutchik、Russell/OCC は実装済みで比較はこれから、Barrett は実装したて」の正直な線引き。解釈は1〜2行の具体で。**内容は実測の再確認結果によって差し替える前提（オーナー確認済み）**
- **Required verification**: 既存 eval 結果の再掘り起こし（results/・transcripts・Zenn 記事の図）。**LT の主張（持続・文脈依存の変化）を実際に支持しているか再確認——支持が弱ければメインメッセージごと上流に戻る**。必要なら LT 向け再プロット
- **Skipped verification**: 新規 eval 実験（全パラダイム対照）、統計的検定の厳密化

#### §6 結論＋持ち帰り（1分・1〜2枚）
- **メッセージ**: メインメッセージ再提示と今夜試せる導線
- **Form**: メッセージ1枚＋試し方1枚
- **Spec**: 最終スライドは正式版一文のみ「自然な感情表現は、プロンプトの演技からではなく、LLM の外に置いた"状態の力学"（永続・減衰・理論構造）から生まれる」（**圧縮版スローガンは廃止——命令形は正直路線と不整合**。§5 の結果次第で文言調整）。持ち帰り: go install →init→snippet 貼付の3ステップ＋リポジトリ URL。締めに「作ってみたかったから作った。理屈は後から付いてきた」で §1 と呼応（口頭可）
