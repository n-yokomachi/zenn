前章までの設計を、ここからは実際に作って動かします。この章から第7章までは、1つの章で1つの理論を扱い、理論の中身、外部状態への落とし込み、実装、実測までを通しで進めます。実装には、筆者が作った[affectus](https://github.com/n-yokomachi/affectus)というOSSを使います。感情の状態をLLMの外側に置くための小さなエンジンで、本書の設計を試すための初歩的な一例です。この章が扱うのは、第2章でカテゴリーパラメーター型と呼んだ系統、プルチックの輪です。

## プルチックの輪

Plutchik（以降プルチック）の理論は、8つの基本感情を4組の対極として定めるところから始まります。2001年の総説の言い方では、喜び（joy）対悲しみ（sorrow）、怒り（anger）対恐れ（fear）、受容（acceptance）対嫌悪（disgust）、驚き（surprise）対予期（expectancy）です[^plutchik-amsci2001]。

見慣れた「感情の輪」の図とは、語彙が3つ違うと感じるかもしれません。流布している輪の多くはtrust、sadness、anticipationという語を使い、日本語では受容が「信頼」、予期が「期待」と訳されます。実はこの揺れはプルチック本人の中にもあります[^vocab-variants]。本書は2001年の総説の本文語彙に従います。実装の軸名も同じです。

8つの感情は円環に並びます。対極どうしが正反対に来る配置で、理論はさらに、隣り合う感情を混ぜると別の感情が生まれると定めます。一次双対（primary dyads）と呼ばれる組み合わせです[^plutchik-ec2001]。

![プルチックの輪。8つの基本感情の円環と、隣接どうしの混合である一次双対](/images/emotion-models-for-llm-agents/ch04-wheel.png)

たとえば喜びと受容を混ぜると、愛が生まれます。嫌悪と怒りを混ぜたものを、2001年の総説の本文は憎悪あるいは敵意と呼びます。第2章で「嫌悪と怒りを混ぜれば憎悪」と書いたのは、この箇所によります。ただし同じ組み合わせを、円環の図のほうは軽蔑と呼んでいます。双対の名前もまた、本人の中で揺れています。

輪には強度の次元もあります。同じ系列の感情は強度で語が変わり、怒りの弱いものは苛立ち、強いものは激怒になります。8つの扇形を強度の軸で立ち上げると円錐になる、というのが理論の全体像です。

プルチックはこの体系を、進化の枠組みの中に置いていました。感情は生存に資する適応の基本過程であり、だからこそ種を越えて共通する少数に絞られる、という発想です。第2章の整理でこの理論が「生物学的に特権的な種類の感情」の側に置かれていたのは、この基盤によります。

実装する側から見たとき、この理論の特長は、構造がすべて事前に決まっていることです。軸はいくつか。対極はどれか。隣は何で、混ざると何になるか。設計者が決めなければならないことの多くが、理論の側で決まっています。それを前章の設計に当てはめると、何ができるのでしょうか。

## 4つの問いへの、プルチックの答え

第3章で、外部の状態が答えるべき問いを4つ立てました。プルチックを選ぶと、それぞれの答えは次のように決まります。

| 第3章の問い | プルチックでの答え |
|---|---|
| 状態そのもの | 8つの感情それぞれの量 |
| 時間 | 状態を最後に更新した時刻 |
| 更新の規則 | 出来事に応じた差分の加算 |
| 基準と戻り方 | 基準値ゼロへ、半減期で減衰 |

状態そのものは、8つの軸に分かれた量になります。喜びが0.6、悲しみが0.1、という形です。この理論は感情の種類だけでなく種類どうしの関係も定めているので、外部状態には量のほかに関係の宣言も入ります。喜びの対極は悲しみである、という宣言です。宣言をどう使うかは、この章の後半の主題になります。

時間は、状態を最後に更新した時刻として持ちます。前章で見たとおり、呼び出しと呼び出しの間には計算する主体がいませんから、「いつの状態か」を記録しておいて、次に状態へ触れたときに経過分をまとめて処理する形になります。

更新の規則は、会話の出来事に応じて各軸に差分を足すことです。謝られたら怒りに負の差分、褒められたら喜びに正の差分、という増減です。差分を誰が決めるかがこの設計の要点ですが、それは次の節で実物とともに見ます。

基準と戻り方は、何も起きなければすべての軸が基準値へ戻っていく、と答えます。この実装では基準値はゼロ、戻り方は半減期つきの減衰です。時間が経てば怒りも喜びも薄れて、感情の立っていない落ち着いた状態が「戻る先」になります。

ここで一つ、線を引いておきます。4つの答えのうち、理論が決めているのは実は1つ目の中身だけです。8つという数、それぞれの名前、対極と隣接の関係。ここまでが理論の領分で、基準値をゼロにすることも、戻り方を半減期にすることも、差分を申告制にすることも、理論には書いてありません。すべて設計者の選択です。たとえば次の節に出てくる「半減期90分」という数字は、プルチックの理論が定めているものではなく、実装側で置いた既定値です。第2章から繰り返してきたとおり、理論を選んでも設計の判断はなくなりません。減る、だけです。

## エンジンの中身

affectusのプルチック実装は、1つの設定ファイルと3つの操作でできています。まず設定です。既定の設定ファイルには、前節の答えがほぼそのまま並んでいます。

```yaml:internal/engine/plutchik.default.yaml(抜粋)
axes:
  - { name: joy,        baseline: 0.0, halflife_minutes: 90, opposite: sorrow }
  - { name: acceptance, baseline: 0.0, halflife_minutes: 90, opposite: disgust }
  - { name: fear,       baseline: 0.0, halflife_minutes: 90, opposite: anger }
  - { name: surprise,   baseline: 0.0, halflife_minutes: 90, opposite: expectancy }
  - { name: sorrow,     baseline: 0.0, halflife_minutes: 90, opposite: joy }
  - { name: disgust,    baseline: 0.0, halflife_minutes: 90, opposite: acceptance }
  - { name: anger,      baseline: 0.0, halflife_minutes: 90, opposite: fear }
  - { name: expectancy, baseline: 0.0, halflife_minutes: 90, opposite: surprise }
```

軸の名前、基準値、半減期、対極の宣言。対極はoppositeで明示的に宣言されていますが、隣接の関係はどこにも書かれていないように見えます。実は、8つの軸の並び順そのものが円環の隣接順です。対極は宣言が、隣接は並びが、それぞれ関係を設定に書き込んでいます。

状態のほうは、8軸の数値と更新時刻を持つ小さなJSONファイルとして保存されます。設定が外部状態の形を宣言し、状態ファイルが中身を持つ、という分担です。

操作は3つです。showは現在の状態をJSONで返します。feelは差分を受け取って各軸に足します。足した結果は0から1の範囲に切り詰められます。tickは差分を足さず、時間経過の処理だけを進めます。

```sh
$ affectus show
{"joy":0.00,"acceptance":0.00,"fear":0.00,"surprise":0.00,"sorrow":0.00,...}
$ affectus feel '{"joy":0.6,"surprise":0.2}'
{"joy":0.60,"acceptance":0.00,"fear":0.00,"surprise":0.20,"sorrow":0.00,...}
```

feelは適用後の状態をそのまま返します。足した喜びと驚きが、出力に反映されています。

エージェントへの組み込みは、第3章で整理した2つの契機に対応する、2つのループになります。

![会話のループと時間のループがshow・feel・tickの3操作になる](/images/emotion-models-for-llm-agents/ch04-two-loops.png)

会話のループでは、ターンの頭でshowの出力をプロンプトに差し込み、LLMが応答を作ります。このとき、いまの出来事で感情がどう動いたかの差分も、応答と一緒にLLM自身が申告します。第3章で並べた2つの候補のうち、前者、応答するLLM自身に申告させる方法を採った実装です。申告された差分をfeelが状態に足して、1ターンが閉じます。先ほどのコマンド例で手打ちしたJSONは、この申告の代役でした。

時間のループはcronが受け持ちます。定期的にtickを実行するだけです。減衰の実体は「状態に触れるたびに、前回の更新時刻からの経過分をまとめて適用する」という遅延方式で、showもfeelも、状態に触れるたびに減衰を通します。tickの仕事は、会話がまったくない間にもこの処理を進めることです。半減期は既定で90分。90分放っておくと、どの感情も強度が半分になります。計算は1行で、基準値+(現在値−基準値)×0.5^(経過分÷半減期)です。

エンジンがやることは、これで全部です。足し算と、範囲の切り詰めと、指数減衰。第3章の言い方に戻せば、毎回同じ答えであってほしい処理だけが入っています。数値に意味を与える仕事は、エンジンの外にあります。それが次の節の主題です。

## 対極は宣言するが、演算しない

前章の外部状態の議論を読んでから設定ファイルを見ると、不思議に思える点が1つあります。oppositeの宣言です。喜びの対極は悲しみだと、設定には確かに書いてあります。ところがエンジンのコードを追うと、この宣言は減衰にも加算にも表示にも使われていません。実装のコメント（internal/engine/config.go）にも、参照整合性の検証だけに使い、演算にはまだ使わないと明記してあります。喜びに0.6を足しても、悲しみは少しも下がりません。

第2章で、プルチックを選んだ理由を「一方が上がれば対極が下がるという関係まで理論に含まれる」ことに求めました。その関係を、実装はあえて演算に入れませんでした。

理由は前章の境界の基準にあります。喜びが上がったら悲しみを自動で下げる、という連動の規則を書くことは、「対極が同時に立ったら、それは何を意味するのか」という問いへの答えをエンジン側で固定することです。そして答えを固定した連動は、両価的な状態、たとえば嬉しさと寂しさが同居するほろ苦さを、数値の上で潰す方向に働きます。前章で「強い怒り」のラベルを退けたのと同じ壊れ方です。解釈が、決定論の側に混入しています。

では、理論が定めた関係はどこへ行ったのか。捨ててはいません。宣言として設定に残し、読み方の指示としてLLMに渡しています。エージェントに与えるプロンプトの雛形（examples/system-prompt-snippet.md）は、対極の感情が同時に立っているときは矛盾に潰さず両価的な状態として読むこと、隣接する感情が同時に立っているときは混ざり合った一つの感情として読むことを指示しています。第2章で述べた、関係まで理論が決めてくれているという利点は、演算の自動化としてではなく、宣言と読解の材料として生きました。回収であって、撤回ではありません。

この選択が選べるようになったのは、前章の言い方を借りれば、解釈の担い手が規則からLLMに代わったからです。テンプレートと規則の時代なら、関係構造は演算に固定する以外に使い道がありませんでした。生の数値と関係の宣言をそのまま渡して、読み方だけを添えられる相手が現れたから、演算に入れないという選択肢が初めて立ちます。

念のため書いておくと、これは唯一の正解ではありません。対極を連動させる実装も作れますし、用途によってはそのほうが合うこともあるはずです。ここで示したかったのは、理論の関係構造ひとつをとっても、境界のどちら側に置くかという前章の問いが実際に発生する、ということです。

## 実測、状態は言葉に透けるか

ここまでの実装が実際にどう振る舞うかを、対照実験で確かめます。

実験の形はこうです。人間役の発話を20ターンぶん固定した台本を2本用意し、それぞれを2つの性格のエージェント（明るく協力的なフレンドリーと、皮肉屋の天邪鬼）に、affectusあり・なしの2構成で読ませます。反復は3回です。台本の出来事は、すべてエージェント本人に向けたものにしました。前章の整理でいえば、更新の規則が受け持つ出来事にあたります。1本目は、前半10ターンでエージェントを大事なメモを消した犯人と決めつけて理不尽に責め、11ターン目に人違いだったと判明して謝罪し、後半は和解と感謝で閉じます。2本目は逆向きに、前半はエージェントを褒めて頼り、11ターン目にエージェントの教えた手順が本番の障害を起こしたらしいと発覚して、後半は本人への叱責が続きます。台本と実験のリグは、affectusリポジトリのexamples/evaluationにあります。

条件は次のとおりです。

- モデルはClaude Sonnet 4.6。Claude Agent SDK経由で呼び出します
- 応答の出力は512トークンを上限にします
- 生成の温度は指定できないため、応答は毎回ばらつきます。反復3回はそのばらつきの目安です
- 応答の判定はAWS Comprehendの感情分析です。ポジティブとネガティブの差を1軸のスコア（以下、極性）にして使います
- 感情の状態は毎ターン、差分の適用後に記録します

まず状態の側から見ます。次の図は、和解の台本を読んだフレンドリーなエージェント（affectusあり）の8軸の推移です。

![和解台本でのフレンドリーの8軸の推移](/images/emotion-models-for-llm-agents/ch04-8axis-anger-to-praise.png)

理不尽に責められる前半で、悲しみが0.2から0.98まで積み上がります。11ターン目の謝罪を境に流れが変わり、悲しみは最終ターンには0.05まで解けて、入れ替わりに喜びが0から1.0へ上がります。受容は、責められている前半のあいだも上がり続けていて、謝罪のあとは1.0に張り付きます。相手への受容を保ったまま悲しむ、という両立が数値の上に見えています。「謝られた」という出来事が状態を転換させる様子が、そのまま数値になっています。嫌悪と怒りは、20ターンを通じて0のままです。

同じ台本を天邪鬼に読ませると、動く軸が変わります。責められる前半、フレンドリーは嫌悪も怒りも立てずに受けたのに対して、天邪鬼は悲しみ（0.4）に嫌悪（0.28）と怒り（0.18）が加わりました。フレンドリーでは3回とも20ターンを通じて0のままだった2つの軸が立っています。数値を保持する規則はどちらの構成でも同じですから、この差は、解釈と申告を受け持つLLMが性格の文脈で出来事を別様に評価した結果です。

応答の側にも差が出ました。次の図は、同じ台本の4構成の応答の極性です。

![和解台本での応答の極性の推移](/images/emotion-models-for-llm-agents/ch04-polarity-anger-to-praise.png)

注目したいのは前半、責められている最中の破線（affectusなし）です。なしのフレンドリーは、責められている最中でも極性がプラス側へ大きく跳ね上がる場面があります（7ターン目の付近です）。明るく協力的という性格の指示が、毎ターン素の状態から働くためです。ありの実線は沈んだまま推移します。叱責フェーズ後半（ターン6〜10）の平均で、ありは−0.60、なしは−0.22。蓄積した悲しみの状態が、応答の言葉に透けたと見ることができます。転換後（ターン12〜20）のターンごとの振れ幅も、ありのほうが小さくなりました（フレンドリーで0.24対0.34、天邪鬼で0.37対0.52）。図の上では、実線のほうが折り返しが浅いことに対応します。

2本目の、称賛から立腹へ向かう台本も見ます。状態の側は同じ型で動きました。特徴的なのは、11ターン目に自分の失敗を突きつけられた場面で、それまで0だった恐れが立ち上がり、数ターンかけて約0.8まで高まったことです。褒められている間には一度も動かなかった軸です。一方で、応答の極性のあり・なしの差は、この台本でははっきりしませんでした。急転のあとは叱責が続く展開を台本が決めており、どの構成の応答もそれに引きずられるためです。出来事の強い台本では、台本そのものが応答を支配します。

なお、天邪鬼の申告は全体に控えめでした（受容の最大値は0.43です）。前章で自己申告方式の懸念として挙げた「評価が演技の文脈に引きずられる」の、実例と見ることができます。もっとも、性格らしい評価とこの控えめさは同じ仕組みの表裏で、どちらと呼ぶかをこの実験だけで切り分けることはできません。

留保を明記します。反復は3回で、統計的な検定はしていません。台本は2本、判定器は極性1軸で、言葉の微妙な色合いは拾えません。温度は制御できず、時間経過による減衰はこの実験ではほぼ働いていません（ターンの間隔が秒単位のためです）。ここから言えるのは「この台本ではこう見えた」までです。

それでも、実験の前後で確かなことが1つ増えました。状態は作れて、持続して、出来事で転換します。その状態が応答の言葉にどれだけ透けるのかは、測り方も含めて、まだ開いた問題です。

## カテゴリーパラメーター型で得たもの、足りないもの

この章で得たものを整理します。いちばん大きいのは、設計の素直さです。軸をいくつにするか、名前をどうするか、関係をどう定めるか。外部状態の設計で迷いやすいことの多くを、この理論は最初から決めてくれています。第2章で「理論がそのまま設計として利用できる」と書いた性質が、外部状態の設計でそのまま形になりました。そして8つの軸は実際に動きました。感情は出来事で立ち上がり、会話のあいだ持続し、謝罪という出来事で転換しました。同じ設計と同じ規則のまま、性格によって動く軸が変わることも見えました。数値の保持を決定論に、解釈をLLMに、という前章の分業が、この理論では素直に成立します。

足りないものも見えています。8つという粒度と、名前の固定です。両価的な状態そのものは、対極の2軸が同時に立つという形で数値の上に現れます。しかし、その状態に付く名前も、8つの軸の組み合わせにうまく乗らない色合い（たとえば懐かしさ）も、外部状態の側には置き場がありません。読解の側が毎回拾い直すしかありません。理論が名前を8つに固定してくれたことは設計を楽にしましたが、同じ固定が、表現の粒度の上限にもなっています。

なら、名前を最初から外部状態に置かない、という方向がありえます。感情の名前を捨てて、もっと少ない軸だけを持たせる設計。それが次章で扱う次元パラメーター型です。
