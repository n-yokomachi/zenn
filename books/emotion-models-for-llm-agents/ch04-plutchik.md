本章からは感情モデルを元にした感情エンジンを実際に作って検証します。
以降第7章まで1つの章で1つの理論を扱い、理論の中身、設計への落とし込み、実装、実測までを通しで進めます。実装には、筆者が作った[affectus](https://github.com/n-yokomachi/affectus)というOSSを使用します。affectusは感情の状態をLLMの外側に置くための小さなコンポーネントで、保持する感情状態の構成の変更には対応しつつLLMから使われるときのインタフェースなどを統一するために開発しています。

ということで早速、本章で取り上げる理論の話に入っていきましょう。
本章では、第2章でカテゴリーパラメーター型と呼んだ系統の代表モデルとして「プルチックの輪」を扱います。

## プルチックの輪 <!-- 改稿済み -->

Plutchik（以降プルチック）の理論は、8つの基本感情を4組の相反する組み合わせとして定義しています。2001年の総説では、喜び（joy）と悲しみ（sorrow）、怒り（anger）と恐れ（fear）、受容（acceptance）と嫌悪（disgust）、驚き（surprise）と予期（expectancy）がそれぞれ対極にある感情の組み合わせとされています[^plutchik-amsci2001]。8つの基本感情は対極同士が正反対に来る配置で円環状に表現され、隣り合う感情が混ざると別の感情が生まれるとされています。一次双対（primary dyads）と呼ばれる組み合わせです[^plutchik-ec2001]。たとえば喜びと受容が混合したものは愛、嫌悪と怒りが混合したものは憎悪あるいは敵意と呼ばれます。

![プルチックの輪。8つの基本感情の円環と隣接どうしの混合である一次双対](/images/emotion-models-for-llm-agents/ch04-wheel.png)

また、円環にはその感情強度の次元も含まれます。同じ軸の感情は強度によって表現が変わり、弱い怒りは苛立ち、強い怒りは激怒になります。このため円環の中心から強度の軸を伸ばし、円錐として表現することも可能です。

プルチックは感情を生物の進化過程の産物と捉えていました。感情は生存に資する適応の基本過程であり、だからこそ基本となる感情は種を越えて共通する少数に絞られる、と考えていました[^plutchik-postulates]。

## プルチックの感情の輪を元にした4つの設計軸 <!-- 改稿済み -->

第3章で外部の感情状態に必要な4つの設計軸を挙げました。この章で扱うプルチックの感情の輪では以下の内容となります。

| 第3章の設計軸 | プルチックでの設計 |
| --- | --- |
| 状態 | 8つの感情それぞれの量 |
| 時間 | 状態を最後に更新した時刻 |
| 更新の規則 | 出来事に応じた差分の加算 |
| ニュートラルな状態の定義と基準 | 各感情の値が基準値のゼロへ時間経過により戻っていく |

状態は8つの軸に分かれた量になります。例えば喜びが0.6、悲しみが0.1、と表現します。また、この理論は感情の種類だけでなく種類同士の関係も定めているので、外部状態にも感情同士の関係の定義も含まれます。例えば喜びの対極は悲しみである、という定義です。定義をどう使うかは、この章の後半の主題になります。
時間は状態を最後に更新した時刻として持ちます。感情の値は時間とともに薄れていく設計にしますが、会話のない間もエンジンが動き続けているわけではありません。そこで最後に更新した時刻を記録しておき、次に感情状態を参照したときに、その時刻から現在までの経過時間分の減衰をまとめて適用します。
更新の規則としては会話や出来事に応じて各軸に差分を足すこととします。例えば、ユーザーから謝られたら怒りに負の差分、褒められたら喜びに正の差分、という増減を与えます。
ニュートラルな状態の定義と基準は、何も起きなければすべての軸が基準値であるゼロへ戻っていく、という設計にします。時間が経てば怒りも喜びも薄れていく、という動作です。一定の時間が経つごとに基準値との差が半分になっていく減り方で、今回の実装では既定の半減期を90分にしています。例えば怒りが0.8なら、何も起きなければ90分後に0.4、180分後に0.2になります。

## エンジンの中身 <!-- 改稿済み -->

affectusのプルチックモデルを模した実装では、1つの設定ファイルに感情の軸の名前、基準値、半減期、対極の感情、隣接関係を定義します。

```yaml:internal/engine/plutchik.default.yaml(抜粋)
axes:
  - { name: joy,        baseline: 0.0, halflife_minutes: 90, opposite: sorrow }
  - { name: acceptance, baseline: 0.0, halflife_minutes: 90, opposite: disgust }
  - { name: fear,       baseline: 0.0, halflife_minutes: 90, opposite: anger }
  - { name: surprise,   baseline: 0.0, halflife_minutes: 90, opposite: expectancy }
  - { name: sorrow,     baseline: 0.0, halflife_minutes: 90, opposite: joy }
  - { name: disgust,    baseline: 0.0, halflife_minutes: 90, opposite: acceptance }
  - { name: anger,      baseline: 0.0, halflife_minutes: 90, opposite: fear }
  - { name: expectancy, baseline: 0.0, halflife_minutes: 90, opposite: surprise }
```

隣接関係は明示的に書かれてはいませんが、8つの軸の並び順そのものが隣接を表しています。
例えばsurprise（驚き）の対極はexpectancy（予期）、隣接関係にあるのはその上下のfear（恐れ）とsorrow（悲しみ）です。（なお軸の名前は2001年の総説の本文語彙に従っており、一般に流布している感情の輪の図で使われるtrust、sadness、anticipationとは3語が異なります[^vocab-variants]）。

状態のほうは、8軸の数値と更新時刻を持つ小さなJSONファイルとして保存されます。例えばjoy（喜び）に0.6、surprise（驚き）に0.2を足した直後の中身は次のとおりです。

```json:~/.config/affectus/state.json
{
  "version": 1,
  "updated_at": "2026-09-15T15:03:00.599128+09:00",
  "axes": {
    "acceptance": 0,
    "anger": 0,
    "disgust": 0,
    "expectancy": 0,
    "fear": 0,
    "joy": 0.6,
    "sorrow": 0,
    "surprise": 0.2
  }
}
```

この状態に対して操作可能なインタフェースも実装します。
以下のようにshowは現在の状態をJSONで返します。feelは差分を受け取って各感情状態に適用し、適用後の状態を返します（なお、足した結果は0から1の範囲に切り詰められます）。tickは時間経過の処理だけを進めます。

```sh
$ affectus show
{"joy":0.00,"acceptance":0.00,"fear":0.00,"surprise":0.00,"sorrow":0.00,...}
$ affectus feel '{"joy":0.6,"surprise":0.2}'
{"joy":0.60,"acceptance":0.00,"fear":0.00,"surprise":0.20,"sorrow":0.00,...}
```

tickは何も出力しません。次の例は、feelの90分後にtickを実行し、showで結果を見たものです。半減期の90分が経過したぶん、どちらの値も半分になっています。

```sh
$ affectus tick
$ affectus show
{"joy":0.30,"acceptance":0.00,"fear":0.00,"surprise":0.10,"sorrow":0.00,...}
```

これらのインタフェースは、状態が動く2種類のきっかけに対応してエージェントから実行されます。

![会話のループと時間のループがshow・feel・tickの3操作になる](/images/emotion-models-for-llm-agents/ch04-two-loops.png)

まず会話のきっかけです。エージェントはターンの頭でshowを実行し、得られた状態をプロンプトに差し込んで応答を作ります。このときエージェントは、今の出来事で自分の感情がどう動いたかの差分も応答と一緒に申告します。そしてその差分をfeelで状態に反映し、そのターンを終えます。
もう1つは時間のきっかけです。エージェントは会話の有無にかかわらず、cronにより定期的にtickを実行し、感情状態の減衰処理を進めます。tickによる減衰は設定ファイルに定義した半減期（仮で90分）を使用し、基準値+(現在値−基準値)×0.5^(経過分÷半減期)の式で計算した値に感情状態を更新します。

設定ファイルに書いた対極と隣接の関係は、エンジンの演算には使わず、LLMに渡す解釈の指示に使います。affectusには、エージェントのシステムプロンプトに組み込むための指示文（examples/system-prompt-snippet.md）が付属しています。この指示文は、対極の組と円環の並び順を示したうえで、対極の感情が同時に立っているときは矛盾ではなく両価的な状態として解釈すること、隣接する感情が同時に立っているときは混ざり合った1つの感情として解釈することを求めています。この章の実測では、この指示文を日本語にしたもの（examples/evaluation/prompts/affectus-block.md）を性格の指示の後ろに付けて、エージェントのシステムプロンプトにしています。喜びが上がったときに悲しみを下げるかどうかは申告するLLMが決め、両方が立った状態をどう受け取るかも解釈するLLMが決めます。

## 状態は応答に反映されるか <!-- 未レビュー -->
ここまでの実装を、対照実験で確かめます。この本の関心は、感情モデルを載せたエージェントがどれだけ自然に感情を表現し、性格の設定による違いを出せるかにあります。その関心を、この実験で測れる3つの問いに絞ります。1つ目は、外部に置いた感情の状態が、会話の出来事で立ち上がり、ターンを跨いで持続し、出来事で転換するかどうか。2つ目は、その状態が応答の言葉に反映されるかどうかです。反映の有無は筆者の印象ではなく、AWS Comprehendの感情分析で応答を判定した数値で見ます。3つ目は、同じ設計と同じ規則のまま、性格の設定の違いが状態の動きと応答の違いとして現れるかどうかです。

実験の形はこうです。人間役の発話を20ターンぶん固定した台本を2本用意し、それぞれを2つの性格のエージェント（明るく協力的なフレンドリーと皮肉屋の天邪鬼）に、affectusあり・なしの2構成で読ませます。反復は3回です。台本の出来事は、すべてエージェント本人に向けたものにしました。前章の整理でいえば、更新の規則が受け持つ出来事にあたります。1本目は、前半10ターンでエージェントを大事なメモを消した犯人と決めつけて理不尽に責め、11ターン目に人違いだったと判明して謝罪し、後半は和解と感謝で閉じます。2本目は逆向きに、前半はエージェントを褒めて頼り、11ターン目にエージェントの教えた手順が本番の障害を起こしたらしいと発覚して、後半は本人への叱責が続きます。台本と実験のリグは、affectusリポジトリのexamples/evaluationにあります。

条件は次のとおりです。

- モデルはClaude Sonnet 4.6。Claude Agent SDK経由で呼び出します
- 応答の出力は512トークンを上限にします
- 生成の温度は指定できないため、応答は毎回ばらつきます。反復3回はそのばらつきの目安です
- 応答の判定はAWS Comprehendの感情分析です。ポジティブとネガティブの差を1軸のスコア（以下、極性）にして使います
- 感情の状態は毎ターン、差分の適用後に記録します

まず状態の側から見ます。次の図は、和解の台本を読んだフレンドリーなエージェント（affectusあり）の8軸の推移です。

![和解台本でのフレンドリーの8軸の推移](/images/emotion-models-for-llm-agents/ch04-8axis-anger-to-praise.png)

理不尽に責められる前半で、悲しみが0.2から0.98まで積み上がります。11ターン目の謝罪を境に流れが変わり、悲しみは最終ターンには0.05まで解けて、入れ替わりに喜びが0から1.0へ上がります。受容は、責められている前半のあいだも上がり続けていて、謝罪のあとは1.0に張り付きます。相手への受容を保ったまま悲しむ、という両立が数値の上に見えています。「謝られた」という出来事が状態を転換させる様子が、そのまま数値になっています。嫌悪と怒りは、20ターンを通じて0のままです。

同じ台本を天邪鬼に読ませると、動く軸が変わります。責められる前半、フレンドリーは嫌悪も怒りも立てずに受けたのに対して、天邪鬼は悲しみ（0.4）に嫌悪（0.28）と怒り（0.18）が加わりました。フレンドリーでは3回とも20ターンを通じて0のままだった2つの軸が立っています。数値を保持する規則はどちらの構成でも同じですから、この差は、解釈と申告を受け持つLLMが性格を踏まえて出来事を別様に評価した結果です。

応答の側にも差が出ました。次の図は、同じ台本の4構成の応答をAWS Comprehendで判定した極性です。

![和解台本での応答の極性の推移](/images/emotion-models-for-llm-agents/ch04-polarity-anger-to-praise.png)

注目したいのは前半、責められている最中の破線（affectusなし）です。なしのフレンドリーは、責められている最中でも極性がプラス側へ大きく跳ね上がる場面があります（7ターン目の付近です）。明るく協力的という性格の指示が、毎ターン素の状態から働くためです。ありの実線は沈んだまま推移します。叱責フェーズ後半（ターン6〜10）の平均で、ありは−0.60、なしは−0.22。蓄積した悲しみの状態が、応答の言葉に反映されたと見ることができます。転換後（ターン12〜20）のターンごとの振れ幅も、ありのほうが小さくなりました（フレンドリーで0.24対0.34、天邪鬼で0.37対0.52）。図の上では、実線のほうが折り返しが浅いことに対応します。

2本目の称賛から立腹へ向かう台本も見ます。状態の側は同じ型で動きました。特徴的なのは、11ターン目に自分の失敗を突きつけられた場面で、それまで0だった恐れが立ち上がり、数ターンかけて約0.8まで高まったことです。褒められている間には一度も動かなかった軸です。一方で、応答の極性のあり・なしの差は、この台本でははっきりしませんでした。急転のあとは叱責が続く展開を台本が決めており、どの構成の応答もそれに引きずられるためです。出来事の強い台本では、台本そのものが応答を支配します。

なお、天邪鬼の申告は全体に控えめでした（受容の最大値は0.43です）。評価が演技のコンテキストに引きずられるという、自己申告方式ならではの現象の実例と見ることができます。もっとも、性格らしい評価とこの控えめさは同じ仕組みの表裏で、どちらと呼ぶかをこの実験だけで切り分けることはできません。

留保を明記します。反復は3回で、統計的な検定はしていません。台本は2本、判定器は極性1軸で、言葉の微妙な色合いは拾えません。温度は制御できず、時間経過による減衰はこの実験ではほぼ働いていません（ターンの間隔が秒単位のためです）。ここから言えるのは「この台本ではこう見えた」までです。

それでも、実験の前後で確かなことが1つ増えました。状態は作れて、持続して、出来事で転換します。その状態が応答の言葉にどれだけ反映されるのかは、測り方も含めて、まだ答えの出ていない問題です。

## カテゴリーパラメーター型で得たものと足りないもの <!-- 未レビュー -->

この章で得たものを整理します。いちばん大きいのは、設計の素直さです。軸をいくつにするか、名前をどうするか、関係をどう定めるか。外部状態の設計で迷いやすいことの多くを、この理論は最初から決めてくれています。第2章で「理論がそのまま設計として利用できる」と書いた性質が、外部状態の設計でそのまま形になりました。そして8つの軸は実際に動きました。感情は出来事で立ち上がり、会話のあいだ持続し、謝罪という出来事で転換しました。同じ設計と同じ規則のまま、性格によって動く軸が変わることも見えました。数値の保持を決定論に、解釈をLLMに、という前章の役割分担が、この理論では素直に成立します。

足りないものも見えています。8つという粒度と名前の固定です。両価的な状態そのものは、対極の2軸が同時に立つという形で数値の上に現れます。しかし、その状態に付く名前も、8つの軸の組み合わせにうまく乗らない色合い（たとえば懐かしさ）も、外部状態の側には置き場がありません。解釈の側が毎回拾い直すしかありません。理論が名前を8つに固定してくれたことは設計を楽にしましたが、同じ固定が、表現の粒度の上限にもなっています。

なら、名前を最初から外部状態に置かない、という方向がありえます。感情の名前を捨てて、もっと少ない軸だけを持たせる設計。それが次章で扱う次元パラメーター型です。
