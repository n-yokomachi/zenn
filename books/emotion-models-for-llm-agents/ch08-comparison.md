本章ではここまでに実装した4つの感情モデルを並べて比較します。最後に本書全体をまとめます。

## 設計の比較 <!-- 未レビュー -->

4つのモデルは同じ感情エンジンの上に実装しました。どのモデルも状態の更新時刻を持ち、感情の値が時間とともに基準値へ減衰する点は同じです。外部状態に持つものと感情エンジンが担当する範囲はモデルごとに違います。

| | プルチックの感情の輪 | ラッセルの円環モデル | OCCモデル | バレットの構成主義的情動理論 |
| --- | --- | --- | --- | --- |
| 外部状態 | 8つの感情の量 | 2軸の値 | 22の感情の量と見込みリスト | 2軸の値と経験の概念ストア |
| 感情の名前の数 | 8 | 0 | 22 | 決まっていない |
| 感情の名前を決めるもの | 理論（8つに固定） | 読む側のLLMの解釈 | 評価から導く規則 | LLMがその場で構成 |
| LLMが申告するもの | 感情の差分 | 2軸の差分 | 出来事の評価 | 2軸の差分と感情の名前と14属性 |

感情エンジンとLLMの役割分担はモデルごとに変わりました。プルチックの感情の輪では理論が定める対極と隣接の関係をLLMへの指示として渡しました。ラッセルの円環モデルでは感情の名前を付ける作業をすべてLLMに任せました。OCCモデルでは評価から感情を導く部分を感情エンジンの規則に移しました。バレットの構成主義的情動理論で感情エンジンが担当するのは状態の保持と減衰と似た経験の検索だけです。

外部状態に残る記録もモデルを追って増えました。プルチックとラッセルは感情の量だけです。OCCモデルでは見込みリストに希望や恐れが生じた理由が記録され、バレットでは過去に付けた感情の名前が蓄積されます。記録が増えるほどセッションをまたいで引き継げる情報も増えます。プロンプトの長さへの影響はモデルで異なります。OCCモデルの見込みリストは毎ターン全件をLLMに渡しますが上限は20件です。バレットの概念ストアは想起した5件だけを渡すので、ストアが増えてもプロンプトは長くなりません。

## 検証結果の比較 <!-- 未レビュー -->

4つのモデルの検証は同じ台本と同じ性格と同じ判定方法で行いました。ただしバレットでは感情エンジンのありとなしではなく想起のありとなしを比較しています。

### 感情状態の変化・持続・転換

感情状態の変化と持続は4つのモデルすべてで確認できました。転換の仕方はモデルで分かれました。プルチックとラッセルでは謝罪や失敗の発覚をきっかけに状態が切り替わりました。OCCモデルでは新しい感情が加わるだけで、一度上がった感情は下がりませんでした。バレットでは状態の転換ではなく感情の名前の連続性を見ています。

| モデル | 外部状態に記録された違い |
| --- | --- |
| プルチックの感情の輪 | 相手を受け入れたまま悲しむ状態が受容と悲しみの2つの軸に分かれて記録された |
| ラッセルの円環モデル | 責められた直後の動揺と責められ続けたあとの消沈が覚醒の高さの違いとして記録された |
| OCCモデル | 誰の行為が原因かによって非難と恥が分かれ、恐れの理由が見込みリストに記録された。一度上がった感情は下がらずに残った |
| バレットの構成主義的情動理論 | 想起があると過去に付けた感情の名前が次のターンでも使われることがあった（天邪鬼の1回の実行） |

### 応答への反映

感情エンジンが応答の感情スコアをどちらに動かすかはモデルによって逆になりました。差の大きさも同じ条件を取り直したときのばらつきと同じ程度です。

| 叱責中の平均 | 感情エンジンあり | 感情エンジンなし |
| --- | --- | --- |
| プルチックの感情の輪 | −0.60 | −0.22 |
| ラッセルの円環モデル | −0.43 | −0.41 |
| OCCモデル | −0.42 | −0.46 |
| バレットの構成主義的情動理論 | −0.18 | −0.51 |

| 謝罪後の変動幅 | 感情エンジンあり | 感情エンジンなし |
| --- | --- | --- |
| プルチックの感情の輪 | 0.24 | 0.34 |
| ラッセルの円環モデル | 0.52 | 0.44 |
| OCCモデル | 0.40 | 0.44 |
| バレットの構成主義的情動理論 | 0.18 | 0.30 |

2つの表は4つのモデルの検証で共通して報告している、和解の台本のフレンドリーの感情スコアです。叱責中はターン6〜10の平均で、謝罪後の変動幅はターン12〜20の隣り合うターンの差の絶対値の平均です。バレットの行だけは感情エンジンありの代わりに想起あり、感情エンジンなしの代わりに想起なしの値です。

叱責中の平均はプルチックでは感情エンジンありのほうが低く、バレットでは想起ありのほうが高くなりました。ラッセルとOCCモデルではほぼ同じです。一方で感情エンジンなしの構成はプルチックとラッセルとOCCモデルの検証で同じ設定ですが、叱責中の平均は−0.22から−0.46まで0.24の幅で変わりました。感情エンジンありとなしの差は0.02から0.38なので、取り直しのばらつきと同じ程度です。そのため叱責中の平均の上下はモデルの違いとは言えません。

謝罪後の変動幅は和解の台本のフレンドリーではプルチックとOCCモデルとバレットで感情エンジンありまたは想起ありのほうが小さく、ラッセルでは大きくなりました。ただしOCCモデルの差は0.04で、OCCモデルの検証でもはっきりした差とはしていません。ほかの台本と性格の組み合わせ12組でも感情エンジンありのほうが小さいのは7組で、向きはそろいませんでした。最も大きく逆になったのはOCCモデルの和解の台本の天邪鬼で、感情エンジンありが0.54でなしが0.38でした。

### 性格による違い

性格による違いは4つのモデルすべてで現れ、現れ方はモデルによって変わりました。

| モデル | 性格による違いが現れたところ |
| --- | --- |
| プルチックの感情の輪 | 動く軸。和解の台本で天邪鬼だけが嫌悪と怒りを上げた |
| ラッセルの円環モデル | 変化の幅と応答への反映。天邪鬼は変化が小さく、称賛から立腹へ向かう台本では状態と応答が連動しなかった |
| OCCモデル | 評価の向き。天邪鬼は3回のうち2回で苦悩を上げず相手への非難だけを上げた |
| バレットの構成主義的情動理論 | 名前の付け方。称賛から立腹へ向かう台本で天邪鬼は3回のうち1回で過去の名前を使い、フレンドリーは毎回言い換えた |

どのモデルでも状態を保持する規則は2つの性格で同じです。違いは申告するLLMが性格をふまえて出来事を評価したことで生じています。

## モデルの選び方 <!-- 未レビュー -->

本書では最初に試すモデルとしてプルチックの感情の輪を勧めます。理論が軸と関係を決めているので設計の判断が少なく、検証でも状態の変化と性格による違いがはっきり出たからです。そのうえで目的に応じて次のモデルを検討してください。

- 外部状態を最小にしたい場合はラッセルの円環モデルです。2つの数値で変化と持続を表せます。感情の名前はLLMが解釈します
- 感情が生じた理由を残したい場合はOCCモデルです。本書の実装には感情を下げる規則がありません。長い会話では半減期を短くするか値を下げる規則を加える必要があります
- セッションをまたいで経験を蓄積したい場合はバレットの構成主義的情動理論です。ただしセッションをまたいだ保持は本書では検証していません。名前の付け方の一貫性を確認できたのは天邪鬼の1回の実行だけです。構成の質はLLMに大きく依存します

## 本書のまとめ <!-- 未レビュー -->

本書ではLLMエージェントに感情を持たせる方法を感情心理学の理論から実装と検証まで通して扱いました。結論は3つです。

1つ目は、感情の状態をLLMの外側に置けば感情の変化と持続を記録として残せることです。4つのモデルのどれでも感情状態は会話の出来事で変化してターンをまたいで持続し、性格による違いも状態に現れました。

2つ目は、何が記録に残るかは感情モデルの選択で決まることです。量だけを残すプルチックとラッセル、理由まで残すOCC、名前の履歴まで残すバレットのどれを選ぶかで、感情エンジンとLLMの役割分担も決まります。

3つ目は、どのモデルを選んでも会話そのものの感情表現には大きな違いが出なかったことです。応答の感情スコアの差は同じ条件を取り直したときのばらつきと区別できず、差の向きもモデルや台本によって逆になりました。人間どうしの会話では身振りや声の調子や表情も感情を伝えます。チャットインタフェースしか持たないAIエージェントが感情を表せるのは言葉だけで、外部状態の違いを会話に出せる幅は想像以上に狭いものでした。

そのため本書の感情エンジンの価値は、応答の言葉を変えることではなく状態を残せることにあります。状態が残っていれば、セッションをまたいで感情を引き継ぐことも、時間とともに落ち着かせることも、あとから状態を読んで振る舞いの理由を確かめることもできます。ただしセッションをまたいだ持続と時間による減衰は本書では検証していません。

本書の設計は次のとおりです。感情心理学の理論をカテゴリーパラメーター型と次元パラメーター型と評価導出型と経験構成型の4つの系統に整理し、それぞれの代表モデルを同じ感情エンジンの上に実装しました。感情の状態はLLMの外側に置き、状態、時間、更新の規則、ニュートラルな状態の定義と基準の4つの軸で設計します。状態の保持と減衰と演算は感情エンジンが担当し、状態の解釈と命名と言語化はLLMが担当します。感情の数値状態の上に解釈と言語化の層がある構図は20年前の研究と同じで、変わったのはその層をLLMが担うようになったことです。

## 残された課題 <!-- 未レビュー -->

本書の検証には次の限界があります。

- 反復は3回で統計的な検定はしていません
- 台本は2本でモデルはClaude Sonnet 4.6だけです
- 応答の判定はポジティブとネガティブの1軸の感情スコアなので言葉の細かいニュアンスは測れていません
- ターンの間隔が秒単位なので時間による減衰とセッションをまたいだ持続は検証していません
- LLMが申告した差分や評価の値が妥当だったかは確認していません

設計上の課題も残っています。1つは申告の偏りです。本書では応答を生成するLLM自身が感情の変化を申告します。天邪鬼の申告が全体に小さめだったのが性格に沿った評価なのか演技による偏りなのかは分けられませんでした。応答とは別の判定用のモデルに評価させる方法も考えられます。もう1つは身体です。会話の感情表現の幅が狭いのは、感情を出せる先が言葉しかないからです。2Dや3Dのモデルを持つエージェントなら表情や身振りにも状態を出せます。「感情モデルの整理」の章で触れた、身体の状態を感情に結び付ける理論も試せるかもしれません。

## 試し方 <!-- 未レビュー -->

本書で使った感情エンジンは[affectus](https://github.com/n-yokomachi/affectus)として公開しています。macOSかLinuxで動きます。Goの環境があれば次のコマンドでインストールできます。

```sh
go install github.com/n-yokomachi/affectus/cmd/affectus@latest
```

:::message
Goがない場合はリポジトリのReleasesページからビルド済みのバイナリを取得できます。
:::

モデルはinitコマンドで初期化するときに選びます。何も指定しなければプルチックの感情の輪になります。

```sh
affectus init                  # プルチックの感情の輪
affectus init --model russell  # ラッセルの円環モデル
affectus init --model occ      # OCCモデル
affectus init --model barrett  # バレットの構成主義的情動理論
```

エージェントに組み込むときはリポジトリのexamplesにあるモデルごとの指示文をシステムプロンプトに入れます。時間による減衰のためにtickコマンドを定期実行します。MCPに対応したエージェントでは`affectus mcp`をMCPサーバーとして登録すると、プルチックとラッセルとOCCの3つのモデルを使えます。バレットの想起と保存はMCPに対応していないのでコマンドで使います。tickコマンドはMCPに含まれないので、MCPを使う場合も定期実行が必要です。
