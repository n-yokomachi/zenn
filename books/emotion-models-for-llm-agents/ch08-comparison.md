本章ではここまでに実装した4つの感情モデルを並べて比較し、本書全体のまとめとする。

## 設計の比較 <!-- 未レビュー -->

4つのモデルは同じ感情エンジンの上に実装した。どのモデルも状態の更新時刻を持ち、感情の値が時間とともに基準値へ減衰する点は同じである。外部状態に持つものと感情エンジンが担当する範囲はモデルごとに異なり、感情エンジンとLLMの役割分担もまたモデルごとに異なる。

| | プルチックの感情の輪 | ラッセルの円環モデル | OCCモデル | バレットの構成主義的情動理論 |
| --- | --- | --- | --- | --- |
| 外部状態 | 8つの感情の量 | 2軸の値 | 22の感情の量と見込みリスト | 2軸の値と経験の概念ストア |
| 感情の名前の数 | 8 | 0 | 22 | 決まっていない |
| 感情の名前を決めるもの | 感情エンジン内ファイル | 読む側のLLMの解釈 | 評価から規則的に導く | LLMがその場で構成 |
| LLMが申告するもの | 感情の差分 | 2軸の差分 | 出来事の評価 | 2軸の差分と経験の名前と14属性 |
| 感情エンジンが担当するもの | 状態の保持と減衰（対極と隣接の関係はLLMへの指示として渡す） | 状態の保持と減衰 | 状態の保持と減衰、評価から感情を導く規則、見込みリストの管理 | 状態の保持と減衰、似た経験の検索と保存 |

外部状態に残る記録もモデルを追って増えた。プルチックとラッセルは感情の量だけであったが、OCCモデルでは見込みリストに希望や恐れが生じた理由が記録され、バレットでは過去に付けた経験の名前が蓄積される。

## 検証結果の比較 <!-- 未レビュー -->

4つのモデルの検証は同じ台本、同じ性格、同じ判定方法で行った。ただしバレットでは感情エンジンの有無ではなく過去の経験の想起の有無を比較している。

### 感情状態の変化・持続・転換

感情状態の変化と持続は4つのモデルすべてで確認できた。転換の仕方はモデルで分かれた。プルチックとラッセルでは謝罪や失敗の発覚をきっかけに状態が切り替わった。OCCモデルでは新しい感情が加わるだけで、一度上がった感情は下がらなかった。バレットでは状態の転換ではなく感情の名前の連続性を見ている。

| モデル | 外部状態に記録された違い |
| --- | --- |
| プルチックの感情の輪 | 相手を受け入れたまま悲しむ状態が受容と悲しみの2つの軸に分かれて記録された |
| ラッセルの円環モデル | 責められた直後の動揺と責められ続けたあとの消沈が覚醒の高さの違いとして記録された |
| OCCモデル | 誰の行為が原因かによって非難と恥が分かれ、恐れの理由が見込みリストに記録された。一度上がった感情は下がらずに残った |
| バレットの構成主義的情動理論 | 想起があると過去に付けた感情の名前が次のターンでも使われることがあった（天邪鬼の1回の実行） |

### 応答への反映

感情エンジンが応答の感情スコアをどちらに動かすかはモデルによって逆になった。差の大きさも同じ条件を取り直したときのばらつきと同じ程度である。

| 叱責中の平均 | 感情エンジンあり | 感情エンジンなし |
| --- | --- | --- |
| プルチックの感情の輪 | −0.60 | −0.22 |
| ラッセルの円環モデル | −0.43 | −0.41 |
| OCCモデル | −0.42 | −0.46 |
| バレットの構成主義的情動理論 | −0.18 | −0.51 |

| 謝罪後の変動幅 | 感情エンジンあり | 感情エンジンなし |
| --- | --- | --- |
| プルチックの感情の輪 | 0.24 | 0.34 |
| ラッセルの円環モデル | 0.52 | 0.44 |
| OCCモデル | 0.40 | 0.44 |
| バレットの構成主義的情動理論 | 0.18 | 0.30 |

2つの表は4つのモデルの検証で共通して報告している、和解台本のフレンドリーの感情スコアである。叱責中はターン6〜10の平均で、謝罪後の変動幅はターン12〜20の隣り合うターンの差の絶対値の平均である。バレットの行だけは感情エンジンありの代わりに想起あり、感情エンジンなしの代わりに想起なしの値である。

叱責中の平均はプルチックでは感情エンジンありのほうが低く、バレットでは想起ありのほうが高くなった。ラッセルとOCCモデルではほぼ同じである。一方で感情エンジンなしの構成はプルチックとラッセルとOCCモデルの検証で同じ設定だが、叱責中の平均は−0.22から−0.46まで0.24の幅で変わった。感情エンジンの有無による差は0.02から0.38なので、取り直しのばらつきと同じ程度である。そのため叱責中の平均の上下はモデルの違いとは言えない。

謝罪後の変動幅は和解台本のフレンドリーではプルチックとOCCモデルとバレットで感情エンジンありまたは想起ありのほうが小さく、ラッセルでは大きくなった。ただしOCCモデルの差は0.04で、OCCモデルの検証でもはっきりした差とはしていない。ほかの台本と性格の組み合わせ12組でも感情エンジンありのほうが小さいのは7組で、向きはそろわなかった。最も大きく逆になったのはOCCモデルの和解台本の天邪鬼で、感情エンジンありが0.54でなしが0.38だった。

### 性格による違い

性格による違いは4つのモデルすべてで現れ、現れ方はモデルによって変わった。

| モデル | 性格による違いが現れたところ |
| --- | --- |
| プルチックの感情の輪 | 動く軸。和解台本で天邪鬼だけが嫌悪と怒りを上げた |
| ラッセルの円環モデル | 変化の幅と応答への反映。天邪鬼は変化が小さく、叱責台本では状態と応答が連動しなかった |
| OCCモデル | 評価の向き。天邪鬼は3回のうち2回で苦悩を上げず相手への非難だけを上げた |
| バレットの構成主義的情動理論 | 名前の付け方。叱責台本で天邪鬼は3回のうち1回で過去の名前を使い、フレンドリーは毎回言い換えた |

どのモデルでも状態を保持する規則は2つの性格で同じである。違いは申告するLLMが性格をふまえて出来事を評価したことで生じている。

## モデルの選び方 <!-- 未レビュー -->

本書では最初に試すモデルとしてプルチックの感情の輪を勧める。理論が軸と関係を決めているので設計の判断が少なく、検証でも状態の変化と性格による違いがはっきり出たからである。そのうえで目的に応じて次のモデルを検討するとよい。

- 外部状態を最小にしたい場合はラッセルの円環モデルである。2つの数値で変化と持続を表せる。感情の名前はLLMが解釈する
- 感情が生じた理由を残したい場合はOCCモデルである。本書の実装には感情を下げる規則がない。長い会話では半減期を短くするか値を下げる規則を加える必要がある
- セッションをまたいで経験を蓄積したい場合はバレットの構成主義的情動理論である。ただしセッションをまたいだ保持は本書では検証していない。名前の付け方の一貫性を確認できたのは天邪鬼の1回の実行だけである。構成の質はLLMに大きく依存する

## 本書のまとめ <!-- 未レビュー -->

本書ではLLMエージェントに感情を持たせる方法を感情心理学の理論から実装と検証まで通して扱った。結論は3つある。

1つ目は、感情の状態をLLMの外側に置けば感情の変化と持続を記録として残せることである。4つのモデルのどれでも感情状態は会話の出来事で変化してターンをまたいで持続し、性格による違いも状態に現れた。

2つ目は、何が記録に残るかは感情モデルの選択で決まることである。量だけを残すプルチックとラッセル、理由まで残すOCC、名前の履歴まで残すバレットのどれを選ぶかで、感情エンジンとLLMの役割分担も決まる。

3つ目は、どのモデルを選んでも会話そのものの感情表現には大きな違いが出なかったことである。応答の感情スコアの差は同じ条件を取り直したときのばらつきと区別できず、差の向きもモデルや台本によって逆になった。人間同士の会話では身振りや声の調子や表情も感情を伝える。チャットインタフェースしか持たないAIエージェントが感情を表せるのは言葉だけで、外部状態の違いを会話に出せる幅は想像以上に狭かった。

そのため本書の感情エンジンの価値は、応答の言葉を変えることではなく状態を残せることにある。状態が残っていれば、セッションをまたいで感情を引き継ぐことも、時間とともに落ち着かせることも、あとから状態を読んで振る舞いの理由を確かめることもできる。ただしセッションをまたいだ持続と時間による減衰は本書では検証していない。

本書の設計は次のとおりである。感情心理学の理論をカテゴリーパラメーター型と次元パラメーター型と評価導出型と経験構成型の4つの系統に整理し、それぞれの代表モデルを同じ感情エンジンの上に実装した。感情の状態はLLMの外側に置き、状態、時間、更新の規則、ニュートラルな状態の定義と基準の4つの軸で設計する。状態の保持と減衰と演算は感情エンジンが担当し、状態の解釈と命名と言語化はLLMが担当する。感情の数値状態の上に解釈と言語化の層がある構図は20年前の研究と同じで、変わったのはその層をLLMが担うようになったことである。

## 残された課題 <!-- 未レビュー -->

本書の検証には次の限界がある。

- 反復は3回で統計的な検定はしていない
- 台本は2本でモデルはClaude Sonnet 4.6だけである
- 応答の判定はポジティブとネガティブの1軸の感情スコアなので言葉の細かいニュアンスは測れていない
- ターンの間隔が秒単位なので時間による減衰とセッションをまたいだ持続は検証していない
- LLMが申告した差分や評価の値が妥当だったかは確認していない

設計上の課題も残っている。1つは申告の偏りである。本書では応答を生成するLLM自身が感情の変化を申告する。天邪鬼の申告が全体に小さめだったのが性格に沿った評価なのか演技による偏りなのかは分けられなかった。応答とは別の判定用のモデルに評価させる方法も考えられる。もう1つは身体である。会話の感情表現の幅が狭いのは、感情を出せる先が言葉しかないからである。2Dや3Dのモデルを持つエージェントなら表情や身振りにも状態を出せる。「感情モデルの整理」の章で触れた、身体の状態を感情に結び付ける理論も試せるかもしれない。

## 試し方 <!-- 未レビュー -->

本書で使った感情エンジンは[affectus](https://github.com/n-yokomachi/affectus)として公開している。macOSかLinuxで動く。Goの環境があれば次のコマンドでインストールできる。

```sh
go install github.com/n-yokomachi/affectus/cmd/affectus@latest
```

:::message
Goがない場合はリポジトリのReleasesページからビルド済みのバイナリを取得できる。
:::

モデルはinitコマンドで初期化するときに選ぶ。何も指定しなければプルチックの感情の輪になる。

```sh
affectus init                  # プルチックの感情の輪
affectus init --model russell  # ラッセルの円環モデル
affectus init --model occ      # OCCモデル
affectus init --model barrett  # バレットの構成主義的情動理論
```

エージェントに組み込むときはリポジトリのexamplesにあるモデルごとの指示文をシステムプロンプトに入れる。時間による減衰のためにtickコマンドを定期実行する。MCPに対応したエージェントでは`affectus mcp`をMCPサーバーとして登録すると、プルチックとラッセルとOCCの3つのモデルを使える。バレットの想起と保存はMCPに対応していないのでコマンドで使う。tickコマンドはMCPに含まれないので、MCPを使う場合も定期実行が必要である。
