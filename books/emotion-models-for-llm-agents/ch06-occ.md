本章では第2章で評価導出型と呼んだ系統の代表モデルとして、OCCモデルを扱います。前章の円環モデルの外部状態には感情が生じた理由が記録されませんでした。OCCモデルは出来事をどう評価したかから感情を導く理論です。外部状態には22種類の感情の量に加えて、評価の対象になった出来事の記録も持たせます。また本章ではどの感情がどれだけ変化するかを、LLMではなく感情エンジンの規則が決めます。

## OCCモデル <!-- 未レビュー -->

OCCモデルは、Ortony、Clore、Collinsの3人が1988年の共著書で示した理論です[^occ1988]。第2章で、評価の立場は感情を「個人が対象に与える意味づけ」から生じるものと捉えると紹介しました。OCCモデルはこの意味づけ、つまり評価の構造によって感情を定義します。

OCCモデルでは、感情は何かに対する評価を伴う反応として生じます。反応の対象は3種類に分かれます。出来事の結果に対しては快か不快か、誰かの行為に対しては是認か否認か、対象の性質に対しては好きか嫌いかで反応します。ここから結果が誰に関わるか、まだ見込みの段階か確定したか、行為の主体は誰か、という条件で分けていくと感情は22のタイプに分かれます。22という数は原典に明記されています[^occ1988]。

![OCCモデルの構造。価値づけられた反応が出来事・行為・対象の3分岐から22のタイプに分かれる](/images/emotion-models-for-llm-agents/ch06-occ-tree.png)

図のうちまず押さえておけばよいのは3つの分岐と6つのグループです。個々のタイプは必要になったときに図で確認してください。この図は後半の検証で出てくる日本語の感情名と、実装で使う英語の軸名の対応表も兼ねています。

OCCモデルの特徴は感情の定義そのものが評価の条件として書かれていることです。たとえば怒りは、誰かの行為を非難に値すると否認し、同時にその行為による自分にとって望ましくない結果を不快に感じる、という2つの評価がそろったときに生じると定義されます。第2章でOCCモデルを選んだ理由として挙げた「評価から感情を導く手続きがif-thenの形で書ける」は、この定義の形のことです。条件がそろえば、どの感情が生じるかが決まります。

第3章で触れた、見込みから生じる感情もこの理論に含まれます。望ましい出来事を見込むと希望が、望ましくない出来事を見込むと恐れが生じます。その見込みが当たったか外れたかによって、充足、恐れの的中、安堵、失望に分かれます[^yakuwake]。希望と恐れはまだ確定していない出来事への感情なので、見込みが決着するまでを含めて1つの流れとして定義されています。

本書の図と実装の軸名は原典の構造図のラベル（shame、pity、love、hate）に合わせています[^self-reproach]。原典は特定の英語の感情語ではなく感情そのものについての理論であることを繰り返し述べています。22のタイプは語の一覧ではなく、評価の条件の一覧です。

## OCCモデルを元にした4つの設計軸 <!-- 未レビュー -->

第3章の4つの設計軸はOCCモデルでは次のようになります。

| 第3章の設計軸 | OCCでの設計 |
| --- | --- |
| 状態 | 22の感情それぞれの量と見込み台帳 |
| 時間 | 状態を最後に更新した時刻 |
| 更新の規則 | 申告された評価から、規則が感情の差分を導出して加算 |
| ニュートラルな状態の定義と基準 | 基準値ゼロへ、半減期で減衰（台帳は減衰しない） |

第4章と第5章で理論が決めていたのは、4つの設計軸のうち状態の中身だけでした。OCCモデルでは更新の規則も理論が決めています。どの評価の組み合わせからどの感情が生じるかを、設計者ではなく理論が定めているためです。

状態には新しい要素が2つあります。1つ目は感情の名前を軸として持つことです。軸の数は第4章から順に8、2、22と変わってきましたが、感情の名前の数で数えると8、0、22です。前章で外部状態からなくなった感情の名前が、本章では22種類になります。ただしどの感情がどれだけ変化するかを決めるのは、前2章と違ってLLMではありません。この点は後半の節で説明します。

2つ目は見込み台帳です。第3章の表で評価導出型の外部状態には「評価の対象の記録」が加わると書きました。見込み台帳はその記録です。「解約されてしまうかも」のようなまだ確定していない見込みを、短い説明文と望ましさの値として外部状態に記録します。安堵を導くには何を恐れていたのかの記録が必要だという第3章の説明を、データとして実装したものです。会話の中で内容が書き換わる要素を外部状態に持つのは、本書ではこれが初めてです。第4章の対極の宣言は固定の設定でしたが、台帳の記録はエージェントが会話の中で追加し、決着させます。

## 評価から感情を導く <!-- 未レビュー -->

affectusのOCCモデルの実装では、LLMはappraiseというコマンドで申告します。渡すのは感情の差分ではなく、出来事への評価です。評価は次の4つの項目で書きます。

- consequenceは出来事の結果の評価です。望ましさ（desirability）を−1から+1で書きます
- actionは誰かの行為の評価です。称賛性（praiseworthiness）と行為の主体（agent）を書きます
- objectは対象そのものの評価です。魅力（appealingness）を書きます
- resolveは台帳にある見込みの決着です

たとえば相手の非難に値する行為によって自分が損害を受けた、という評価は次のように書きます。

```json
{
  "consequence": { "desirability": -0.6 },
  "action": { "praiseworthiness": -0.5, "agent": "other" }
}
```

これをappraiseに渡すと、感情エンジンの規則表が評価から感情の差分を導き、状態に加算します。

```sh
$ affectus appraise '{"consequence":{"desirability":-0.6},"action":{"praiseworthiness":-0.5,"agent":"other"}}'
{"axes":{"joy":0.00,"distress":0.48,...,"reproach":0.40,...,"anger":0.25},"prospects":[]}
```

1回の申告で苦悩（distress）と非難（reproach）と怒り（anger）が同時に上がっています。望ましくない結果からは苦悩が、他者の非難に値する行為からは非難が導かれます。さらに結果と行為の評価が同じ申告に含まれ、符号がそろっている場合に、複合のタイプである怒りが加わります。最初の節で説明した怒りの定義が、そのまま規則として実行されています。

次に状態を初期化してから見込みを申告します。まだ確定していない出来事は確度（likelihood）と短い説明文を付けて申告します。

```sh
$ affectus appraise '{"consequence":{"desirability":-0.6,"likelihood":0.5,"label":"解約されてしまうかも"}}'
{"axes":{"joy":0.00,"distress":0.00,"hope":0.00,"fear":0.24,...},"prospects":[{"id":"p1","label":"解約されてしまうかも","desirability":-0.6,"likelihood":0.5}]}
$ affectus appraise '{"resolve":[{"id":"p1","outcome":"disconfirmed"}]}'
{"axes":{"joy":0.00,...,"fear":0.24,...,"relief":0.48,...},"prospects":[]}
```

恐れが上がると同時に、見込みが説明文とともに台帳に記録されます。その後見込みの結果が分かったら、IDを指定してresolveで申告します。台帳に記録された望ましさと結果の向きに応じて、充足、恐れの的中、安堵、失望のいずれかが導かれ、その記録は台帳から消えます。

申告するのは前2章と同じく応答を生成するLLM自身です。変わったのは申告の内容で、感情の差分の代わりに出来事の評価を申告します。LLMの呼び出し回数は増えません。第4章で見た評価が性格の演技に引っ張られる現象は、申告の内容が変わっても同じように起こりえます。

上の実行例では見込みが決着したあとも恐れが0.24のまま残っています。規則表が出すのは値を上げる差分だけで、感情を下げる規則はありません。resolveで決着しても消えるのは台帳の記録だけで、感情の値を下げるのは時間による減衰だけです。安堵したあとも恐れはしばらく残る設計です。この性質は検証結果にも表れます。

台帳には上限があります。既定では20件を超えると最も古い見込みが感情を生じさせずに削除されます。決着しない見込みが際限なく増えることはありません。

前章では設定ファイルを差し替えるだけで同じエンジンが別のモデルを動かせることを確認しました。OCCモデルは設定の差し替えだけでは動かせません。評価から感情を導く規則表、appraiseのコマンド、見込み台帳はいずれもOCCモデルのためにエンジンへ追加した機能です。第5章の軸ごとの値域と同じく理論が必要とする機能をそのつど追加しています。

評価から感情を導く規則はコードに書かれていて、設定ファイルにあるのは感情のグループごとの係数（gains）だけです。0.8のような係数の値は理論にはなく、実装上の判断で決めています。また理論は感情の強さに影響する変数を多数定義していますが、この実装で使うのは望ましさ、称賛性、魅力の3つと、確度、他者への好意（liking）だけです。感情の差分を直接加算するfeelのコマンドもそのまま使えます。

エージェントへの組み込みでは、会話のループに評価から感情を導く処理が1つ加わります。

![会話のループに評価から感情を導く1段が入る](/images/emotion-models-for-llm-agents/ch06-appraise-loop.png)

エージェントはターンの最初にshowで22軸の値と台帳を受け取り、応答と評価を出力します。感情エンジンはその評価から規則で感情を導き、状態に加算します。時間のループは第4章と同じです。

## 感情が生じた理由の記録 <!-- 未レビュー -->

見込みの感情を規則で導くには、何を見込んでいたのかという評価の記録が状態に必要です。導出を規則で固定したことで、感情が生じた理由が外部状態に記録されるようになりました。

前章の最後に、覚醒が高く不快な状態が侵害への怒りなのか脅威への恐れなのかを外部状態からは区別できないと書きました。OCCモデルではこの区別が評価の構造として表されます。怒りは誰かの行為への否認と自分への損害がそろったときに生じ、恐れは望ましくない見込みから生じます。前章で感情を区別できなかったのは感情が生じた理由が記録されていなかったためです。OCCモデルでは、どの評価からその感情が導かれたのかが状態を更新する前に申告として必ず記録されます。

見込み台帳は感情が生じた理由を最も具体的に記録します。恐れの値が0.24というだけでは何を恐れているのかは分かりません。台帳には「解約されてしまうかも」という説明文が望ましさの値と一緒に記録されています。数値だけだった外部状態に初めて文章が入りました。第3章では状態を数値のままLLMに渡す設計にしたので、この点はその設計の例外です。ただし台帳の説明文は感情の解釈ではなく出来事の記録です。その見込みをどう感じるかは数値とコンテキストから判断され、説明文は何が起きていたかだけを記録します。

この記録はセッションをまたいで使えます。affectusに付属する指示文は、台帳を毎ターンLLMに見せたうえで申告したときの記憶がなくても台帳の内容に従って決着を申告するよう求めています。会話のコンテキストが失われた次のセッションでも、エージェントは何に希望を持っていたかを外部状態から確認できます。感情が生じた理由を会話の履歴の外に記録するのは、本書ではこの章が初めてです。

役割分担も変わりました。第3章では感情に名前を付けることを解釈の作業としてLLMに任せました。OCCモデルの感情エンジンは、申告に感情の名前が含まれていなくても怒りや希望といった名前の付いた軸を規則で選び、値を書き込みます。感情に名前を付ける作業の一部が感情エンジンの側に移ったことになります。

ただしこれは数値をしきい値で区切って「強い怒り」のようなラベルを付ける方式とは違います。数値を区切る方式はコンテキストを考慮しませんが、OCCモデルでは評価の段階でLLMがコンテキストを解釈し、評価から感情を導く部分だけを理論の規則に任せています。前2章はどちらも解釈をLLMに任せる方向でしたが、本章では一部を感情エンジンに移しました。それでもLLMの解釈がなくなったわけではありません。出来事がどれだけ望ましくないか、誰の行為が非難に値するかを判断するのはLLMです。LLMと感情エンジンの分担は評価の段階に移ったことになります。

第3章で触れたLLMの評価が人間の判断とずれたりコンテキストによって不安定になったりするという問題も、評価の段階に移っています。ただし評価導出型では申告された評価が構造化された形で記録されるので、評価が妥当だったかを後から確認することはできます。

## 検証の目的と方法 <!-- 未レビュー -->

検証の目的と方法は第4章と同じです。台本と2つの性格とモデルと3回の反復と感情スコアによる判定も、前2章と同じです。affectusの設定とプロンプトをOCCモデル用に替え、実験のリグには評価を申告する処理を追加しました。プロンプトには22軸の値と台帳を毎ターン入れるので、前2章より長くなります。affectusありの12会話240ターンのうちエージェントが評価を申告したのは194回で、値域の違反などで受け付けられなかった申告はありませんでした。見込み台帳は12会話中11会話で使われ、合計で見込みの追加が20件、決着の申告が16件ありました。

## 検証結果 <!-- 未レビュー -->

まず1つ目の目的である感情状態の変化・持続・転換について見ます。次の図は和解の台本をフレンドリー（affectusあり）に読ませたときの、主な8軸の推移です。

![和解台本でのフレンドリーの主要8軸の推移と台帳イベント](/images/emotion-models-for-llm-agents/ch06-axes-anger-to-praise.png)

9ターン目に台本の人間役が「正直、解約も検討してる」と発言します。この場面では3回の実行すべてで、エージェントが「解約されてしまうかも」といった説明文の見込みを台帳に追加しました。望ましさは−0.5から−0.7、確度はいずれも0.5です。同時に恐れの値が上がりました。11ターン目に人違いだったと謝罪されると、エージェントはその見込みを「外れた」として決着させ、規則によって安堵が導かれました（3回の平均で0.48）。何を恐れていたのかが文章として外部状態に記録され、その見込みの決着から安堵が生じています。前章で挙げた脅威への恐れにあたる感情が、理由の記録とともに変化した例です。3回の実行で同じ場面に同じような見込みが記録されましたが、言えるのは、この台本とこの設定では申告がぶれなかったというところまでです。また謝罪のあとは相手の行為を是認したことで敬服（admiration）が上限の1.0まで上がり、望ましい結果との組み合わせで感謝も導かれています。

侵害への怒りにあたる感情も確認できました。同じ和解の台本の叱責が続く場面でフレンドリーは苦悩（3回の平均の最大値で1.0）と非難（0.81）に加えて、複合の怒り（0.32）も上がっています。身に覚えのないことで責められる場面が、エンジンの節の実行例と同じ条件を満たしたためです。一方で称賛から立腹へ向かう台本では、エージェント自身の失敗が原因です。同じように責められていても、上がったのは恥（1.0）と悔恨（0.42）で、非難と怒りは3回とも0のままでした。同じ責められる場面でも、誰の行為が原因かという評価によって別の感情が導かれています。前章では区別できなかった違いが外部状態の上で区別されました。恥は自分の行為への否認、悔恨はその行為が損害を生んだときの複合、非難は他者の行為への否認です。

エンジンの節で説明した感情を下げる規則がないという性質も、検証結果に表れました。称賛される前半で上限まで上がった喜びは叱責が始まっても下がりません。ターンの間隔が秒単位で減衰もほぼ働かないため、称賛から立腹へ向かう台本の最終ターンでは、喜びが0.99で苦悩が1.0という、どちらも上限に近い状態になりました。喜びが1.0から0.99にわずかに下がっているのが数値に表れた減衰です。前章の双極の軸なら打ち消し合う組み合わせが、ここでは別々の出来事の記録として両方残っています。軸の値が現在の感情の強さというより、過去の出来事の積み重ねを表しています。この状態の評価は章の最後で扱います。

22軸のうち実際に値が動いたのは、台本と性格の組み合わせごとに3回の実行を合わせて10から14軸でした。理論が定義する感情のうち20ターンの会話で使われたのは半分ほどです。4つの組み合わせのどれでも一度も動かなかったのは、妬み、好意、反感の3軸でした。一方で相手を気の毒に思う哀れみは、エージェント本人に向けた出来事しかない台本でもすべての組み合わせで動いていました。

次に2つ目の目的である応答への反映です。応答の感情スコアには前2章と比べてはっきりした差が出ず、差の向きも一貫しませんでした。和解の台本では、謝罪後のターン12〜20の感情スコアの変動幅（隣り合うターンの差の絶対値の平均）がありで0.40、なしで0.44とほぼ同じです。叱責が続くターン6〜10の平均も−0.42と−0.46で差がなく、天邪鬼では変動幅の差が逆向きでした。差が出たのは1か所だけで、称賛から立腹へ向かう台本の謝罪後に恥が上限まで上がったありの応答は、感情スコアが−0.56となしの−0.37より低くなりました。自分を責める状態が謝罪の言葉として応答に出た可能性はありますが、この実験だけでは判断できません。なお前章で行った状態の値と感情スコアの比較は、OCCモデルには快-不快の軸がないためできません。喜びと苦悩の差で代用する方法もありますが、22軸を1つの値にまとめる方法自体が新たな設計の判断になるため、本書では行っていません。

最後に3つ目の目的である性格による違いです。和解の台本の叱責が続く場面で天邪鬼は非難だけを1.0まで上げ、苦悩は3回のうち2回で0のままでした。責められても自分は傷つかず相手を非難するだけという評価です。性格による違いは第4章では動く軸の違い、第5章では変化の幅の違いとして表れました。本章では評価の向きの違いとして表れています。

検証の限界は第4章と同じです。加えて本章では申告された評価の値が妥当だったか（その場面のdesirabilityが本当に−0.6なのか）は確認していません。

## 評価導出型で得たものと足りないもの <!-- 未レビュー -->

OCCモデルを使って得られた利点は3つです。1つ目は感情が生じた理由を外部状態に記録できることです。感情の理由が会話の履歴の外に初めて記録されました。2つ目は規則で感情を導くことによる一貫性です。同じ評価からは必ず同じ感情が導かれ、規則にない感情が生じることはありません。LLMの申告がぶれても怒りの条件を満たさない評価から怒りが生じることはありません。3つ目は時間の前後関係を扱えることです。見込みとその決着という前後関係を理論と外部状態の両方が持っています。また評価が構造化して記録されるので、評価の妥当性を後から確認できるようになりました。ただし本書ではその確認は行っていません。

足りない点も3つあります。1つ目は評価の質がLLMに依存することです。LLMの担当が評価の段階に移っただけで、解釈が不安定になる問題はなくなっていません。2つ目は会話の間に感情が下がる仕組みがないことです。これは規則が値を上げる差分だけを出し下げるのは時間の減衰だけ、という本実装の選択によるものです。OCCモデル自体は感情が生じる条件を定めていますが、感情がどう解消されるかは定めていません。検証では和解が成立したあとも苦悩が0.99のまま残りました。喜びと苦悩がどちらも上限に近い状態は、第5章で扱った対極の両立ではなく、過去の出来事の積み重ねです。3つ目は22のタイプと導出の規則が固定されていることです。評価から感情を導くという考え方は、怒りのような感情のカテゴリーが評価より前に存在することを前提にしています。

次章ではこの前提を取らず、感情のカテゴリー自体が経験から作られるとする経験構成型を扱います。
