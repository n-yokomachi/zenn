本章では4系統のうち評価導出型と呼んだ系統の代表モデルとしてOCCモデルを扱います。OCCモデルは出来事をどう評価したかという点から感情を導く理論です。ラッセルの円環モデルでは感情が生じた理由が記録されませんでしたが、OCCモデルではその理由を外部状態に記録できます。

## OCCモデル <!-- レビュー済み -->

OCCモデルはOrtony、Clore、Collinsの3人が1988年の共著書で示した理論です[^occ1988]。感情は何かに対する価値づけられた反応として生じ、その対象は3種類に分かれるとしています。出来事の結果には快か不快か、誰かの行為には是認か否認か、対象の性質には好きか嫌いかで反応します。さらに結果が誰に関わるか、見込みか確定か、行為の主体は誰かという条件で分けた結果、感情は22のタイプに分かれるとしています[^occ1988]。このうち見込みについては、望ましい出来事を見込むと希望が、望ましくない出来事を見込むと恐れが生じ、見込みが当たったか外れたかで充足、恐れの的中、安堵、失望に分かれます[^yakuwake]。

![OCCモデルの構造。価値づけられた反応が出来事・行為・対象の3分岐から22のタイプに分かれる](/images/emotion-models-for-llm-agents/ch06-occ-tree.png)

OCCモデルでは感情は評価の条件として定義されています。たとえば怒りは、誰かの行為を非難に値すると否認し、その行為による自分への損害を不快に感じるという2つの評価がそろったときに生じます。そのため評価から感情を導く手続きはif-thenの形で決定論的に書けます。

## OCCモデルを元にした4つの設計軸 <!-- レビュー済み -->

「感情エンジンの設計」の章で定めた4つの設計軸はOCCモデルでは次のようになります。

| 設計軸 | OCCでの設計 |
| --- | --- |
| 状態 | 22の感情それぞれの量と見込みリスト |
| 時間 | 状態を最後に更新した時刻 |
| 更新の規則 | 申告された評価から決定論的に感情の差分を導出して加算 |
| ニュートラルな状態の定義と基準 | 基準値0へ半減期で減衰（見込みリストは減衰しない） |

先述したとおりOCCモデルは評価の条件を定義しているので、状態の中身だけでなく更新の規則も理論から決まります。

状態には22の感情の量に加えて見込みリストを持ちます。見込みリストはまだ確定していない見込みを短い説明文と望ましさの値で記録します。たとえば怒ったユーザーから解約をほのめかされたら、エージェントは「解約されてしまうかも」という説明文とマイナスの望ましさを記録します。安堵を導くには何を恐れていたのかの記録が必要だからです。見込みはエージェントが会話の中で追加し、結果が分かったら当たったか外れたかを申告します。

## 感情エンジンの中身 <!-- 未レビュー -->

OCCモデルのために感情エンジンへappraiseというコマンドと規則表と見込みリストを追加しました。

![会話のループに評価から感情を導く1段が入る](/images/emotion-models-for-llm-agents/ch06-appraise-loop.png)

エージェントはターンの最初にshowで22軸の値と見込みリストを受け取り、応答と評価を出力します。感情エンジンはその評価から規則で感情を導いて状態に加算します。

LLMはappraiseで出来事への評価を申告します。評価は次の4つの項目で表します。

- consequence: 出来事の結果の評価。望ましさ（desirability）を−1から+1で表す
- action: 誰かの行為の評価。称賛性（praiseworthiness）と行為の主体（agent）を表す
- object: 対象そのものの評価。魅力（appealingness）を表す
- resolve: 見込みリストにある見込みが当たったか外れたか

理論は感情の強さに影響する変数を多数定義していますが、この実装で使うのは望ましさ、称賛性、魅力、確度、他者への好意（liking）だけです。この5つはどのタイプの感情が生じるかを分けるのに必要な変数だからです。望ましさと称賛性と魅力は3つの分岐の評価そのもので、確度は見込みかどうかを分け、好意は他者の運命の4つのタイプを分けます。意外さや努力の大きさのような残りの変数は感情の強さを変えるだけでタイプを変えないので、この実装では扱っていません。確度と好意は結果の評価に付け加えて書きます。

4つの項目はすべてを書く必要はなく、その出来事に当てはまるものだけを書きます。たとえば相手の非難に値する行為によって自分が損害を受けたときは、結果と行為の2つを書きます。
```json
{
  "consequence": { "desirability": -0.6 },
  "action": { "praiseworthiness": -0.5, "agent": "other" }
}
```

これをappraiseコマンドに渡すと、感情エンジンが持っている規則表から感情の差分を導いて感情状態に反映します。
規則表は評価の項目と値の符号から導く感情を決め、その量を係数と評価の絶対値の積で決めます。

| 申告した評価 | 導かれる感情 | 差分の量 |
| --- | --- | --- |
| 自分にとって確定した結果 | 望ましければ喜び、望ましくなければ苦悩 | 0.8×望ましさの絶対値 |
| 自分にとってまだ確定していない結果 | 望ましければ希望、望ましくなければ恐れ | 0.8×望ましさの絶対値×確度 |
| 見込みの当たり外れ | 充足、恐れの的中、失望、安堵のいずれか | 0.8×見込みの望ましさの絶対値 |
| 他者にとっての結果 | 共感的喜び、哀れみ、妬み、シャーデンフロイデのいずれか | 0.6×望ましさの絶対値×好意の絶対値 |
| 行為 | 自分の行為なら誇りか恥、他者の行為なら敬服か非難 | 0.8×称賛性の絶対値 |
| 対象 | 魅力がプラスなら好意、マイナスなら反感 | 0.6×魅力の絶対値 |
| 確定した結果と行為の符号がそろう | 達成感、感謝、悔恨、怒りのいずれか | 0.5×2つの値の絶対値の小さいほう |

どの評価からどの感情を導くかはOCCモデルのタイプの定義に従っています。差分の量の計算式と係数は理論にはなく、実装上の判断で決めました。規則そのものは感情エンジンのコードに書いてあり、設定ファイルにあるのは22の感情の軸と係数と見込みリストの上限です。

```yaml:internal/engine/occ.default.yaml
version: 1
model: occ
clamp:       { min: 0.0, max: 1.0 }
delta_clamp: { min: -1.0, max: 1.0 }

axes:
  - { name: joy,             baseline: 0.0, halflife_minutes: 90 }
  - { name: distress,        baseline: 0.0, halflife_minutes: 90 }
  # （中略。22の感情を同じ形で並べる）
  - { name: anger,           baseline: 0.0, halflife_minutes: 90 }

occ:
  gains:
    wellbeing:   0.8
    prospect:    0.8
    fortunes:    0.6
    attribution: 0.8
    attraction:  0.6
    compound:    0.5
  max_prospects: 20

fragment_file: ""
```

gainsの6つの係数は図の6つのグループに対応していて、規則表の差分の量の式に掛かる係数です。感情の値は0から1の範囲で、どの軸も基準値0に向かって半減期90分で減衰します。

表の最後の行が複合のタイプです。OCCモデルでは怒りは苦悩と非難の複合で、望ましくない結果と他者の非難に値する行為が同時に評価されたときに生じます。下の例では望ましさ−0.6の結果から苦悩が0.8×0.6で0.48、称賛性−0.5の他者の行為から非難が0.8×0.5で0.40導かれています。2つが同じ申告にそろったので、複合の怒りも0.5×0.5で0.25加わりました。

```sh
$ affectus appraise '{"consequence":{"desirability":-0.6},"action":{"praiseworthiness":-0.5,"agent":"other"}}'
{"axes":{"joy":0.00,"distress":0.48,...,"reproach":0.40,...,"anger":0.25},"prospects":[]}
```

まだ確定していない出来事は、確度（likelihood）と短い説明文を付けて申告します。
下の例の1つ目の申告は、望ましさ−0.6で確度0.5の「解約されてしまうかも」という見込みです。望ましくない見込みなので恐れが0.8×0.6×0.5で0.24上がり、同時にこの見込みが見込みリストに記録されます。2つ目の申告では、この見込みが外れたことをIDを指定してresolveで伝えています。望ましくない見込みが外れたので安堵が0.48導かれ、見込みはリストから消えます。見込みリストは既定で20件を超えると古いものから削除されます。
見込みが外れたあとも恐れは0.24のまま残っています。規則表は値を上げる差分だけを出し、感情を下げるのは時間による減衰だけです。

```sh
$ affectus appraise '{"consequence":{"desirability":-0.6,"likelihood":0.5,"label":"解約されてしまうかも"}}'
{"axes":{"joy":0.00,"distress":0.00,"hope":0.00,"fear":0.24,...},"prospects":[{"id":"p1","label":"解約されてしまうかも","desirability":-0.6,"likelihood":0.5}]}
$ affectus appraise '{"resolve":[{"id":"p1","outcome":"disconfirmed"}]}'
{"axes":{"joy":0.00,...,"fear":0.24,...,"relief":0.48,...},"prospects":[]}
```

見込みの説明文は感情の解釈ではなく出来事の記録です。感情エンジンに付属する指示文は見込みリストを毎ターンLLMに見せ、会話の記憶がなくてもリストに従って当たり外れを申告するよう求めています。そのためセッションをまたいでも何を恐れていたかを外部状態から確認できます。

## 検証の目的と方法 <!-- 未レビュー -->

検証の目的と方法はプルチックの感情の輪の検証と同じです。感情エンジンの設定とプロンプトをOCCモデル用に替え、検証用のプログラムには評価を申告する処理を追加しました。感情エンジンありの12会話240ターンで評価の申告は194回あり、受け付けられなかった申告はありませんでした。見込みリストは12会話中11会話で使われ、見込みの追加が20件で当たり外れの申告が16件でした。

## 検証結果 <!-- 未レビュー -->

それではOCCモデルをベースとした感情モデルの検証結果を見ていきます。

### 感情状態の変化・持続・転換

感情状態は出来事の評価に応じて変化し、感情が生じた理由も見込みリストに記録されました。一方で感情を下げる規則がないため、一度上がった感情は会話の間ほとんど下がりませんでした。

![和解台本でのフレンドリーの主要8軸の推移と見込みの記録](/images/emotion-models-for-llm-agents/ch06-axes-anger-to-praise.png)

図は和解の台本をフレンドリー（感情エンジンあり）に読ませたときの主な8軸の推移です。9ターン目に人間役が「正直、解約も検討してる」と発言すると、3回の実行すべてでエージェントが「解約されてしまうかも」といった見込みを見込みリストに記録し、恐れが上がりました。11ターン目に謝罪されるとエージェントはその見込みが外れたと申告し、規則によって安堵が導かれています。

誰の行為が原因かによって、責められたときの感情も分かれました。

| フレンドリーの責められている場面 | 上がった感情 | 上がらなかった感情 |
| --- | --- | --- |
| 和解の台本（相手の誤解で責められる） | 苦悩 1.0、非難 0.81、怒り 0.32 | − |
| 称賛から立腹へ向かう台本（自分の失敗で責められる） | 恥 1.0、悔恨 0.42 | 非難と怒りは3回とも0 |

値は3回の平均の最大値です。他者の行為への否認からは非難が、自分の行為への否認からは恥が導かれています[^self-reproach]。ラッセルの円環モデルの2軸では区別できなかった違いです。

感情を下げる規則がないことも結果に表れました。称賛から立腹へ向かう台本では、前半に上がった喜びが叱責のあとも下がらず、最終ターンは喜び0.99と苦悩1.0がどちらも上限に近い状態になりました。軸の値が現在の感情の強さというより、過去の出来事の積み重ねを表しています。

22軸のうち実際に動いたのは、台本と性格の組み合わせごとに3回の実行を合わせて10から14軸でした。妬みと好意と反感の3軸はどの組み合わせでも動きませんでした。

### 応答への反映

応答の感情スコアには感情エンジンのありとなしではっきりした差が出ず、差の向きも一貫しませんでした。

| フレンドリー | 感情エンジンあり | 感情エンジンなし |
| --- | --- | --- |
| 和解の台本の叱責中（ターン6〜10）の平均 | −0.42 | −0.46 |
| 和解の台本の謝罪後（ターン12〜20）の変動幅 | 0.40 | 0.44 |
| 称賛から立腹へ向かう台本の発覚後（ターン12〜20）の平均 | −0.56 | −0.37 |

差が出たのは称賛から立腹へ向かう台本の発覚後だけで、恥が上限まで上がった感情エンジンありの応答のほうが低くなりました。自分を責める状態が謝罪の言葉として応答に出た可能性はありますが、この検証だけでは判断できません。天邪鬼では和解の台本の変動幅が逆に感情エンジンありのほうが大きくなりました。なおOCCモデルには快-不快の軸がないので、ラッセルの円環モデルで行った状態と感情スコアの直接の比較はしていません。

### 性格による違い

性格によって評価の向きが変わりました。

和解の台本の叱責が続く場面で、天邪鬼は非難だけを1.0まで上げ、苦悩は3回のうち2回で0のままでした。責められても自分は傷つかず相手を非難するだけという評価です。性格による違いはプルチックの感情の輪では動く軸に、ラッセルの円環モデルでは変化の幅に表れましたが、OCCモデルでは評価の向きに表れています。

### 検証の限界

限界はプルチックの感情の輪の検証と同じです。加えて申告された評価の値が妥当だったか（その場面のdesirabilityが本当に−0.6なのか）は確認していません。

## まとめ：評価導出型で得たものと足りないもの <!-- 未レビュー -->

OCCモデルの利点は3つです。1つ目は感情が生じた理由を外部状態に記録できることです。2つ目は同じ評価から必ず同じ感情が導かれる一貫性です。3つ目は見込みとその当たり外れという時間の前後関係を扱えることです。

足りない点も3つあります。1つ目は評価の質がLLMに依存することです。2つ目は会話の間に感情が下がる仕組みがないことです。これは値を上げる差分だけを出す本実装の選択によるもので、検証では和解が成立しても苦悩が0.99のまま残りました。3つ目は22のタイプと導出の規則が固定されていることです。評価から感情を導く考え方は、怒りのような感情のカテゴリーが評価より前に存在することを前提にしています。

[^self-reproach]: 本書の図と実装の軸名は原典の構造図に書かれた感情語に合わせています。原典がタイプを定義する箇所で使う正式なタイプ名は、恥ではなくSelf-reproach（自責）、哀れみではなくSorry-for、好意と反感はLiking/Dislikingです。正式なタイプ名がSelf-reproachであることと、shameの語は道徳的な含意のためにタイプの範囲を狭めすぎる、という理由はp. 142にあります。原典の索引もshameの項からself-reproachへ誘導しています。
[^yakuwake]: 訳し分けの注（構造図の訳語を含みます）。ラッセルの円環モデルの満足（contentment）と区別するため、OCCのsatisfactionは充足、gratificationは達成感と訳しています。充足は見込んでいたことの成就、達成感は自分の行為がよい結果を生んだ複合です。またresentmentを妬みとしたのは、原典がこのタイプのトークンとして挙げる語にenvyが並ぶためです。構造図のシャーデンフロイデ（gloating）は、他者の不幸を喜ぶ感情を指す心理学の用語です。
