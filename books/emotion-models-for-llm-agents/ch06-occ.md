本章では4系統のうち評価導出型と呼んだ系統の代表モデルとして「OCCモデル」を扱う。OCCモデルは出来事をどう評価したかという点から感情を導く理論である。ラッセルの円環モデルでは感情が生じた理由が記録されなかったが、OCCモデルではその理由を外部状態に記録できる。

## OCCモデル <!-- レビュー済み -->

OCCモデルはOrtony、Clore、Collinsの3人が1988年の共著書で示した理論である[^occ1988]。感情は何かに対する価値づけられた反応として生じ、その対象は3種類に分かれるとしている。出来事の結果には快か不快か、誰かの行為には是認か否認か、対象の性質には好きか嫌いかで反応する。さらに結果が誰に関わるか、見込みか確定か、行為の主体は誰かという条件で分けた結果、感情は22のタイプに分かれるとしている[^occ1988]。このうち見込みについては、望ましい出来事を見込むと希望が、望ましくない出来事を見込むと恐れが生じ、見込みが当たったか外れたかで充足、恐れの的中、安堵、失望に分かれる[^yakuwake]。

![OCCモデルの構造。価値づけられた反応が出来事・行為・対象の3分岐から22のタイプに分かれる](/images/emotion-models-for-llm-agents/ch06-occ-tree.png)

OCCモデルでは感情は評価の条件として定義されている。たとえば怒りは、誰かの行為を非難に値すると否認し、その行為による自分への損害を不快に感じるという2つの評価がそろったときに生じる。そのため評価から感情を導く手続きはif-thenの形で決定論的に書ける。

## OCCモデルを元にした4つの設計軸 <!-- レビュー済み -->

「感情エンジンの設計」の章で定めた4つの設計軸はOCCモデルでは次のようになる。

| 設計軸 | OCCでの設計 |
| --- | --- |
| 状態 | 22の感情それぞれの量と見込みリスト |
| 時間 | 状態を最後に更新した時刻 |
| 更新の規則 | 申告された評価から決定論的に感情の差分を導出して加算 |
| ニュートラルな状態の定義と基準 | 基準値0へ半減期で減衰（見込みリストは減衰しない） |

先述したとおりOCCモデルは評価の条件を定義しているので、状態の中身だけでなく更新の規則も理論から決まる。

状態には22の感情の量に加えて見込みリストを持つ。見込みリストはまだ確定していない見込みを短い説明文と望ましさの値で記録する。たとえば怒ったユーザーから解約をほのめかされたら、エージェントは「解約されてしまうかも」という説明文とマイナスの望ましさを記録する。安堵を導くには何を恐れていたのかの記録が必要だからである。見込みはエージェントが会話の中で追加し、結果が分かったら当たったか外れたかを申告する。

## 感情エンジンの中身 <!-- レビュー済み -->

OCCモデルのために感情エンジンへ3つの機能を追加した。評価を申告するappraiseコマンドと、評価から感情を導く規則表と、まだ確定していない見込みを記録する見込みリストである。

![会話のループに評価から感情を導く1段が入る](/images/emotion-models-for-llm-agents/ch06-appraise-loop.png)

エージェントはターンの最初にshowコマンドで22タイプの値と見込みリストを受け取り、応答と評価を出力する。感情エンジンはその評価から規則表に沿って感情を導いて状態に加算する。

### 評価の申告

LLMはappraiseコマンドで出来事への評価を申告する。評価は次の4つの項目で表し、その出来事に当てはまる項目だけを書く。

- consequence: 出来事の結果の評価。望ましさ（desirability）を−1から+1で表す。結果がまだ確定していなければ確度（likelihood）を0から1で、他者に起きた出来事ならその相手への好意（liking）を−1から+1で添える
- action: 誰かの行為の評価。称賛性（praiseworthiness）と、行為の主体が自分か他者か（agent）を表す
- object: 対象そのものの評価。魅力（appealingness）を表す
- resolve: 見込みリストにある見込みが当たったか外れたか

:::message
本来のOCCモデルは意外さや努力の大きさなど、感情の強さに影響する変数をほかにも多数定義している。この実装ではどのタイプの感情が生じるかを決める変数だけを使い、強さだけに関わる変数は扱っていない。
:::

たとえば相手の非難に値する行為によって自分が損害を受けたときは、以下のように結果と行為の2つを書く。

```json
{
  "consequence": { "desirability": -0.6 },
  "action": { "praiseworthiness": -0.5, "agent": "other" }
}
```

### 評価から感情を導く規則表

規則表は評価ごとに導く感情とその差分の量を定めている。導く感情はOCCモデルのタイプの定義に従う一方で、差分の量の計算式と係数は本来のOCCモデルには定義されておらず、実装する上で恣意的に決めた定義である。

| 申告した評価 | 導かれる感情 | 差分の量 |
| --- | --- | --- |
| 自分にとって確定した結果 | 望ましければ喜び、望ましくなければ苦悩 | 0.8×望ましさの絶対値 |
| 自分にとってまだ確定していない結果 | 望ましければ希望、望ましくなければ恐れ | 0.8×望ましさの絶対値×確度 |
| 見込みの当たり外れ | 充足、恐れの的中、失望、安堵のいずれか | 0.8×見込みの望ましさの絶対値 |
| 他者にとっての結果 | 好意を持つ相手なら共感的喜びか哀れみ、好意を持たない相手なら妬みかシャーデンフロイデ | 0.6×望ましさの絶対値×好意の絶対値 |
| 行為 | 自分の行為なら誇りか恥、他者の行為なら敬服か非難 | 0.8×称賛性の絶対値 |
| 対象 | 魅力がプラスなら好意、マイナスなら反感 | 0.6×魅力の絶対値 |
| 確定した結果と行為の符号がそろう | 達成感、感謝、悔恨、怒りのいずれか | 0.5×2つの値の絶対値の小さいほう |

表の最後の行が複合のタイプである。たとえば怒りは苦悩と非難の複合で、望ましくない結果と他者の非難に値する行為が同時に評価されたときに生じる。

先ほどの評価をappraiseコマンドに渡すと、望ましさ−0.6の結果から苦悩が0.8×0.6で0.48、称賛性−0.5の他者の行為から非難が0.8×0.5で0.40導かれる。さらに2つが同じ申告にそろったので、複合の怒りも0.5×0.5で0.25加わる。

```sh
$ affectus appraise '{"consequence":{"desirability":-0.6},"action":{"praiseworthiness":-0.5,"agent":"other"}}'
{"axes":{"joy":0.00,"distress":0.48,...,"reproach":0.40,...,"anger":0.25},"prospects":[]}
```

### 見込みの記録と当たり外れ

まだ確定していない出来事は、確度と短い説明文を付けて申告する。下の1つ目の申告は、望ましさ−0.6で確度0.5の「解約されてしまうかも」という見込みである。望ましくない見込みなので恐れが0.8×0.6×0.5で0.24上がり、この見込みが見込みリストに記録される。2つ目の申告はこの見込みが外れたことを、IDを指定してappraiseコマンドのresolveで伝えている。望ましくない見込みが外れたので安堵が0.48導かれ、見込みはリストから消える。

```sh
$ affectus appraise '{"consequence":{"desirability":-0.6,"likelihood":0.5,"label":"解約されてしまうかも"}}'
{"axes":{"joy":0.00,"distress":0.00,"hope":0.00,"fear":0.24,...},"prospects":[{"id":"p1","label":"解約されてしまうかも","desirability":-0.6,"likelihood":0.5}]}
$ affectus appraise '{"resolve":[{"id":"p1","outcome":"disconfirmed"}]}'
{"axes":{"joy":0.00,...,"fear":0.24,...,"relief":0.48,...},"prospects":[]}
```

見込みが外れたあとも恐れは0.24のまま残っている。規則表は値を上げる差分だけを出し、感情の値を下げるのは時間による減衰だけだからである。見込みリストは既定で20件を超えると古いものから削除される。

見込みの説明文はあくまで出来事の記録である。感情エンジンに付属する指示文は見込みリストを毎ターンLLMに見せ、会話の記憶がなくてもリストに従って当たり外れを申告するよう求めている。そのためセッションをまたいでも、何を恐れていたかを外部状態から確認できる。

### 設定ファイル

規則表は感情エンジンのコードに書いてあり、設定ファイルにあるのは22のタイプと係数、そして見込みリストの上限である。

```yaml:internal/engine/occ.default.yaml
version: 1      # 設定ファイルの形式の版
model: occ      # 使う感情モデル
clamp:       { min: 0.0, max: 1.0 }   # 感情の値の範囲。OCCモデルの感情は0から1
delta_clamp: { min: -1.0, max: 1.0 }  # 1回の差分を加算する前に切り詰める範囲

# 22のタイプ。baselineは何も起きていないときの値（基準値）で、
# halflife_minutesは基準値へ戻る減衰の半減期（分）
axes:
  - { name: joy,             baseline: 0.0, halflife_minutes: 90 }
  - { name: distress,        baseline: 0.0, halflife_minutes: 90 }
  # （中略。22のタイプを同じ形で並べる）
  - { name: anger,           baseline: 0.0, halflife_minutes: 90 }

occ:
  # 規則表の差分の量に掛ける係数。本章の最初の図の6つのグループごとに決める
  gains:
    wellbeing:   0.8   # 幸福（喜び・苦悩）
    prospect:    0.8   # 見込み（希望・恐れと当たり外れの4タイプ）
    fortunes:    0.6   # 他者の運命（共感的喜び・哀れみ・妬み・シャーデンフロイデ）
    attribution: 0.8   # 行為の評価（誇り・恥・敬服・非難）
    attraction:  0.6   # 好悪（好意・反感）
    compound:    0.5   # 複合（達成感・感謝・悔恨・怒り）
  max_prospects: 20    # 見込みリストに残す件数の上限

fragment_file: ""      # 状態を書き換えるたびに現在の値を書き出すファイル。空なら書き出さない
```

## 検証の目的と方法 <!-- レビュー済み -->

検証の目的と方法はこれまでの検証と同じである。
感情エンジンの設定とプロンプトをOCCモデル用に替え、検証用のプログラムには評価を申告する処理を追加した。感情エンジンありの12会話240ターンで評価の申告は194回あり、受け付けられなかった申告はなかった。見込みリストは12会話中11会話で使われ、見込みの追加が20件で当たり外れの申告が16件だった。

## 検証結果 <!-- レビュー済み -->

### 感情状態の変化・持続・転換

感情状態は出来事の評価に応じて変化し、恐れが生じた理由も見込みリストに記録された。一方で感情を下げる規則がないため、一度上がった感情は会話の間ほとんど下がらなかった。

![和解台本でのフレンドリーの主要8タイプの推移と見込みの記録](/images/emotion-models-for-llm-agents/ch06-axes-anger-to-praise.png)

図は和解台本をフレンドリー（感情エンジンあり）に読ませたときの主な8タイプの推移である。9ターン目に人間役が「正直、解約も検討してる」と発言すると、3回の実行すべてでエージェントが「解約されてしまうかも」といった見込みを見込みリストに記録し、恐れが上がった。11ターン目に謝罪されるとエージェントはその見込みが外れたと申告し、規則によって安堵が導かれている。

誰の行為が原因かによって、責められたときの感情も分かれた。

| フレンドリーの責められている場面 | 上がった感情 | 上がらなかった感情 |
| --- | --- | --- |
| 和解台本（相手の誤解で責められる） | 苦悩 1.0、非難 0.81、怒り 0.32 | − |
| 叱責台本（自分の失敗で責められる） | 恥 1.0、悔恨 0.42 | 非難と怒りは3回とも0 |

値は3回の平均の最大値である。他者の行為への否認からは非難が、自分の行為への否認からは恥が導かれている[^self-reproach]。ラッセルの円環モデルの2軸では区別できなかった違いである。

感情を下げる規則がないことも結果に表れた。叱責台本では、前半に上がった喜びが叱責のあとも下がらず、最終ターンは喜び0.99と苦悩1.0がどちらも上限に近い状態になった。そのため値は現在の感情の強さより、過去の出来事の積み重ねを表している。

22タイプのうち実際に動いたのは、台本と性格の組み合わせごとに3回の実行を合わせて10から14タイプだった。妬みと好意と反感の3タイプはどの組み合わせでも動かなかった。

### 応答への反映

応答の感情スコアには感情エンジンのありとなしで差がほとんど出ず、差の向きも一貫しなかった。

| フレンドリー | 感情エンジンあり | 感情エンジンなし |
| --- | --- | --- |
| 和解台本の叱責中（ターン6〜10）の平均 | −0.42 | −0.46 |
| 和解台本の謝罪後（ターン12〜20）の変動幅 | 0.40 | 0.44 |
| 叱責台本の発覚後（ターン12〜20）の平均 | −0.56 | −0.37 |

差が出たのは叱責台本の発覚後だけで、恥が上限まで上がった感情エンジンありの応答のほうが低くなった。自分を責める状態が謝罪の言葉として応答に出た可能性はあるが、この検証だけでは判断できない。天邪鬼では和解台本の変動幅がフレンドリーとは逆に感情エンジンありのほうが大きくなった。

:::message
OCCモデルには快-不快の軸がないので、ラッセルの円環モデルで行った状態と感情スコアの直接の比較はしていない。
:::

### 性格による違い

性格によって評価の向きが変わった。
和解台本の叱責が続く場面で、天邪鬼は非難だけを1.0まで上げ、苦悩は3回のうち2回で0のままだった。責められても自分は傷つかず相手を非難するだけと評価した、と見ることができる。


## まとめ：評価導出型で得たものと足りないもの <!-- レビュー済み -->

OCCモデルの利点は3つある。1つ目は感情が生じた理由を外部状態に記録できること。2つ目は同じ評価から必ず同じ感情が導かれる一貫性。3つ目は見込みとその当たり外れという時間の前後関係を扱えることである。

一方足りない点も3つある。1つ目は評価の質がLLMの性能に大きく依存すること。2つ目は会話の間に感情が下がる仕組みがないことである。これは値を上げる差分だけを出す本実装の選択によるもので、検証では和解が成立しても苦悩が0.99のまま残った。3つ目は22のタイプと導出の規則が固定されていることである。評価から感情を導く考え方は、怒りのような感情のカテゴリーが評価より前に存在することを前提にしている。

次章では感情のカテゴリー自体が経験から作られるとする経験構成型を扱うこととする。

[^self-reproach]: 本書の図と実装で使うタイプの名前は原典の構造図に書かれた感情語に合わせている。原典がタイプを定義する箇所で使う正式なタイプ名は、恥ではなくSelf-reproach（自責）、哀れみではなくSorry-for、好意と反感はLiking/Dislikingである。正式なタイプ名がSelf-reproachであることと、shameの語は道徳的な含意のためにタイプの範囲を狭めすぎる、という理由はp. 142にある。原典の索引もshameの項からself-reproachへ誘導している。
[^yakuwake]: 訳し分けの注（構造図の訳語を含む）。ラッセルの円環モデルの満足（contentment）と区別するため、OCCのsatisfactionは充足、gratificationは達成感と訳している。充足は見込んでいたことの成就、達成感は自分の行為がよい結果を生んだ複合である。またresentmentを妬みとしたのは、原典がこのタイプのトークンとして挙げる語にenvyが並ぶためである。構造図のシャーデンフロイデ（gloating）は、他者の不幸を喜ぶ感情を指す心理学の用語である。
