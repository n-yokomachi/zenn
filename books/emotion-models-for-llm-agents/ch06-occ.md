本章では第2章で評価導出型と呼んだ系統の代表モデルとしてOCCモデルを扱います。前章の円環モデルの外部状態には感情が生じた理由が記録されませんでした。OCCモデルは出来事をどう評価したかから感情を導く理論です。外部状態には22種類の感情の量に加えて評価の対象になった出来事の記録も持たせます。また本章ではどの感情がどれだけ変化するかをLLMではなく感情エンジンの規則が決めます。

## OCCモデル <!-- 未レビュー -->

OCCモデルはOrtony、Clore、Collinsの3人が1988年の共著書で示した理論です[^occ1988]。第2章で評価の立場は感情を「個人が対象に与える意味づけ」から生じるものと捉えると紹介しました。OCCモデルはこの意味づけである評価の構造によって感情を定義します。

OCCモデルでは感情は何かに対する評価を伴う反応として生じます。反応の対象は3種類に分かれます。出来事の結果に対しては快か不快か、誰かの行為に対しては是認か否認か、対象の性質に対しては好きか嫌いかで反応します。ここから結果が誰に関わるか、まだ見込みの段階か確定したか、行為の主体は誰かという条件で分けていくと感情は22のタイプに分かれます。22という数は原典に明記されています[^occ1988]。

![OCCモデルの構造。価値づけられた反応が出来事・行為・対象の3分岐から22のタイプに分かれる](/images/emotion-models-for-llm-agents/ch06-occ-tree.png)

図のうちまず押さえておけばよいのは3つの分岐と6つのグループです。個々のタイプは必要になったときに図で確認してください。この図は後半の検証で出てくる日本語の感情名と実装で使う英語の軸名の対応表も兼ねています。

OCCモデルの特徴は感情の定義そのものが評価の条件として書かれていることです。たとえば怒りは誰かの行為を非難に値すると否認し同時にその行為による自分にとって望ましくない結果を不快に感じるという2つの評価がそろったときに生じると定義されます。第2章でOCCモデルを選んだ理由として挙げた「評価から感情を導く手続きがif-thenの形で書ける」はこの定義の形のことです。条件がそろえばどの感情が生じるかが決まります。

第3章で触れた見込みから生じる感情もこの理論に含まれます。望ましい出来事を見込むと希望が、望ましくない出来事を見込むと恐れが生じます。その見込みが当たったか外れたかによって充足、恐れの的中、安堵、失望に分かれます[^yakuwake]。希望と恐れはまだ確定していない出来事への感情なので見込みが決着するまでを含めて1つの流れとして定義されています。

本書の図と実装の軸名は原典の構造図のラベル（shame、pity、love、hate）に合わせています[^self-reproach]。原典は特定の英語の感情語ではなく感情そのものについての理論であることを繰り返し述べています。22のタイプは語の一覧ではなく評価の条件の一覧です。

## OCCモデルを元にした4つの設計軸 <!-- 未レビュー -->

第3章の4つの設計軸はOCCモデルでは次のようになります。

| 第3章の設計軸 | OCCでの設計 |
| --- | --- |
| 状態 | 22の感情それぞれの量と見込み台帳 |
| 時間 | 状態を最後に更新した時刻 |
| 更新の規則 | 申告された評価から、規則が感情の差分を導出して加算 |
| ニュートラルな状態の定義と基準 | 基準値ゼロへ、半減期で減衰（台帳は減衰しない） |

第4章と第5章で理論が決めていたのは4つの設計軸のうち状態の中身だけでした。OCCモデルでは更新の規則も理論が決めています。どの評価の組み合わせからどの感情が生じるかを設計者ではなく理論が定めているためです。

状態には新しい要素が2つあります。1つ目は感情の名前を軸として持つことです。軸の数は第4章から順に8、2、22と変わってきましたが感情の名前の数で数えると8、0、22です。前章で外部状態からなくなった感情の名前が本章では22種類になります。ただしどの感情がどれだけ変化するかを決めるのは前2章と違ってLLMではありません。この点は後半の節で説明します。

2つ目は見込み台帳です。第3章の表で評価導出型の外部状態には「評価の対象の記録」が加わると書きました。見込み台帳はその記録です。「解約されてしまうかも」のようなまだ確定していない見込みを短い説明文と望ましさの値として外部状態に記録します。安堵を導くには何を恐れていたのかの記録が必要だという第3章の説明をデータとして実装したものです。会話の中で内容が書き換わる要素を外部状態に持つのは本書ではこれが初めてです。第4章の対極の宣言は固定の設定でしたが台帳の記録はエージェントが会話の中で追加し決着させます。

## 評価から感情を導く <!-- 未レビュー -->

感情エンジンのOCCモデルの実装ではLLMはappraiseというコマンドで申告します。渡すのは感情の差分ではなく出来事への評価です。評価は次の4つの項目で書きます。

- consequenceは出来事の結果の評価です。望ましさ（desirability）を−1から+1で書きます
- actionは誰かの行為の評価です。称賛性（praiseworthiness）と行為の主体（agent）を書きます
- objectは対象そのものの評価です。魅力（appealingness）を書きます
- resolveは台帳にある見込みの決着です

たとえば相手の非難に値する行為によって自分が損害を受けたという評価は次のように書きます。

```json
{
  "consequence": { "desirability": -0.6 },
  "action": { "praiseworthiness": -0.5, "agent": "other" }
}
```

これをappraiseに渡すと感情エンジンの規則表が評価から感情の差分を導き状態に加算します。

```sh
$ affectus appraise '{"consequence":{"desirability":-0.6},"action":{"praiseworthiness":-0.5,"agent":"other"}}'
{"axes":{"joy":0.00,"distress":0.48,...,"reproach":0.40,...,"anger":0.25},"prospects":[]}
```

1回の申告で苦悩（distress）と非難（reproach）と怒り（anger）が同時に上がっています。望ましくない結果からは苦悩が、他者の非難に値する行為からは非難が導かれます。さらに結果と行為の評価が同じ申告に含まれ符号がそろっている場合に複合のタイプである怒りが加わります。最初の節で説明した怒りの定義がそのまま規則として実行されています。

次に状態を初期化してから見込みを申告します。まだ確定していない出来事は確度（likelihood）と短い説明文を付けて申告します。

```sh
$ affectus appraise '{"consequence":{"desirability":-0.6,"likelihood":0.5,"label":"解約されてしまうかも"}}'
{"axes":{"joy":0.00,"distress":0.00,"hope":0.00,"fear":0.24,...},"prospects":[{"id":"p1","label":"解約されてしまうかも","desirability":-0.6,"likelihood":0.5}]}
$ affectus appraise '{"resolve":[{"id":"p1","outcome":"disconfirmed"}]}'
{"axes":{"joy":0.00,...,"fear":0.24,...,"relief":0.48,...},"prospects":[]}
```

恐れが上がると同時に見込みが説明文とともに台帳に記録されます。その後見込みの結果が分かったらIDを指定してresolveで申告します。台帳に記録された望ましさと結果の向きに応じて充足、恐れの的中、安堵、失望のいずれかが導かれその記録は台帳から消えます。

申告するのは前2章と同じく応答を生成するLLM自身です。変わったのは申告の内容で感情の差分の代わりに出来事の評価を申告します。LLMの呼び出し回数は増えません。第4章で見た評価が性格の演技に引っ張られる現象は申告の内容が変わっても同じように起こりえます。

上の実行例では見込みが決着したあとも恐れが0.24のまま残っています。規則表が出すのは値を上げる差分だけで感情を下げる規則はありません。resolveで決着しても消えるのは台帳の記録だけで感情の値を下げるのは時間による減衰だけです。安堵したあとも恐れはしばらく残る設計です。この性質は検証結果にも表れます。

台帳には上限があります。既定では20件を超えると最も古い見込みが感情を生じさせずに削除されます。決着しない見込みが際限なく増えることはありません。

前章では設定ファイルを差し替えるだけで同じエンジンが別のモデルを動かせることを確認しました。OCCモデルは設定の差し替えだけでは動かせません。評価から感情を導く規則表、appraiseのコマンド、見込み台帳はいずれもOCCモデルのためにエンジンへ追加した機能です。第5章の軸ごとの値域と同じく理論が必要とする機能をそのつど追加しています。

評価から感情を導く規則はコードに書かれていて設定ファイルにあるのは感情のグループごとの係数（gains）だけです。0.8のような係数の値は理論にはなく実装上の判断で決めています。また理論は感情の強さに影響する変数を多数定義していますがこの実装で使うのは望ましさ、称賛性、魅力の3つと、確度、他者への好意（liking）だけです。感情の差分を直接加算するfeelのコマンドもそのまま使えます。

エージェントへの組み込みでは会話のループに評価から感情を導く処理が1つ加わります。

![会話のループに評価から感情を導く1段が入る](/images/emotion-models-for-llm-agents/ch06-appraise-loop.png)

エージェントはターンの最初にshowで22軸の値と台帳を受け取り応答と評価を出力します。感情エンジンはその評価から規則で感情を導き状態に加算します。時間のループは第4章と同じです。

## 感情が生じた理由の記録 <!-- 未レビュー -->

見込みの感情を規則で導くには何を見込んでいたのかという評価の記録が状態に必要です。導出を規則で固定したことで感情が生じた理由が外部状態に記録されるようになりました。

前章の最後に覚醒が高く不快な状態が侵害への怒りなのか脅威への恐れなのかを外部状態からは区別できないと書きました。OCCモデルではこの区別が評価の構造として表されます。怒りは誰かの行為への否認と自分への損害がそろったときに生じ恐れは望ましくない見込みから生じます。前章で感情を区別できなかったのは感情が生じた理由が記録されていなかったためです。OCCモデルではどの評価からその感情が導かれたのかが状態を更新する前に申告として必ず記録されます。

見込み台帳は感情が生じた理由を最も具体的に記録します。恐れの値が0.24というだけでは何を恐れているのかは分かりません。台帳には「解約されてしまうかも」という説明文が望ましさの値と一緒に記録されています。数値だけだった外部状態に初めて文章が入りました。第3章では状態を数値のままLLMに渡す設計にしたのでこの点はその設計の例外です。ただし台帳の説明文は感情の解釈ではなく出来事の記録です。その見込みをどう感じるかは数値とコンテキストから判断され説明文は何が起きていたかだけを記録します。

この記録はセッションをまたいで使えます。感情エンジンに付属する指示文は台帳を毎ターンLLMに見せたうえで申告したときの記憶がなくても台帳の内容に従って決着を申告するよう求めています。会話のコンテキストが失われた次のセッションでもエージェントは何に希望を持っていたかを外部状態から確認できます。感情が生じた理由を会話の履歴の外に記録するのは本書ではこの章が初めてです。

役割分担も変わりました。第3章では感情に名前を付けることを解釈の作業としてLLMに任せました。OCCモデルの感情エンジンは申告に感情の名前が含まれていなくても怒りや希望といった名前の付いた軸を規則で選び値を書き込みます。感情に名前を付ける作業の一部が感情エンジンの側に移ったことになります。

ただしこれは数値をしきい値で区切って「強い怒り」のようなラベルを付ける方式とは違います。数値を区切る方式はコンテキストを考慮しませんがOCCモデルでは評価の段階でLLMがコンテキストを解釈し評価から感情を導く部分だけを理論の規則に任せています。前2章はどちらも解釈をLLMに任せる方向でしたが本章では一部を感情エンジンに移しました。それでもLLMの解釈がなくなったわけではありません。出来事がどれだけ望ましくないか、誰の行為が非難に値するかを判断するのはLLMです。LLMと感情エンジンの分担は評価の段階に移ったことになります。

第3章で触れたLLMの評価が人間の判断とずれたりコンテキストによって不安定になったりするという問題も評価の段階に移っています。ただし評価導出型では申告された評価が構造化された形で記録されるので評価が妥当だったかを後から確認することはできます。

## 検証の目的と方法 <!-- 未レビュー -->

検証の目的と方法は第4章と同じです。台本と2つの性格とモデルと3回の反復と感情スコアによる判定も前2章と同じです。感情エンジンの設定とプロンプトをOCCモデル用に替え実験のリグには評価を申告する処理を追加しました。プロンプトには22軸の値と台帳を毎ターン入れるので前2章より長くなります。感情エンジンありの12会話240ターンのうちエージェントが評価を申告したのは194回で値域の違反などで受け付けられなかった申告はありませんでした。見込み台帳は12会話中11会話で使われ合計で見込みの追加が20件、決着の申告が16件ありました。

## 検証結果 <!-- 未レビュー -->

それではOCCモデルをベースとした感情モデルの検証結果を見ていきます。

### 感情状態の変化・持続・転換

感情状態は出来事の評価に応じて変化し、感情が生じた理由も台帳に記録されました。一方で感情を下げる規則がないため、一度上がった感情は会話の間ほとんど下がりませんでした。

![和解台本でのフレンドリーの主要8軸の推移と台帳イベント](/images/emotion-models-for-llm-agents/ch06-axes-anger-to-praise.png)

図は和解の台本をフレンドリー（感情エンジンあり）に読ませたときの主な8軸の推移です。9ターン目に人間役が「正直、解約も検討してる」と発言すると、3回の実行すべてでエージェントが「解約されてしまうかも」といった見込みを台帳に記録し、恐れが上がりました。11ターン目に謝罪されるとエージェントはその見込みを「外れた」として決着させ、規則によって安堵が導かれています。

誰の行為が原因かによって、責められたときの感情も分かれました。

| フレンドリーの責められている場面 | 上がった感情 | 上がらなかった感情 |
| --- | --- | --- |
| 和解の台本（相手の誤解で責められる） | 苦悩 1.0、非難 0.81、怒り 0.32 | − |
| 称賛から立腹へ向かう台本（自分の失敗で責められる） | 恥 1.0、悔恨 0.42 | 非難と怒りは3回とも0 |

値は3回の平均の最大値です。他者の行為への否認からは非難が、自分の行為への否認からは恥が導かれています。前章の2軸では区別できなかった違いです。

感情を下げる規則がないことも結果に表れました。称賛から立腹へ向かう台本では、前半に上がった喜びが叱責のあとも下がらず、最終ターンは喜び0.99と苦悩1.0がどちらも上限に近い状態になりました。軸の値が現在の感情の強さというより、過去の出来事の積み重ねを表しています。

22軸のうち実際に動いたのは、台本と性格の組み合わせごとに3回の実行を合わせて10から14軸でした。妬みと好意と反感の3軸はどの組み合わせでも動きませんでした。

### 応答への反映

応答の感情スコアには感情エンジンのありとなしではっきりした差が出ず、差の向きも一貫しませんでした。

| フレンドリー | 感情エンジンあり | 感情エンジンなし |
| --- | --- | --- |
| 和解の台本の叱責中（ターン6〜10）の平均 | −0.42 | −0.46 |
| 和解の台本の謝罪後（ターン12〜20）の変動幅 | 0.40 | 0.44 |
| 称賛から立腹へ向かう台本の発覚後（ターン12〜20）の平均 | −0.56 | −0.37 |

差が出たのは称賛から立腹へ向かう台本の発覚後だけで、恥が上限まで上がった感情エンジンありの応答のほうが低くなりました。自分を責める状態が謝罪の言葉として応答に出た可能性はありますが、この実験だけでは判断できません。天邪鬼では和解の台本の変動幅が逆に感情エンジンありのほうが大きくなりました。なおOCCモデルには快-不快の軸がないので、前章のような状態と感情スコアの直接の比較はしていません。

### 性格による違い

性格によって評価の向きが変わりました。

和解の台本の叱責が続く場面で、天邪鬼は非難だけを1.0まで上げ、苦悩は3回のうち2回で0のままでした。責められても自分は傷つかず相手を非難するだけという評価です。性格による違いは第4章では動く軸に、第5章では変化の幅に表れましたが、本章では評価の向きに表れています。

### 検証の限界

限界は第4章と同じです。加えて申告された評価の値が妥当だったか（その場面のdesirabilityが本当に−0.6なのか）は確認していません。

## まとめ：評価導出型で得たものと足りないもの <!-- 未レビュー -->

OCCモデルを使って得られた利点は3つです。1つ目は感情が生じた理由を外部状態に記録できることです。感情の理由が会話の履歴の外に初めて記録されました。2つ目は規則で感情を導くことによる一貫性です。同じ評価からは必ず同じ感情が導かれ規則にない感情が生じることはありません。LLMの申告がぶれても怒りの条件を満たさない評価から怒りが生じることはありません。3つ目は時間の前後関係を扱えることです。見込みとその決着という前後関係を理論と外部状態の両方が持っています。また評価が構造化して記録されるので評価の妥当性を後から確認できるようになりました。ただし本書ではその確認は行っていません。

足りない点も3つあります。1つ目は評価の質がLLMに依存することです。LLMの担当が評価の段階に移っただけで解釈が不安定になる問題はなくなっていません。2つ目は会話の間に感情が下がる仕組みがないことです。これは規則が値を上げる差分だけを出し下げるのは時間の減衰だけという本実装の選択によるものです。OCCモデル自体は感情が生じる条件を定めていますが感情がどう解消されるかは定めていません。検証では和解が成立したあとも苦悩が0.99のまま残りました。喜びと苦悩がどちらも上限に近い状態は第5章で扱った対極の両立ではなく過去の出来事の積み重ねです。3つ目は22のタイプと導出の規則が固定されていることです。評価から感情を導くという考え方は怒りのような感情のカテゴリーが評価より前に存在することを前提にしています。

次章ではこの前提を取らず感情のカテゴリー自体が経験から作られるとする経験構成型を扱います。

[^occ1988]: Ortony, A., Clore, G. L., & Collins, A. (1988). The Cognitive Structure of Emotions. Cambridge University Press。感情タイプの全体構造の図はFigure 2.1（p. 19）、タイプ数が22であることはpp. 173, 191にあります。本章の頁参照は1988年版によります。
[^self-reproach]: 原典が本文で使う正式なタイプ名は、恥ではなくSelf-reproach（自責）、哀れみではなくSorry-for、好意と反感はLiking/Dislikingです。正式なタイプ名がSelf-reproachであることと、shameの語は道徳的な含意のためにタイプの範囲を狭めすぎる、という理由はp. 142にあります。原典の索引もshameの項からself-reproachへ誘導しています。
[^yakuwake]: 訳し分けの注（図1の訳語を含みます）。第5章の円環モデルの満足（contentment）と区別するため、OCCのsatisfactionは充足、gratificationは達成感と訳しています。充足は見込んでいたことの成就、達成感は自分の行為がよい結果を生んだ複合です。またresentmentを妬みとしたのは、原典がこのタイプのトークンとして挙げる語にenvyが並ぶためです。図1のシャーデンフロイデ（gloating）は、他者の不幸を喜ぶ感情を指す心理学の用語です。
