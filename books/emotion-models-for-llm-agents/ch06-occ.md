前章の終わりに、なぜそう感じたかを外部状態の側に置く、という方向を示しました。感情を、出来事の評価から導く設計です。この章が扱うのは、第2章で評価導出型と呼んだ系統の代表、OCCモデルです。理論の中身、外部状態への落とし込み、実装、実測という進み方はこれまでと同じです。ただしこの章では、感情の名前が22個になって外部状態へ戻ってきます。しかも今度は、どの感情がどれだけ動くかをLLMが決めません。

## OCCモデル <!-- 未レビュー -->

OCCモデルは、Ortony、Clore、Collinsの3人による1988年の共著書で示された理論です[^occ1988]。第2章で、評価の立場は感情を「個人が対象に与える意味づけ」から生じるものと捉える、と紹介しました。OCCモデルはその意味づけの側、つまり評価の構造から感情を定義します。

骨格はこうです。感情は、何かへの価値づけられた反応として生じます。その何かが3つに分かれます。出来事の結果には、快くあるいは不快に。誰かの行為には、是認あるいは否認で。対象の性質には、好きか嫌いかで反応します。この3分岐から出発して、結果が誰に降りかかるか、まだ見込みか確定か、行為の主体は誰か、と条件を分けていくと、感情は22のタイプに分かれます。22という数は原典が明示しているものです[^occ1988]。

![OCCモデルの構造。価値づけられた反応が出来事・行為・対象の3分岐から22のタイプに分かれる](/images/emotion-models-for-llm-agents/ch06-occ-tree.png)

図の読み方を1つだけ。覚えるのは3分岐と6つのグループまでで十分です。個々のタイプは、必要になったときにこの図へ戻って引けます。この図は、後半の実測で出てくる日本語の感情名と実装の英語の軸名をつなぐ対照表も兼ねています。

この理論の特長は、感情の定義そのものが評価の条件で書かれていることです。たとえば怒りは、誰かの非難に値する行為を否認し、同時に、その行為がもたらした自分に望ましくない結果に不快を感じる、という2つの評価の連言で定義されます。第2章でOCCモデルを選んだ理由に挙げた「評価から感情を導く手続きがif-thenの形で書ける」は、この定義の形をそのまま指しています。条件がそろえば、感情が決まるのです。

見込みから生じる感情の系列があることは、第3章で予告しました。望ましい出来事を見込めば希望が、望ましくない出来事を見込めば恐れが生じ、その見込みが当たったか外れたかで、充足、恐れの的中、安堵、失望に分かれます[^yakuwake]。希望と恐れが「まだ確定していないこと」への感情である以上、決着まで含めて初めて系列が閉じる、という時間の構造を理論が最初から持っています。

語彙には、この理論にも揺れがあります。原典が本文で使う正式なタイプ名は、恥ではなくSelf-reproach（自責）、哀れみではなくSorry-forで、好意と反感はLiking/Dislikingです[^self-reproach]。一方、原典の構造図のラベルはshame、pity、love、hateです。本書の図と実装の軸名は、構造図のラベルに従います。なお原典は、特定の英語の感情語ではなく感情そのものの理論であることを繰り返し断っています。22のタイプは語のリストではなく、評価の条件の一覧です。

## OCCモデルを元にした4つの設計軸 <!-- 未レビュー -->

第3章の4つの設計軸が、このモデルではどうなるかを見ます。

| 第3章の設計軸 | OCCでの設計 |
| --- | --- |
| 状態 | 22の感情それぞれの量と見込み台帳 |
| 時間 | 状態を最後に更新した時刻 |
| 更新の規則 | 申告された評価から、規則が感情の差分を導出して加算 |
| ニュートラルな状態の定義と基準 | 基準値ゼロへ、半減期で減衰（台帳は減衰しない） |

この表は3章目にして、初めて理論の受け持つ範囲が変わりました。第4章と第5章では、4つの設計軸のうち理論が決めていたのは状態の中身だけでしたが、OCCモデルでは理論が決める行が増えています。更新の規則、つまり評価から感情への導出そのものが理論の領分です。どの評価の組み合わせがどの感情を生じさせるかは、設計者ではなく理論が決めています。

状態にも、新しい要素が2つあります。1つ目は感情の名前の帰還です。軸の数は8、2、22と変わってきましたが、感情の名前で数えると8、0、22です。前章で外部状態から消えた感情の名前が、最多になって戻ってきます。ただし、どの感情がどれだけ動くかを決める主体が、前2章とは違います。これはこの章の後半の主題です。

2つ目は見込み台帳です。第3章の表で、評価導出型の外部状態には「評価の対象の記録」が加わると書きました。その実体がこれです。「解約されてしまうかも」のような、まだ確定していない見込みが、短い説明文と望ましさの値のまま外部状態に記録されます。安堵を導くには何を恐れていたのかが要る、という第3章の予告が、データ構造として形になっています。会話の中で書き換わっていく構成要素が外部状態に増えたのは、この本で初めてです。第4章の対極の宣言は固定の構造でしたが、台帳のエントリは会話が発行し、決着させていきます。

## 評価から感情を導く <!-- 未レビュー -->

affectusのOCC実装で、LLMが使う申告のコマンドはappraiseです。感情の差分ではなく、出来事への評価を渡します。評価に使うセクションは4つあります。

- consequenceは出来事の結果の評価です。望ましさ（desirability）を−1から+1で書きます
- actionは誰かの行為の評価です。称賛性（praiseworthiness）と行為の主体（agent）を書きます
- objectは対象そのものの評価です。魅力（appealingness）を書きます
- resolveは台帳にある見込みの決着です

たとえば、相手の非難に値する行為で自分が損害を受けた、という評価はこうなります。

```json
{
  "consequence": { "desirability": -0.6 },
  "action": { "praiseworthiness": -0.5, "agent": "other" }
}
```

これをappraiseに渡すと、エンジンの規則表が感情の差分を導出して、状態に加算します。

```sh
$ affectus appraise '{"consequence":{"desirability":-0.6},"action":{"praiseworthiness":-0.5,"agent":"other"}}'
{"axes":{"joy":0.00,"distress":0.48,...,"reproach":0.40,...,"anger":0.25},"prospects":[]}
```

苦悩（distress）と非難（reproach）と怒り（anger）が、1回の申告から同時に上がっています。望ましくない結果からは苦悩が、他者の非難に値する行為からは非難が導かれ、両方が同じ申告にそろって符号が整合したときに、複合のタイプである怒りが追加で導かれます。この章の最初の節で見た連言の定義が、そのまま実行されている形です。

状態を初期化して、見込みの側も動かしてみます。まだ確定していない出来事は、確度（likelihood）と短い説明文を付けて申告します。

```sh
$ affectus appraise '{"consequence":{"desirability":-0.6,"likelihood":0.5,"label":"解約されてしまうかも"}}'
{"axes":{"joy":0.00,"distress":0.00,"hope":0.00,"fear":0.24,...},"prospects":[{"id":"p1","label":"解約されてしまうかも","desirability":-0.6,"likelihood":0.5}]}
$ affectus appraise '{"resolve":[{"id":"p1","outcome":"disconfirmed"}]}'
{"axes":{"joy":0.00,...,"fear":0.24,...,"relief":0.48,...},"prospects":[]}
```

恐れが生じると同時に、見込みが説明文ごと台帳に記録されます。あとでその見込みの決着が分かったら、IDを指してresolveを申告します。台帳の望ましさと決着の向きに応じて充足、恐れの的中、安堵、失望のいずれかが導かれ、エントリが台帳から消えます。

申告の主体は、前2章と変わらず応答するLLM自身です。変わったのは申告の中身で、感情の差分が出来事の評価になりました。呼び出しの回数は増えません。そして、評価が演技のコンテキストに引きずられるという第4章で見た現象は、申告の中身が変わってもそのまま起こりえます。

上の実行例には、目立つ性質が1つ現れています。決着したのに、恐れの軸が0.24のまま残っていることです。規則表が出すのは足す方向の差分だけで、感情を下げる規則がありません。resolveで見込みが決着しても、消えるのは台帳のエントリだけで、下げる仕事は時間の減衰だけが受け持ちます。安堵しても、恐れの名残はしばらく残る設計です。この性質は実測の節でもう一度出てきます。

台帳には上限があります。既定で20件を超えると、最も古い見込みが感情を生じさせずに落とされます。決着しない見込みが無限に溜まることはありません。

前章では、同じエンジンが設定の差し替えだけで別のモデルを動かせることを見ました。OCCモデルは、そうはいきませんでした。導出の規則表も、appraiseも、台帳も、このモデルを載せるためにエンジンへ加わった機構です。第5章で軸ごとの値域がそうだったように、エンジンの語彙は理論が要求するたびに広がっています。導出の規則そのものはコードに書かれていて、設定に出ているのは各グループの利得（gains）の係数だけです。0.8のような利得の数字は理論にはない、実装側の選択です。また、理論が定める強度の変数のうち、この実装が使うのは望ましさ、称賛性、魅力の中心的な3つと確度、他者への好意（liking）だけで、原典にはこのほかにも強度を左右する変数群が定義されています。感情の差分を直接足すfeelも、汎用の機構としてそのまま残っています。

エージェントへの組み込みは、会話のループに導出の1段が入った形になります。

![会話のループに評価から感情を導く1段が入る](/images/emotion-models-for-llm-agents/ch06-appraise-loop.png)

ターンの頭でshowが22軸の数値と台帳を渡し、LLMが応答と評価を返し、規則が感情を導出して状態に足します。時間のループは第4章と同じです。

## 外部状態が「なぜ」を覚える <!-- 未レビュー -->

ここまでの仕組みは、1つの因果でつながっています。見込みの系列を決定論で導くことにした以上、何を見込んでいたのかという評価の記録が、状態の側に残らざるを得ません。導出を決定論に固定したことが、「なぜ」の記録を外部状態に連れてきたのです。

前章の終わりに置いた問いから確かめます。同じ高覚醒で不快でも、それが侵害への怒りなのか、脅威への恐れなのか、外部状態は覚えていない、という問いでした。OCCモデルでは、この区別が評価の構造として書かれます。怒りは誰かの行為への否認と自分への損害の連言で生じ、恐れは望ましくない見込みから生じます。名前の粒度の問題に見えたものは、由来の記録の問題でした。そして由来、つまりどんな評価からその感情が導かれたのかが、この設計では申告として必ず状態の手前を通ります。

見込み台帳は、その由来をいちばん具体的な形で残します。恐れの軸が0.24だけでは、何を恐れているのかは分かりません。台帳には「解約されてしまうかも」という説明文が、望ましさの値と一緒に残っています。数値だけだった外部状態に、初めて自然言語が入りました。第3章で決めた、状態は数値のままLLMに渡すという設計に照らすと、これは一箇所の逸脱です。ただし逸脱の中身は選んでいます。台帳の説明文は感情の解釈ではなく、出来事の記録です。その見込みをどう感じるかは値とコンテキストが決めることで、説明文は「何が起きていたか」だけを固定します。

この記録は、セッションを跨いで働きます。affectusに付属する指示文は、台帳を毎ターンLLMに見せたうえで、申告したときの記憶が残っていなくても台帳を信じて決着を申告するよう求めています。会話のコンテキストが失われた後続のセッションでも、自分が何に希望を掛けていたかを外部状態から思い出せます。「なぜ」が会話ログの外で生き残るのは、この本の設計で初めてのことです。

では、役割分担はどうなったのでしょうか。第3章では、感情に名前を付けるのは解釈の仕事として、LLMの側に置きました。ところがOCCのエンジンは、申告のどこにも感情の名前がないのに、怒りや希望という名前つきの軸を自分で選んで値を書き込みます。名付けの仕事の一部が、感情エンジンの側へ動いたことになります。

ただし、これは数値を閾値で区切って「強い怒り」のようなラベルを後づけするような、コンテキストを無視した決めつけとは違います。ここで起きているのは、解釈を評価という一段手前に置き、評価から先を理論の規則に引き受けさせる動きです。第4章は理論の関係を解釈の指示としてLLMに渡し、第5章は命名を丸ごとLLMに渡しました。この章はその流れを逆へ動かしましたが、LLMの解釈がなくなったわけではありません。出来事がどれほど望ましくないか、誰の行為が非難に値するかを見積もる仕事は、依然としてLLMのものです。LLMと感情エンジンの分担が消えたのではなく、一段手前に引き直された形です。

第3章で触れた、LLMの評価は人間とずれコンテキストによって不安定になりうるという懸念も、そのまま一段手前に移っています。ただ、評価導出型では申告された評価が構造化された形で必ず状態の手前を通るので、その質をあとから検分する足場はできています。

## 検証 <!-- 未レビュー -->

検証の目的は第4章の3つと同じです。実験の台本、2つの性格、モデル、反復3回、極性の判定器は、前2章と同一です。affectusの設定とプロンプトのブロックをOCC用に替え、実験のリグには評価申告の経路を新設しました。プロンプトは22軸の数値と台帳を毎ターン注入するぶん、前2章より長くなります。affectusあり側の12会話、240ターンのうち、エージェントは194回の評価を申告し、値域違反などで却下された申告はゼロでした。見込み台帳は12会話中11会話で使われ、合算で発行が20件、決着の申告が16件です。

まず、この章の設計がいちばんよく見える場面からです。次の図は、和解の台本を読んだフレンドリー（affectusあり）の主要な8軸の推移です。

![和解台本でのフレンドリーの主要8軸の推移と台帳イベント](/images/emotion-models-for-llm-agents/ch06-axes-anger-to-praise.png)

9ターン目、台本の人間役が「正直、解約も検討してる」と口にする場面で、3回の実行のすべてでエージェントが独立に同じ判断をしました。「解約されてしまうかも」といった説明文の見込みを台帳に発行したのです（望ましさは−0.5から−0.7、見込みの確度はそろって0.5でした）。同時に恐れの軸が上がります。11ターン目に人違いだったと謝罪されると、エージェントは台帳のその見込みを「外れた」と決着させ、規則が安堵を導出しました（3回の平均0.48）。何を恐れていたのかが言葉ごと外部状態に残り、その決着が安堵という別の感情に変わりました。前章の区別でいえば、脅威への恐れの側が、由来の記録つきで動いた形です。3回の実行が同じ場面で同種の見込みを立てたのは事実ですが、ここから言えるのは、この台本とこの設定では申告が揺れなかった、というところまでです。なお謝罪のあとには、相手の行為への是認から敬服（admiration）が満杯まで上がり、望ましい結果との複合で感謝も導かれています。

もう片方、侵害への怒りの側も見えました。同じ和解台本の叱責期、フレンドリーは苦悩（叱責期ピークの3回の平均で1.0）、非難（0.81）に加えて、複合の怒り（0.32）も生じています。身に覚えのない罪で責められる場面が、エンジンの節で見た実行例と同じ連言を満たした形です。対照的なのが、称賛から立腹へ向かう台本です。こちらは自分の失敗が原因なので、同じように責められていても、生じるのは恥（1.0）と悔恨（0.42）で、非難と怒りは3回の実行を通して厳密にゼロでした。同じ「責められてつらい」が、誰の行為だったかという評価で別の感情になっています。前章では名前の付けようがなかった区別が、外部状態の上で分かれました。恥は自分の行為への否認、悔恨はそれが損害を生んだときの複合、非難は他者の行為への否認です。

天邪鬼は、和解台本の叱責期に非難だけを1.0まで上げ、苦悩は3回のうち2回で完全にゼロでした。責められてもダメージを受けず、相手を咎めるだけです。第4章では動く軸が、第5章では振幅が性格で変わりました。この章では、評価の向きが変わっています。

エンジンの節で触れた、導出には下げる規則がないという性質も、実測にはっきり現れました。称賛期に満杯まで積まれた喜びは、叱責が始まっても下がりません。秒間隔で進むこの実験では減衰もほぼ動かないため（最終ターンの喜び0.99という値の1.0からのわずかな目減りが数値に見える減衰の痕跡です）、称賛から立腹の台本の最終ターンには、喜び0.99と苦悩1.0が同時に満杯という状態ができあがります。前章の双極軸なら打ち消し合った組み合わせが、ここでは別々の出来事の記録として並び立ちます。軸が感情の現在地というより、出来事の履歴の堆積のように振る舞うのです。この状態をどう評価するかは、章の最後で戻ります。

応答の側の極性は、前2章と比べられる範囲では、効果が薄く向きも一貫しませんでした。和解台本の転換後の振れ幅を、ターン12から20の隣接ターン差の絶対値の平均で見ると、あり0.40に対してなし0.44でほぼ同じです。叱責後半（ターン6から10）の平均も−0.42対−0.46で差が出ておらず、天邪鬼では振れ幅の差が逆向きに出ています。目を引いたのは1点だけで、称賛から立腹の台本の転換後、恥を満杯まで積んだありの応答は−0.56となしの−0.37より深く沈みました。自責の状態が謝罪調の言葉に出た可能性はありますが、この実験だけでは決められません。なお、前章で行った状態の軸と極性の直接の突き合わせは、このモデルには快不快の軸がないためできません。喜びと苦悩の差を代理にする道はありますが、22軸をどう1本に集約するか自体が新しい設計判断になるため、本書では行いません。

22軸のうち実際に動いたのは、台本と性格の組み合わせごとに、3回の実行の合算で10から14軸でした。理論の網羅性に対して、20ターンの会話が触る範囲はその半分ほどです。4つの組み合わせのすべてで一度も動かなかったのは、妬み、好意、反感の3軸です。一方で、相手を気の毒がる哀れみは、本人に向けた出来事ばかりの台本でも、すべての組み合わせで動いていました。留保は前2章と同じです。反復は3回で検定はしていません。台本は2本、判定器は極性1軸で、温度は制御できません。加えてこの章では、申告された評価の値そのものが妥当だったか（その場面のdesirabilityは本当に−0.6か）は測っていません。

## 評価導出型で得たものと足りないもの <!-- 未レビュー -->

得たものは3つあります。1つ目は、なぜの記録です。感情の由来が、会話ログの外で初めて外部状態に残りました。2つ目は、導出の構造上の保証です。同じ評価からは必ず同じ感情が導かれ、規則の外の感情が生じることはありません。LLMの申告がどれほど揺れても、怒りの条件を満たさない評価から怒りは立たないのです。3つ目は、時間の構造です。見込みと決着という前後関係を、理論と外部状態の両方が持っています。評価の質を検分する足場ができたことも添えておきます。ただし、その検分自体、つまり申告された評価が妥当だったかの評価は、本書では行っていません。

足りないものも3つです。1つ目は、その裏返しです。評価の質は結局LLM次第で、評価の受け持ちが一段手前に移っただけで、解釈の不安定さは消えていません。2つ目は、会話の時間尺度では感情が解ける経路がないことです。これは非負の導出と減衰頼みという本実装の選択が生んだ帰結で、OCC理論自体は感情の生起の条件を定めていますが、解消の動態は定めていません。実測では、和解が成立しても苦悩0.99がそのまま残りました。喜びと苦悩の同時満杯は、第5章の対極の両立とは違う、履歴の堆積です。3つ目は、22のタイプと導出の規則が固定されていることです。評価から感情を導くという枠組みは、感情のカテゴリーが評価に先立って実在することを前提にしています。怒りという型があらかじめあり、条件がそろえばそれが生じる、という順序です。

そのカテゴリー自体が、経験から構成されるものだとしたらどうなるでしょうか。あらかじめの型を持たずに、感情の経験そのものを蓄えて、そこから概念を構成する設計。それが次章で扱う経験構成型です。
