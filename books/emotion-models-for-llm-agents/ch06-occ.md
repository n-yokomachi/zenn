本章では第2章で評価導出型と呼んだ系統の代表モデルとしてOCCモデルを扱います。OCCモデルは出来事をどう評価したかから感情を導く理論です。前章の円環モデルでは記録されなかった感情が生じた理由を、外部状態に記録できるようになります。

## OCCモデル <!-- 未レビュー -->

OCCモデルはOrtony、Clore、Collinsの3人が1988年の共著書で示した理論です[^occ1988]。感情は何かに対する評価を伴う反応として生じ、その対象は3種類に分かれます。出来事の結果には快か不快か、誰かの行為には是認か否認か、対象の性質には好きか嫌いかで反応します。ここから結果が誰に関わるか、見込みか確定か、行為の主体は誰かという条件で分けると、感情は22のタイプになります[^occ1988]。

![OCCモデルの構造。価値づけられた反応が出来事・行為・対象の3分岐から22のタイプに分かれる](/images/emotion-models-for-llm-agents/ch06-occ-tree.png)

図は3つの分岐と6つのグループを押さえれば十分です。個々のタイプは必要になったときに図で確認してください。本書の図と実装の軸名は原典の構造図のラベル（shame、pity、love、hate）に合わせています[^self-reproach]。

OCCモデルでは感情の定義そのものが評価の条件で書かれています。たとえば怒りは、誰かの行為を非難に値すると否認し、その行為による自分への損害を不快に感じるという2つの評価がそろったときに生じます。第2章でOCCモデルを選んだのは、このように評価から感情を導く手続きがif-thenの形で書けるからです。

見込みから生じる感情もあります。望ましい出来事を見込むと希望が、望ましくない出来事を見込むと恐れが生じ、見込みが当たったか外れたかで充足、恐れの的中、安堵、失望に分かれます[^yakuwake]。

## OCCモデルを元にした4つの設計軸 <!-- 未レビュー -->

第3章の4つの設計軸はOCCモデルでは次のようになります。

| 第3章の設計軸 | OCCでの設計 |
| --- | --- |
| 状態 | 22の感情それぞれの量と見込み台帳 |
| 時間 | 状態を最後に更新した時刻 |
| 更新の規則 | 申告された評価から、規則が感情の差分を導出して加算 |
| ニュートラルな状態の定義と基準 | 基準値ゼロへ、半減期で減衰（台帳は減衰しない） |

OCCモデルでは状態の中身だけでなく更新の規則も理論が決めています。どの評価からどの感情が生じるかを理論が定めているためです。

状態には22の感情の量に加えて見込み台帳を持ちます。台帳は「解約されてしまうかも」のようなまだ確定していない見込みを、短い説明文と望ましさの値として記録するものです。安堵を導くには何を恐れていたのかの記録が必要なためです。台帳の記録はエージェントが会話の中で追加し、決着させます。

## エンジンの中身 <!-- 未レビュー -->

OCCモデルではLLMはappraiseというコマンドで出来事への評価を申告します。評価は次の4つの項目で書きます。

- consequenceは出来事の結果の評価です。望ましさ（desirability）を−1から+1で書きます
- actionは誰かの行為の評価です。称賛性（praiseworthiness）と行為の主体（agent）を書きます
- objectは対象そのものの評価です。魅力（appealingness）を書きます
- resolveは台帳にある見込みの決着です

相手の非難に値する行為によって自分が損害を受けたという評価は次のとおりです。

```json
{
  "consequence": { "desirability": -0.6 },
  "action": { "praiseworthiness": -0.5, "agent": "other" }
}
```

これをappraiseに渡すと、感情エンジンの規則表が評価から感情の差分を導いて状態に加算します。

```sh
$ affectus appraise '{"consequence":{"desirability":-0.6},"action":{"praiseworthiness":-0.5,"agent":"other"}}'
{"axes":{"joy":0.00,"distress":0.48,...,"reproach":0.40,...,"anger":0.25},"prospects":[]}
```

1回の申告で苦悩（distress）と非難（reproach）と怒り（anger）が上がっています。結果と行為の評価が同じ申告にそろったときに、複合のタイプである怒りが加わります。

まだ確定していない出来事は、確度（likelihood）と短い説明文を付けて申告します。

```sh
$ affectus appraise '{"consequence":{"desirability":-0.6,"likelihood":0.5,"label":"解約されてしまうかも"}}'
{"axes":{"joy":0.00,"distress":0.00,"hope":0.00,"fear":0.24,...},"prospects":[{"id":"p1","label":"解約されてしまうかも","desirability":-0.6,"likelihood":0.5}]}
$ affectus appraise '{"resolve":[{"id":"p1","outcome":"disconfirmed"}]}'
{"axes":{"joy":0.00,...,"fear":0.24,...,"relief":0.48,...},"prospects":[]}
```

恐れが上がると同時に見込みが台帳に記録されます。結果が分かったらIDを指定してresolveで申告すると、充足、恐れの的中、安堵、失望のいずれかが導かれて記録は台帳から消えます。台帳は既定で20件を超えると古いものから削除されます。

上の例では決着したあとも恐れが0.24のまま残っています。規則表は値を上げる差分だけを出し、感情を下げるのは時間による減衰だけです。

規則表とappraiseと見込み台帳は、OCCモデルのためにエンジンへ追加した機能です。設定ファイルにあるのは感情のグループごとの係数（gains）だけで、係数の値は理論にはなく実装上の判断で決めています。また理論は感情の強さに影響する変数を多数定義していますが、この実装で使うのは望ましさ、称賛性、魅力、確度、他者への好意（liking）だけです。

![会話のループに評価から感情を導く1段が入る](/images/emotion-models-for-llm-agents/ch06-appraise-loop.png)

エージェントはターンの最初にshowで22軸の値と台帳を受け取り、応答と評価を出力します。感情エンジンはその評価から規則で感情を導いて状態に加算します。

見込み台帳によって、数値だけだった外部状態に初めて文章が入りました。台帳の説明文は感情の解釈ではなく出来事の記録です。感情エンジンに付属する指示文は台帳を毎ターンLLMに見せ、記憶がなくても台帳に従って決着を申告するよう求めています。そのためセッションをまたいでも、何を恐れていたかを外部状態から確認できます。

役割分担も変わります。OCCモデルでは感情の名前を規則が選ぶので、名前を付ける作業の一部が感情エンジンに移りました。ただしコンテキストを解釈して出来事を評価するのはLLMのままです。LLMの評価が人間とずれたり不安定になったりする問題も評価の段階に残ります。

## 検証の目的と方法 <!-- 未レビュー -->

検証の目的と方法は第4章と同じです。感情エンジンの設定とプロンプトをOCCモデル用に替え、実験のリグには評価を申告する処理を追加しました。感情エンジンありの12会話240ターンで評価の申告は194回あり、受け付けられなかった申告はありませんでした。見込み台帳は12会話中11会話で使われ、見込みの追加が20件で決着の申告が16件でした。

## 検証結果 <!-- 未レビュー -->

それではOCCモデルをベースとした感情モデルの検証結果を見ていきます。

### 感情状態の変化・持続・転換

感情状態は出来事の評価に応じて変化し、感情が生じた理由も台帳に記録されました。一方で感情を下げる規則がないため、一度上がった感情は会話の間ほとんど下がりませんでした。

![和解台本でのフレンドリーの主要8軸の推移と台帳イベント](/images/emotion-models-for-llm-agents/ch06-axes-anger-to-praise.png)

図は和解の台本をフレンドリー（感情エンジンあり）に読ませたときの主な8軸の推移です。9ターン目に人間役が「正直、解約も検討してる」と発言すると、3回の実行すべてでエージェントが「解約されてしまうかも」といった見込みを台帳に記録し、恐れが上がりました。11ターン目に謝罪されるとエージェントはその見込みを「外れた」として決着させ、規則によって安堵が導かれています。

誰の行為が原因かによって、責められたときの感情も分かれました。

| フレンドリーの責められている場面 | 上がった感情 | 上がらなかった感情 |
| --- | --- | --- |
| 和解の台本（相手の誤解で責められる） | 苦悩 1.0、非難 0.81、怒り 0.32 | − |
| 称賛から立腹へ向かう台本（自分の失敗で責められる） | 恥 1.0、悔恨 0.42 | 非難と怒りは3回とも0 |

値は3回の平均の最大値です。他者の行為への否認からは非難が、自分の行為への否認からは恥が導かれています。前章の2軸では区別できなかった違いです。

感情を下げる規則がないことも結果に表れました。称賛から立腹へ向かう台本では、前半に上がった喜びが叱責のあとも下がらず、最終ターンは喜び0.99と苦悩1.0がどちらも上限に近い状態になりました。軸の値が現在の感情の強さというより、過去の出来事の積み重ねを表しています。

22軸のうち実際に動いたのは、台本と性格の組み合わせごとに3回の実行を合わせて10から14軸でした。妬みと好意と反感の3軸はどの組み合わせでも動きませんでした。

### 応答への反映

応答の感情スコアには感情エンジンのありとなしではっきりした差が出ず、差の向きも一貫しませんでした。

| フレンドリー | 感情エンジンあり | 感情エンジンなし |
| --- | --- | --- |
| 和解の台本の叱責中（ターン6〜10）の平均 | −0.42 | −0.46 |
| 和解の台本の謝罪後（ターン12〜20）の変動幅 | 0.40 | 0.44 |
| 称賛から立腹へ向かう台本の発覚後（ターン12〜20）の平均 | −0.56 | −0.37 |

差が出たのは称賛から立腹へ向かう台本の発覚後だけで、恥が上限まで上がった感情エンジンありの応答のほうが低くなりました。自分を責める状態が謝罪の言葉として応答に出た可能性はありますが、この実験だけでは判断できません。天邪鬼では和解の台本の変動幅が逆に感情エンジンありのほうが大きくなりました。なおOCCモデルには快-不快の軸がないので、前章のような状態と感情スコアの直接の比較はしていません。

### 性格による違い

性格によって評価の向きが変わりました。

和解の台本の叱責が続く場面で、天邪鬼は非難だけを1.0まで上げ、苦悩は3回のうち2回で0のままでした。責められても自分は傷つかず相手を非難するだけという評価です。性格による違いは第4章では動く軸に、第5章では変化の幅に表れましたが、本章では評価の向きに表れています。

### 検証の限界

限界は第4章と同じです。加えて申告された評価の値が妥当だったか（その場面のdesirabilityが本当に−0.6なのか）は確認していません。

## まとめ：評価導出型で得たものと足りないもの <!-- 未レビュー -->

OCCモデルの利点は3つです。1つ目は感情が生じた理由を外部状態に記録できることです。2つ目は同じ評価から必ず同じ感情が導かれる一貫性です。3つ目は見込みとその決着という時間の前後関係を扱えることです。

足りない点も3つあります。1つ目は評価の質がLLMに依存することです。2つ目は会話の間に感情が下がる仕組みがないことです。これは値を上げる差分だけを出す本実装の選択によるもので、検証では和解が成立しても苦悩が0.99のまま残りました。3つ目は22のタイプと導出の規則が固定されていることです。評価から感情を導く考え方は、怒りのような感情のカテゴリーが評価より前に存在することを前提にしています。

次章では感情のカテゴリー自体が経験から作られるとする経験構成型を扱います。
