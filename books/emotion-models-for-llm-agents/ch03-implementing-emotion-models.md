---
title: "感情モデルをLLMエージェントに実装するには"
---

前章では、感情の理論を4つの系統に整理しました。本章では、それらの理論を LLM エージェントに実装するとしたら、何をどこに作ることになるのかを考えます。

先に断っておくと、この章にコードは出てきません。この章で決めるのは、感情の何を、どこに置き、いつ誰が読み書きするのかという設計です。実際に手を動かすのは第4章からで、本章はその4つの章に共通する土台にあたります。特定のツールにも依存しません。読者が自分のエージェントの設計に持ち帰れる形を目指します。

## プロンプトで演技させたときに足りないもの

いちばん手軽な方法から出発します。システムプロンプトに「あなたは明るい性格で、いま機嫌がよい」と書けば、LLM はそのとおりに振る舞います。会話の中で怒らせれば文面は硬くなり、なだめれば和らぎます。文脈の中では感情らしきものが動いて見えますし、実際、多くの用途でこれで足ります。この方法で十分だと感じるなら、それを選ばない理由はありません。

足りなくなるのは、時間が関わるときです。文脈が切れれば状態も消えます。昨日のセッションでどれだけ怒らせても、今日の最初の応答は何もなかったところから始まります。逆に、同じ文脈が続いているかぎり、3時間の中断を挟んでも、会話は中断の直前の温度のまま再開されます。何もしていない間に気分が動く、という現象がどこにも起きません。会話の要約や履歴を外部に保存して思い出させる工夫はすでによく使われていますが、多くの場合そこに残るのは何があったかという事実であって、そのとき気分がどれだけ高ぶっていたかではありません。

こうした振る舞いを不自然と感じるかどうかは主観です。感じない人にとっては、この先の設計は不要な複雑さです。ただ、不自然だと感じるのだとすれば、欠けているものははっきりしています。演技の指示が決めているのは「いま、どう振る舞うか」です。その状態が時間の中でどう続き、どう薄れ、どこへ戻っていくのかは、誰も決めていません。

では、感情が続くようにするとは、何を作ることなのでしょうか。

## LLM の内側に感情はあるのか

エージェントの外に感情を置く話をする前に、内側で何が分かっているのかを見ておきます。

LLM の内部表現を調べる研究が続いています。複数の独立した研究が同じ方向に収束していて、大まかには次のように言えます。LLM の内部には感情の概念に対応する構造化された表現があり、それが出力に因果的な影響を与えます。快と不快、覚醒の高低といった軸に沿った構造も見つかっています。こうした研究の側では、この2軸を valence と arousal という語で呼びます。第5章でも、この呼び名で登場します。valence のほうは後年に定着した呼称で、円環モデルを出した Russell 自身の語ではありません。

中でも詳しいのが、Anthropic の研究者たちが2026年に公開した、Claude Sonnet 4.5 を対象とする分析です。感情の概念に対応する表現が文脈や挙動を跨いで一般化することを示し、その表現を操作すると出力が変わること、さらに迎合や報酬ハッキング（与えられた目標の抜け道を突く挙動）といった望ましくない挙動の発生率まで変わることを報告しています。

ここまでなら、内側に感情の状態があると言いたくなります。しかし同じ論文が、そう単純ではないと書いています。

同論文は人間の感情との違いを正面から論じています。人間の感情は時間を跨いで持続するもので、ひどい知らせを受けた人はその直後に明るい文章を読んでも悲しいままです。ところが彼らの手法が捉えていたのは、直後のトークン（モデルが文章を扱う単位）を予測するのに関係する内容でした。著者らはこれを locally scoped と呼び、会話を通じて維持される安定した感情の状態を常に表すわけではないと述べています。そのうえで、会話を通じて一貫して見える応答は、各生成ステップで似た概念が繰り返し活性化した結果かもしれず、持続的に符号化された内部状態とは限らない、と書いています。

ただし著者らはここで断定していません。この区別が実践的あるいは哲学的に重要かどうかは未解決の問いだとし、自分たちの手法が見落としている持続的な表現の可能性も排除しないと明記しています。さらに踏み込んで、持続が感情の状態の鍵だという直感そのものが transformer を基にしたモデルでは適切でないかもしれない、とも書いています。

本書もこの姿勢を借ります。持てるか持てないかを争点にしません。

代わりに2つの事実を押さえておきます。一つは、これらの表現が機能する範囲が、トークンの位置と文脈 window（モデルが一度に読み込める範囲）の内側だということです。文脈 window を超えた永続化を扱った研究は、筆者が参照した範囲には見当たりませんでした。もう一つは、内部に表現があるとしても、それはエージェントを作る側が状態として読み書きできる形にはなっていないということです。

問題は、感情の状態を持てるかどうかではありません。どこに置けば、いつ、誰が読み書きできるのか。ここから先の節で、順に考えます。

## 外に置くなら、何を置くことになるか

本書はここから、感情の状態を LLM の外側に置く設計を考えます。最初に、この判断の性格をはっきりさせておきます。外部化は、前節の事実から自動的に導かれる帰結ではありません。筆者の設計判断です。

判断の根拠は、前節で押さえた2つの事実です。内側の表現は、エージェントを作る側が状態として読み書きできる形になっていないこと。そして、文脈 window を超えた持続を扱った研究が、筆者の参照した範囲には見当たらないこと。選ばなかった側にも触れておくと、モデルの内側の表現に直接介入する手法は研究として存在しますが、API を通じてモデルを使う立場からは手が届きません。事実から言えるのはここまでです。そこから先、実際に外に置くと決めるのは、事実ではなく設計者です。本書はそう決めた、という宣言をして先へ進みます。

外に置くと決めたら、次は何を置くかです。理論を選ぶ前でも、外部の状態である以上、答えることになる問いが4つあります。

1つ目は状態そのものです。いま、何が、どれだけあるのか。これがなければ、応答のたびに文脈から気分を推測し直すことになり、前節までの話に戻ります。

2つ目は時間です。その状態はいつのものか。記録がなければ、3時間前の怒りを、3時間ぶりに戻ってきた相手へそのままの強さでぶつけることになります。

3つ目は更新の規則です。出来事が起きたとき、状態はどう変わるのか。これがなければ、謝られても褒められても数値は動かず、置いた状態はただの飾りになります。

4つ目は基準と戻り方です。何も起きなければ、状態はどこへ向かうのか。これがなければ、上がった怒りには下がる理由がありません。放っておいても冷めない感情は、持続というより固着です。

4つを部品ではなく問いとして立てたのは、答え方が設計ごとに違うからです。たとえば「時間が経っても減衰させない」という選択も、4つ目の問いへの一つの答えです。また、3つ目と4つ目は似て見えますが、受け持ちが違います。更新の規則は出来事による変化を、基準と戻り方は時間による変化を受け持ちます。この区別は、状態が動く契機が2種類あることに対応していて、後の節でもう一度出てきます。

こうして問いを並べると、LLM の内側に欠けているものの正体も、前節より一段はっきりします。欠けているのは「持つこと」そのものではありません。リクエストとリクエストの間に、時間が流れることです。LLM の計算は呼び出されたときにだけ走り、呼び出しと呼び出しの間には何も起きていません。4つ目の問いが求める「何もしなくても進む変化」の担い手が、内側には存在しないのです。

なお、ここで組み立てている外部化の設計は本書の発明ではなく、系譜があります。どんな系譜で、いま何が変わったのかは、この章の後半で扱います。

## 境界をどこに引くか

外部状態と LLM の間の線は、こう引きます。保持・減衰・演算は決定論の処理に任せ、解釈・命名・言語化は LLM に任せます。状態は数値のまま LLM に渡し、その数値が何を意味するかは、受け取った側が文脈の中で決めます。

![LLM の外側に置く外部状態と決定論の処理、内側に残す解釈と言語化の分担](/images/emotion-models-for-llm-agents/ch03-division-of-labor.png)

なぜこの線なのか。数値の意味が、文脈に依存する解釈だからです。怒りが0.6という値は、それだけでは何も語りません。直前まで0.9だったなら、収まりつつある怒りです。ずっと0.2で推移してきたなら、めったにない苛立ちです。同じ0.6でも、相手が誰で、何の話をしていて、直前に何があったかで、そこから立ち上がる言葉は変わります。この解釈を「0.5を超えたら怒りの応答を返す」のような規則で決め打ちすれば、挙動は毎回同じになりますが、それは文脈を無視することと引き換えです。そして規則を書く側が想定できる文脈の数は、実際に来る文脈の数を必ず下回ります。

この線は、両側のどちらからでも破れます。破るとどうなるかを見ておきます。

まず、決定論の側が境界を越える場合です。数値に「強い怒り」のようなラベルを添えて渡す設計を考えてみます。閾値で区切って名前を付けるだけなので、実装は簡単です。しかしこの時点で、解釈が決定論の側に混入しています。「強い」かどうかは文脈が決めることであって、閾値が決めることではありません。ラベルを受け取った LLM は、自前の解釈よりラベルに引きずられた応答を返すようになり、生の数値を文脈に応じて読めるという、この分業でいちばん価値のある部分が失われます。決定論の側が名前を付け始めたら、境界が動いた合図です。

逆に、LLM の側が境界を越える場合です。減衰の計算まで LLM に任せると、「3時間経ったから、怒りは0.6から0.3まで下がっているはず」という算術を、推論のたびに安定して再現することを期待する設計になります。しかし、同じ入力から同じ結果を毎回確実に出すことは、確率的に言葉を生成する仕組みがいちばん苦手とするところです。しかも前節で見たとおり、呼び出しと呼び出しの間には、そもそも計算する主体がいません。時間による変化は、機械的に実行されるからこそ信頼できます。

どちら側に破っても、壊れ方には特徴があります。決定論の側に解釈を寄せた失敗は、同じ場面で同じ不自然さが毎回再現される形で現れます。LLM の側に演算を寄せた失敗は、たいてい合っているが、たまにおかしい形で現れます。前者は原因の規則を直せば消えますが、後者は再現させることも、直ったと確かめることも難しくなります。だから迷ったときは、失敗が再現できる側に倒すのが筆者の判断です。

もう一つ、数値のまま渡すという言い方を補足しておきます。渡すのは現在の値だけではありません。0.6が収まりつつある怒りなのか、めったにない苛立ちなのかを読み分けるには、直前の値や、普段どこに落ち着いているかという基準の値が参照点として要ります。解釈を LLM に任せるという判断は、解釈に必要な材料を揃えて渡す責任を決定論の側に生みます。境界は仕事を分けるものであって、情報を堰き止めるものではありません。

まとめると、線を引く基準はこうなります。決定論の側に置くのは、毎回同じ答えであってほしい処理です。保持と減衰がそうです。そこに判断の余地はなく、判断の余地のない仕事を確率的な生成に任せる理由がありません。LLM の側に残すのは、毎回同じ答えでは困る処理です。同じ数値でも文脈が違えば違う言葉になる、その振れ幅こそが解釈と言語化の価値です。名前を与えることも解釈に含めたのは、名付けが解釈の最初の一歩だからです。感情の持続は決定論に、感情の表出は LLM に属します。本章で筆者がいちばん主張したいのは、この線の引き方です。

## 状態はいつ、誰が更新するのか

前節で引いたのは、状態から言葉へ向かう、出力側の境界でした。残っているのは、出来事から状態へ向かう入力側です。また線の話かと思われそうですが、こちらは前節の原則だけでは決まりません。それがこの節の主題です。

状態が動く契機は2種類あります。一つは会話のターンです。相手の発話という出来事が起き、その内容に応じて状態が動きます。節3の問いで言えば、更新の規則が受け持つ変化です。もう一つは時間の経過です。出来事が何もなくても、状態は基準へ向かって戻っていきます。基準と戻り方が受け持つ変化です。前者は推論のたびに起きます。後者は推論と関係なく、呼び出しと呼び出しの間の時間についても進みます。もっとも、更新処理そのものは次の呼び出しの冒頭でまとめて実行すれば足ります。経過した時間のぶんだけ状態を戻す計算は決定論で書けるので、前節の原則のとおり機械側の仕事です。

![会話のターンによる更新と時間経過による更新が、同じ外部状態に入るループ](/images/emotion-models-for-llm-agents/ch03-update-triggers.png)

設計として決めにくいのは、会話のターンの側です。「謝られた」という出来事が怒りをどれだけ下げるのかは、演算では決まりません。出来事の意味づけ、つまり評価が要ります。前節の基準をここに当てると、答えが片側にきれいに落ちません。同じ出来事には毎回近い重さを与えてほしいという点では、毎回同じ答えを出す決定論の性質がほしくなります。一方で、重さそのものは文脈で変わってほしいので、解釈の性質も欠かせません。決め打ちの規則が文脈に耐えないことは前節で見たとおりなので、実務上は評価も LLM に任せることになります。ただし前節の原則が決めてくれるのはここまでで、評価をどの呼び出しに受け持たせるかは決まりません。だからここには、本書として決め打ちできる答えがなく、選択肢の得失を並べるにとどめます。

候補は2つあります。一つは、応答を生成する LLM 自身に、状態の変化量も併せて申告させる方法です。呼び出しが1回で済み、応答と変化量が同じ解釈から出てくるので、言葉と状態がずれにくい利点があります。代わりに、評価が演技の文脈に引きずられる懸念が残ります。機嫌よく振る舞っている最中の LLM は、出来事の重さを軽く見積もるかもしれません。もう一つは、応答の生成とは別に、出来事を評価する役を立てる方法です。評価を応答から独立させられますが、呼び出しが増え、応答と評価の間に解釈のずれが入り込む余地が生まれます。なお、LLM に出来事の評価をさせると人間の判断とずれ、文脈によって不安定になるという報告もあります。Bhattacharyya らによる査読前のプレプリントですが、評価の質を設計者自身が確かめるべき箇所だという示唆にはなります。

2つの方法のどちらが正しいという話ではありません。応答までの速さと評価の独立性のどちらを重く見るかという、用途の側で決まる釣り合いです。

## この分業は新しくない

ここまで組み立ててきた設計を、筆者の思いつきとして受け取る必要はありません。系譜があります。自分の設計判断に裏づけがほしい読者にとって、これは欠点ではなく保険です。20年前から動いている形は、昨日思いついた形より信頼できます。

感情を数値として外部に保持し、決定論的に減衰させる設計は、affective computing（感情を扱う計算技術の研究分野）が、LLM の登場よりずっと前から積み上げてきたものです。代表を一つ見ます。Gebhard が2005年に発表した ALMA という対話キャラクター向けの感情モデルは、感情・ムード・性格を、持続する時間の長さが違う3つの層に分けます。感情の強度は設定できる減衰関数で決定論的に減衰し、ムードは性格から算出される既定値へ、一定の時間をかけて戻っていきます。節3の4つの問いに、20年前のこのモデルはすべて答えを持っています。状態は活性中の感情と現在のムード、時間は減衰と復帰の時間設定、更新の規則は出来事から感情を導く評価規則、基準と戻り方は性格から導かれる既定のムードです。同じ時期には、PAD と呼ばれる3次元の空間で感情の時間変化を扱った WASABI、評価理論を計算モデルにした EMA など、同型の研究が続いています。

ただし、ALMA と本章の間には決定的な違いが一つあります。ALMA では、状態を表出へ変える側も決定論でした。発話や表情はあらかじめ用意されたものの中から、現在のムードに応じて選ばれます。数値の解釈にあたる仕事が、すべて規則とスクリプトの側にあります。つまり節4で論じた「どこまでを決定論に任せ、どこからを解釈に委ねるか」という問いは、ALMA では立ちません。全部が決定論の側にあるからです。

LLM の登場後、この構図の解釈の側だけが置き換わりました。2023年の Generative Agents は、記憶を決定論的に蓄積し、その解釈を LLM に任せる分業を実装しています。感情に絞った例もあります。Croissant らの Chain-of-Emotion は、応答の生成とは別の LLM 呼び出しで感情の生成と言語化を受け持たせます。ただし感情の薄れ方は決定論の演算ではなく、生成されたテキストの蓄積に頼る形で、本章の切り分けとは少し違います。Lu と Li が2025年に発表したモデルでは、感情の保持と時間減衰を外部システムが受け持ち、LLM は応答の方針の判断だけを受け持ちます。この役割の分け方は、本章がここまで述べてきた形とほとんど同じです。

![2005年ごろと現在の対比。数値の核は同じで、解釈と言語化の層だけが置き換わった](/images/emotion-models-for-llm-agents/ch03-interpreter-shift.png)

並べると、変わっていないものと変わったものが見えます。数値の核があり、その上に解釈と言語化の層が乗るという分業の形は、20年前から同じです。変わったのは層の担い手です。テンプレートと規則とアニメーションが受け持っていた場所に、生の数値を文脈に応じて解釈できるものが入りました。そして、担い手が固定の規則だった時代には立ちようがなかった「境界をどこに引くか」という問いが、この交代によって設計の問いになりました。この境界の引き方そのものを正面から主題にした研究は、筆者の調べた範囲では、ほとんど見当たりません。節4で論じたのは、その部分です。

## パラダイムで変わるもの、変わらないもの

ここまでの節は、感情の理論を特定せずに書いてきました。最後に、前章の4つの系統をこの設計に重ねて、理論の選択で何が変わるのかを見ます。節3の4つの問いは、どの理論を選んでも答えることになる共通部分です。ただし、変わるのは答えの中身だけではありません。理論によっては、答えを納める入れ物、いわば器そのものが増えます。

| 本書の呼称 | 外部状態に置くもの |
|---|---|
| カテゴリーパラメーター型 | 感情の種類ごとの量。理論が定めていれば、感情どうしの関係も |
| 次元パラメーター型 | 少数の軸の値 |
| 評価導出型 | 感情の量に加えて、評価から感情を導く規則と、評価の対象の記録 |
| 経験構成型 | 材料の層に加えて、経験と概念を蓄えて引き出す仕組み |

いちばん身軽なのは次元パラメーター型です。外に置くのは軸の値だけで、感情の名前は外部状態のどこにもありません。快で覚醒が高い、という位置があるだけです。それが高揚なのか歓喜なのかを決めるのは、読み取る側です。この型を選ぶことは、命名の仕事を丸ごと LLM に渡すことを意味します。4つの型の中で、LLM に委ねる解釈の仕事がいちばん多い型です。

カテゴリーパラメーター型は、感情の種類ごとの量を置きます。加えて、対極や混合といった感情どうしの関係を理論が定めている場合は、その関係の構造も外部状態の一部になります。ただし、この系統のすべての理論が関係まで定めているわけではありません。同じ型でも、選んだ理論によって器に含まれるものが変わります。

評価導出型では、感情の量のほかに、評価の対象の記録が器に加わります。前章でこの系統の代表に据えた OCC モデルには、将来の見込みから生じる感情が定義されています。望ましい出来事を見込めば希望が、望ましくない出来事を見込めば恐れが生じ、その見込みが後で当たったか外れたかによって、安堵や失望といった別の感情に変わります。安堵を導くには「何を恐れていたのか」が要ります。つまり感情の量だけでは足りず、見込みという出来事の側の記録を保持していなければ、理論が定義する感情を導けません。

経験構成型は、前章で触れたとおり、材料の層の上に構成の層が乗ります。外部状態も2階建てになります。快と不快のような材料の値に加えて、経験を蓄えて概念として引き出す仕組みが要ります。評価導出型の記録が、いま進行中の感情を導くための短期の記録であるのに対して、こちらの蓄積は長期の知識です。概念は経験から学ばれていくものなので、この在庫は追記と書き換えができなければなりません。

パラダイム間の差は、こうして2つの水準に分かれます。同じ器に入れる中身が違うという水準と、器そのものが増えるという水準です。どちらの水準の差なのかを見ておくと、実装の規模の見当も付けやすくなります。

器の形は、このように理論の選択とともに変わります。変わらないのは、節4で引いた線の基準です。保持と演算は決定論の側、解釈と言語化は LLM の側。この分業は4つのどれを選んでも同じで、分業の形は同じまま担い手が変わったという本章の見立ても、そのまま持ち越されます。それぞれの器が実際にどんなデータの形になり、エージェントの応答がどう変わるのかは、次章から1つずつ確かめます。
