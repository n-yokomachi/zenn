本章では第2章で経験構成型と呼んだ系統の代表モデルとしてバレットの構成主義的情動理論を扱います。前章のOCCモデルは怒りのような感情のカテゴリーがあらかじめ存在することを前提にしていました。構成主義的情動理論は感情のカテゴリーは過去の経験から作られるとする理論です。本章の感情エンジンは感情の量を持たず過去の経験を保存して返すだけです。感情はLLMが渡された過去の経験をもとにその場で作ります。本書で扱う4つのモデルのうち本章が最後のモデルです。

## 構成主義的情動理論 <!-- 未レビュー -->

第2章で心理構成主義の立場は感情を「それ自体は感情に特化していない、より基本的な心理的材料から構成された心的な複合物」とみなすと紹介しました。Barrett（以降バレット）の構成主義的情動理論はこの立場の中でも感情が構成されることを最も強く主張する理論です。2017年の論文によると脳は感情の概念を使って感覚をカテゴリー化しその場で感情の実例を作ります[^tce2017]。論文の結論部には理論を要約した「感情は、世界への反応ではなく、世界の構成である」という一文があります[^tce2017]。

前章までの理論との違いは感情の型があらかじめあるかどうかです。プルチックにもOCCモデルにも怒りという型が最初から定義されていて条件がそろうとその型の感情が生じました。バレットはこの考え方を取りません。怒りという型はなくあるのは怒りの概念、つまり過去に怒りと呼んだ経験の集まりです。論文では脳の内部モデルは過去の経験をもとに動きその過去の経験が概念として実装されていると述べています[^tce2017]。似た状況になると脳は過去の経験を使って現在の感覚をカテゴリー化しその場で怒りの実例を作ります。

さらに理論は同じカテゴリーの実例同士でも決まった表情や自律神経の反応のような共通の特徴を持つとは限らないとしています[^tce2017]。本書で使うのはここまでの内容です。

感情の材料については第2章からの説明とつながります。論文によると体の内部の感覚は通常は低次元のaffectとして経験されその性質は快-不快と覚醒です。この2軸は特定の感情に固有のものではありません[^affect-terms]。論文の用語はaffectですが本書では第2章と同じくコア・アフェクトと呼びます。第5章で実装した2軸の平面はこの理論では感情そのものではなく感情を作る材料の1つという位置づけになります。また第2章の選定理由で挙げたとおり構成主義の理論の中でバレットの理論には計算モデルとしての先行研究があります。

![構成の3つの材料。コア・アフェクトと過去の経験と文脈・語彙から、その場のカテゴリー化が行われる](/images/emotion-models-for-llm-agents/ch07-construction.png)

図は本書で整理したものです。感情を作る材料をコア・アフェクトと過去の経験と文脈・語彙の3つに分けました。文脈・語彙はその場の状況の中で手持ちの感情の言葉を使ってカテゴリー化が行われることを表しています。原典にこの形の図はありませんが以降の実装ではこの3つを外部状態と入力に対応させます。

## バレットの構成主義的情動理論を元にした4つの設計軸 <!-- 未レビュー -->

第3章の4つの設計軸は構成主義的情動理論では次のようになります。

| 第3章の設計軸 | バレットでの設計 |
| --- | --- |
| 状態 | コア・アフェクト2軸と経験の概念ストア |
| 時間 | 状態の更新時刻と経験ごとの作成時刻・最終想起時刻 |
| 更新の規則 | 2軸は差分の加算。経験は追記され、想起で強まり、忘却される |
| ニュートラルな状態の定義と基準 | 2軸は基準へ半減期で減衰。経験は基準に向かわない |

第6章では理論が決める設計軸が増えましたがこの理論は逆に感情のカテゴリーの一覧を定めていません。そのため状態には感情の名前を持つ軸がありません。状態にあるのは感情の材料と過去の経験の記録です。

状態の1つ目の要素は第5章と同じ2軸です。2つ目の要素は概念ストアで個々の経験を記録します。そのとき何を感じたか（当時の2軸の値）と何と名前を付けたか（感情を表す語）とどんな状況だったか（後述の14属性）を1件ずつ記録します。理論では概念は過去の経験の集まりとして働くので本実装では経験の集まりをそのまま保存する形にしました。第3章の表で経験構成型に割り当てた「経験と概念を蓄えて引き出す仕組み」がこれにあたります。第3章では評価導出型の記録が短期のものであるのに対して経験構成型は長期の記録を持つと書きました。概念ストアは追加と更新ができる長期の記録です。

外部状態が持つ感情の名前の数は第4章から順に8、0、22でした。本章では名前の数は決まっていません。どんな名前が入るのかは後半の節で説明します。時間の扱いも2種類になります。2軸は第5章と同じ設定（基準値は0と0.3、半減期は90分）で基準値に戻りますが経験は基準値に戻りません。時間とともに下がるのは経験の内容ではなく経験の思い出されやすさです。

## 経験の保存と想起 <!-- 未レビュー -->

感情エンジンのバレットの実装では1ターンは想起から始まります。recallに現在の状況の記述（後述の14属性）を渡すとストアから似た経験の上位K件（既定は5件）が現在の2軸の値と語彙マップとともに返ります。

```sh
$ affectus recall '{"valence":-0.5,"arousal":0.6,...}'
{"axes":{"valence":-0.40,"arousal":0.65},"recalled":[{"id":"c1","label":"もどかしさ","valence":-0.4,"arousal":0.65,"importance":0.44}],"culture_map":"高覚醒・不快: 怒り / 苛立ち / 焦り\n低覚醒・不快: 悲しみ / 侘しさ / 気だるさ\n..."}
```

recalledに含まれる過去の経験が感情を作る材料です。この例では以前に似た状況で「もどかしさ」と名前を付けた経験が返っています。LLMはこの記録と現在の2軸の値とculture_mapの語彙を組み合わせて今の感情に名前を付け応答に反映させます。ターンの最後にはfeelで2軸の差分を申告してから付けた名前と状況の14属性をrememberで保存します。

```sh
$ affectus remember '{"label":"やるせなさ","vector":{"valence":-0.6,"arousal":0.6,...}}'
```

想起の検索条件と保存するvectorに使う14属性は人間の感情概念の内容を測定した研究の項目を検索の形式として借りたものです[^li2024]。コア・アフェクトの2属性と典型的な表情との類似度の6属性と出来事の評価の6属性で構成されます。感情エンジンはこれらの属性の意味を解釈しません。コサイン類似度を計算するための数値として比較するだけです。体を持たないエージェントに表情との類似度を申告させているのも意味を問わずに形式だけを借りているためです。本書の組み込みでは想起の検索条件に直前のターンで申告した14属性を使います（理由は検証の節で説明します）。そのため会話の1ターン目は想起をせずに始まります。ストアが空の場合、材料は2軸と語彙だけです。

似た経験を選ぶ規則は決定論的です。検索条件との関連度（コサイン類似度）と最後に想起されてからの新しさ（半減期つきで既定は7日）と経験の重要度の3つを正規化して足し合わせ上位K件を返します。第3章で触れたGenerative Agentsの記憶の検索と同じ方式です[^park2023]。重要度は保存したときの2軸の値が基準値からどれだけ離れていたかで決まります。感情が大きく動いた経験ほど重要度が高くなり思い出されやすく忘れられにくくなります。重要度のための追加の申告は必要ありません。

ストアには記憶に似た動きが2つあります。1つは想起された経験は最終想起時刻が更新され何度も思い出されるほど思い出されやすくなることです。もう1つは上限（既定は200件）を超えると古く重要度の低い経験から削除されることです。時間とともに下がるのは検索の新しさの値だけで経験の値そのものは変わりません。同じ名前でrememberしても別の経験として記録されます。またストアの件数がK件以下の間は全件が返るので会話の序盤の想起では経験が選別されません。プロンプトに入るのは上位K件の要約（id、名前、当時の2軸、重要度）だけなのでストアが200件に増えてもプロンプトは長くなりません。

culture_mapは感情の語彙をまとめたマップを設定として持つ仕組みです。本章の検証では本書で用意した日本語の語彙マップを使っています。マップを差し替えると感情の材料が変わる設計ですが差し替えの検証は本書では行っていません。時間経過のループ（tick）は第4章と同じです。感情エンジンが担当するのは状態の保持と減衰と類似した経験の検索の3つです。

![構成のループ。想起、構成、feel、rememberの1ターンと申告が次のターンの想起クエリになる戻り](/images/emotion-models-for-llm-agents/ch07-recall-loop.png)

## 感情の名前を経験として記録する <!-- 未レビュー -->

前章の検証では軸の値が現在の感情の強さではなく過去の出来事の積み重ねを表すようになっていました。これは感情を下げる規則がないことによる副作用でした。本章の設計では過去の記録を持つことを最初から目的にしています。現在の感情の量を表す軸はなくし外部状態には材料である2軸と何を感じて何と名前を付けたかという経験の記録を残します。現在の感情の名前は状態のどこにもありません。毎ターンLLMが名前を付けその名前が経験として保存されます。

保存される名前の出どころが本章の設計の要点です。第4章と第6章の感情の名前は理論が定めた語で第5章には名前がありませんでした。本章のlabelはどちらでもなくエージェント自身が過去に付けた名前です。「もどかしさ」と名前を付けた経験が似た状況で想起され次に名前を付けるときの材料になります。過去に付けた名前が次に付ける名前に影響する仕組みです。第6章では感情が生じた理由として出来事の記録が外部状態に加わりました。本章で加わるのは過去に自分が感情に付けた名前の記録です。

第6章の台帳とは記録の期間が違います。台帳は見込みが決着すると消える短期の記録でした。概念ストアの経験は消えずに蓄積され想起されるほど思い出されやすくなりセッションをまたいで残ります。感情エンジンに付属する指示文にもストアは会話をまたいで残り今後の想起に影響すると書かれています。会話のコンテキストが失われても過去の自分が何をどう名付けたかは外部状態に残ります。外部状態が時間とともに増えていくのは本書ではこの章が初めてです。

ここまでの役割分担の変化を整理します。第4章は理論の関係を解釈の指示としてLLMに渡しました。第5章は感情の名前を付ける作業をすべてLLMに任せ、第6章は評価から感情を導く部分を感情エンジンの規則に任せました。本章で感情エンジンが担当するのは状態の保持と減衰と類似した経験の検索だけです。評価と感情の構成と名前を付けることはすべてLLMが担当します。感情のカテゴリーの一覧がないので評価から感情を導く規則は作れません。感情エンジンは感情に名前を付けずLLMが付けた名前を保存して返すだけです。第3章では感情に名前を付けることを解釈の作業としてLLMに任せました。本章の役割分担はその方針に最も近い形です。

## 検証の目的と方法 <!-- 未レビュー -->

本章が最後の検証です。検証の目的は第4章の3つと同じで台本と性格とモデルと反復回数と判定方法も同じです。ただし比較する条件が変わります。これまでは感情エンジンのありとなしを比較しましたが本章では想起のありとなしを比較します。本章で新たに加えた部品はストアなのでストアの働きだけを切り替えます。設定の違いは想起する件数（recall_k）だけでどちらもコア・アフェクトの申告と経験の保存は同じように行います。想起なしの側も毎ターン経験を保存するのでストアは同じように増えますが参照はされません。保存だけする構成と保存して参照もする構成の比較です。

想起の検索条件には直前のターンの申告を使いました。現在の状況を評価してから想起するとLLMの呼び出しが2倍になるため想起が1ターン遅れることを受け入れた設計です。そのため直前の経験が想起の上位に来るのは設計上当然で検証で見るのは想起されてプロンプトに入った過去の名前をLLMがどう使ったかです。24会話480ターンのすべてでfeelとrememberの両方が申告され受け付けられなかった申告はありませんでした。ストアには会話ごとに20件の経験が保存されます。

## 検証結果 <!-- 未レビュー -->

それではバレットの構成主義的情動理論をベースとした感情モデルの検証結果を見ていきます。

まず1つ目の目的である感情状態の変化について見ます。
結論として想起があると過去に付けた感情の名前が次のターンでも使われました。想起がないと名前は毎ターン新しく付けられました。
差が最もはっきり出たのは称賛から立腹へ向かう台本の天邪鬼です。

![称賛から立腹の台本で天邪鬼が保存した感情の名前。想起ありは同じ名前の帯が続き、想起なしは毎ターン新しい名前になる](/images/emotion-models-for-llm-agents/ch07-label-lineage.png)

図は3回の実行のうちの1回分です。左の想起ありでは20ターンで付けられた名前は8種類だけでした。照れ隠し、昂揚の隠蔽、（失敗の発覚を挟んで）焦りと苛立ち、自責と焦り、鎮静と覚悟、悔恨と覚悟、侘しさ、侘しさの中の覚悟の8つです。同じ名前が数ターン続いて出来事が変わるところで次の名前に変わっています。3回の実行のすべてで20件中10件から12件が過去の名前の再利用でした。想起だけを切った右の図では20ターンで20種類の名前が付けられました。淡い満足と皮肉、照れ隠しの反射、くすぐったい苛立ちのように似た意味の名前が毎ターン新しく付けられて再利用は1件もありませんでした。想起された自分の過去の名前が次に名前を付けるときにそのまま使われたことが分かります。ただしこれはこの台本とこの設定での結果です。再利用が起きるかどうかは台本によっても変わり、和解の台本では同じ天邪鬼でも再利用はありませんでした。

次に2つ目の目的である応答への反映です。
結論として想起があると責められている間の値の下がり方が状態と応答の両方で小さくなりました。
台本と性格の4つの組み合わせのうち3つで状態のvalenceと応答の感情スコアがどちらもこの傾向でした。差が最も大きかったのは和解の台本の天邪鬼で、叱責が続く10ターン目のvalenceは想起ありが−0.26で想起なしが−0.93でした。例外は称賛から立腹へ向かう台本の天邪鬼です。状態は終盤に同じ値になり応答の感情スコアは叱責の間わずかに逆の傾向でした。想起した過去の経験によって感情が穏やかになった可能性はありますが、1ターン遅れの想起という本書の設計での結果なので断定はしません。謝罪後のターン12〜20の変動幅（隣り合うターンの差の絶対値の平均）は半分になった組み合わせも逆になった組み合わせもあり一定しませんでした。culture_mapの影響は両方の構成に同じマップを渡しているためこの比較では分けられません。

最後に3つ目の目的である性格による違いです。
結論として性格によって名前の付け方が変わりました。天邪鬼は過去の名前をそのまま使いフレンドリーは毎回言い換えました。
フレンドリーはどの組み合わせでも名前を再利用しませんでした。ただし想起ありでは名前の付け方に一貫性がありました。和解の台本では「困惑と申し訳なさ」から始まり「嵐の後の穏やかなつながり」で終わるまで、毎回新しい言葉でも意味がつながっている長い名前が続きました。性格による違いは第4章では動く軸に表れ、第5章では変化の幅に、第6章では評価の向きに表れました。本章では名前の付け方に表れています。

本章の検証で確認できなかったこともあります。経験の削除と7日の半減期による新しさの減衰と200件の上限は20ターンを秒単位で進める会話では働きません。ストアの主な役割であるセッションをまたいだ記録の保持と語彙マップの差し替えも検証していません。検証の限界は第4章と同じです。加えて申告された14属性の値が妥当だったかは確認していません。毎ターン14項目の申告がすべて正しい形式で行われたことも今回のモデルでの結果です。

## まとめ：経験構成型で得たものと足りないもの <!-- 未レビュー -->

構成主義的情動理論を使って得られた利点は3つです。1つ目は過去の経験を記録できることです。感情の理由の記録が前章の台帳による出来事の記録から経験の蓄積に広がりました。2つ目は感情の名前を固定しないまま名前の一貫性を保てることです。決まった語彙がなくても過去の自分の名前を使って一貫した名前が付けられることを天邪鬼の1本の台本という限定付きですが検証で確認しました。3つ目は文化に合わせて語彙を差し替えられることです。語彙マップは設定なので同じエンジンで別の文化の語彙を使えます。ただし差し替えは本書では検証していません。

想起があると感情が穏やかになるという結果は感情が安定したとも反応が鈍くなったとも言えるため本書ではどちらとも評価しません。

足りない点も3つあります。1つ目は感情の構成の質がすべてLLMに依存することです。役割分担で最も多くをLLMに任せた結果、カテゴリー化も14属性の申告もLLMの自己申告で行うためその負荷と精度はモデルの性能に左右されます。2つ目は忘れる仕組みが単純なことです。この実装では削除された経験は最初からなかったものと同じになり何も残りません。3つ目は正解がないことです。感情を正しく構成できたかを測る基準が理論にありません。感情のカテゴリーに正解がないことは理論の主張そのものなのでこれは実装の不備ではなく経験構成型を選ぶことで受け入れる制約です。

ここまでで4つのモデルを同じ台本と同じ性格と同じ方法で検証しました。次章では4つのモデルの結果を並べて比較します。
