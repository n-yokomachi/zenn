# はじめに

2026年9月18日の「今話題のAI『Jev』って何？ 宇宙最速で学ぶ会」というイベントでJevについてのトークと急造したデモアプリの紹介をしました
https://www.youtube.com/watch?v=NEgSvks2Rgc

この記事では、個人開発しているAI用感情エンジンにJevを組み込んで、Jevの使用感やLLMとの違いを紹介して、Jevがどう活かせそうかのヒントを残したいなと思っています。

# Jevとは

TypeSafe AIが2026年9月15日に発表したモデルです。
詳しいことはすでにいろんな方が発信しているのでそちらをご覧ください。
https://typesafe.ai/blog/introducing-system-one-models-and-jev

個人的に一番大きい特徴は、文章を生成せず、早く安くレスポンスを返す点です。
状態と選択肢を入力として渡すと、その中のどれが妥当なのかを確率つきで判断して返します。
出力のスキーマは事前定義済みのため、（出力の形式に関して言えば）型エラーにならないしハルシネーションもしない、というのが売り文句です。
価格は入力100万トークンあたり$0.042、出力はあまりにも小さいため無料です。

2026年9月18日時点、Jevを利用するにはWaitListへの登録が必要です。
https://typesafe.ai/

私もWaitListへの登録はしていますが、待ちきれなかったのでVercel AI Gateway経由で使いました。
https://vercel.com/ai-gateway/models/jev


ちなみにJevはSystem One Modelという名称で提供されるモデルのうちの一つ、という立ち位置だそうです。
System Oneというのはダニエル・カーネマンの[『ファスト&スロー』](https://amzn.asia/d/04kZrVIs)でいう「System One（速い思考）」から採っているようです。『ファスト&スロー』は行動経済学・行動心理学系の書籍で、人間は日々迫られる選択の中で素早く判断をしていくために、経験則やバイアス、ヒューリスティクスなど直感的で認知負荷の低い方法を取る、というようなことが書かれています（一回読んだだけなので間違っていたら指摘してください）


# 作ったもの

## 感情エンジン - Affectus

以前から作っている、LLMエージェントに感情の状態を持たせるためのツールです。

https://github.com/n-yokomachi/affectus

現在複数の感情モデルをベースに感情状態の保存・更新・減衰などを実装中ですが、今回のデモにおいてはプルチックの8感情（喜び・受容・恐れ・驚き・悲しみ・嫌悪・怒り・期待）を取り上げています。
詳細な仕組みは以前の投稿をご覧ください。
https://zenn.dev/yokomachi/articles/202605_affectus

感情エンジンというと大袈裟ですが、結局は感情のパラメータを入れる箱だと思っていただければわかりやすいと思います。
ユーザーとAIとの会話の中で、自分が今どういう感情かをこの箱の中に出し入れしながら管理する、みたいなイメージです。

![](/images/202609_jev-affectus/image3.png)

## LLM / Jevの比較

この感情エンジンを使用してJevの性能をLLMと比較してみます。

1. ユーザーからのメッセージと、現在の感情パラメータの値を、JevとLLMの両方に同じ形で入力
2. Jev/LLMそれぞれが「この発言で感情がどう動くか」の変動値（-1.0〜1.0）を出力
3. それぞれの変動値を、それぞれの感情状態に適用し、それぞれの感情状態をベースに返答を生成する（ここはLLM）

![](/images/202609_jev-affectus/image1.png)

左がLLM、右がJevです。
画像の例では感情パラメータの出力に、LLM（Claude Haiku 4.5）は1,184ms、Jevは517msとそれぞれ時間がかかっています。

さらに20回ほど同じタスクをやらせてみて、レイテンシーの違いを見てみます。

| | 最小 | 中央値 | 最大 |
|---|---|---|---|
| Jev | 312 ms | 483 ms | 901 ms |
| LLM（Claude Haiku 4.5） | 1,099 ms | 1,316 ms | 2,341 ms |

中央値で2.7倍の差でした。
また今回は日本国内からのAI Gateway経由での実行のため、これによるネットワークレイテンシーを割り引くとJevのレスポンスはさらに速いはずです。
さらに判断の精度についても、公式のベンチマークでは中位クラスのLLMと同程度のスコアが出ています（ただしこのベンチマークは、GPT-6 AstraとClaude Fable 5.1の判断の平均を正解として「それにどれだけ一致するか」を測っているので、必ずしも正解との一致ではない点は割り引いて見る必要があります）



# 所感

## いいところ

早い。安い。それだけで嬉しいです。

既存のLLMでも同じことはできるじゃん、と言われればそうなんですが、何よりも早くて安いのが個人的に一番の刺激になっています。
速度とコストが大幅に変わると、使える幅がそれだけ大きくなります。

たとえば上記のAffectusでは感情分析に1ターンの会話文ぶんの時間がかかっていて、日常会話で運用するのはかなり厳しかったのですが、Jevを使用することで分析にかける時間を大幅にカットできます。あるいはまた、個人エージェントで大量のツールを定義してしまって大量のトークンコストがかかって月数十ドルかかっていたコストもバッサリカットできそうです。

あと出力の構造化が保証されるのは扱いやすいです。Structured Outputの定義とか後処理とかを頑張る必要がないので。

## 懸念点

説明可能性をどう担保するか、というのが気になっています。
値と一緒に確率も返ってきますが、それがどの程度信頼できるものなのかを評価するのが難しいです。
公式からは大手のLLMと同じようにアーキテクチャは公開されていませんし、学習元データも明示はされていません。

ということで、モデルの透明性・説明可能性という側面ではちょっと疑問が残っています。

# おわりに

Jevは早くて安い、賢いif(switch)です。
一部の仕方なくLLMでやっていた非決定論的な判断処理を肩代わりできます。
発想次第で面白い使い方が色々とできそうですし、今はまだテキストの入力しかサポートしていませんが、マルチモーダルになることでさらに幅の広がる領域だと思います。
